# 统一开发规则与六迭代执行计划

## 唯一集成基线

- 集成分支固定为 `main`，进程分支只允许向集成分支单向合并。
- 本轮合并后的唯一开发起点固定为 `baseline/governance-20260804-cutover-authorization-ledger-v1`。
- T00 独占运行时装配、全局路由顺序、CI/部署门禁和基线更新。
- T01 至 T09 只修改清单内归属路由；跨进程改动统一交由 T00 集成。
- 每次提交前执行 `npm run process:verify`，每次合并前执行完整测试。

## 生产证据边界

- 仓库只保存模板、摘要、受控引用和验证工具，不保存凭据、令牌、私钥、患者数据或供应商原始报文。
- 环境变量中的布尔开关、自动化测试结果和开发人员声明均不能替代真实迁移回执、联调回执、测评报告、现场验收或独立审批。
- 缺少任何外部门禁时，统一判定为 `NO-GO`；代码中的 `productionReady` 和 `productionPrimary` 默认保持 `false`。
- 切换必须绑定不可变发布身份、证据指纹、独立审批人与回滚负责人。

## 六个迭代

1. 统一装配与迁移演练：建立三个生产适配器的组合根、只读模式、工作进程入口和数据库结构校验。
2. 影子转发与一致性恢复：通过本地事务发件箱进行幂等转发，采用摘要对账与可恢复游标，不做不受控双写。
3. 真实集成准备：固化机构接口契约、联调清单和证据引用校验；真实回执仍由现场提供。
4. 区域业务闭环：覆盖居民授权、转诊交付、急救回执的关联标识、状态机和补偿路径。
5. 安全与运营治理：统一最小权限、审计、告警、数据质量、保留与值班门禁。
6. 试点切换与发布判定：生成切换、容灾、回滚和 GO/NO-GO 执行包；真实签字缺失时保持 NO-GO。

程序化定义见 `config/platform-iteration-program.json`。
