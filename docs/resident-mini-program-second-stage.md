# T04-MP 居民端小程序第二阶段

## 本轮可上线能力

本阶段在首个可运行增量上补齐会话恢复、网络降级、安全深链、消息闭环与平台桥接异常处理。入口仍为 `resident-mini-program.html`，微信、支付宝及移动网页共用同一套居民范围和最小化投影规则。

- 启动与恢复：每次启动、回到前台或网络恢复均重新核验本地服务端会话、`/api/auth/me` 主体、有效期和居民范围。进入后台、断网、主体变化或会话失效时立即中止请求，并清空居民详情、筛选、草稿、消息选择、临时操作和内存数据。已成功运行过的页面恢复后一律从居民首页开始。
- 网络降级：身份、状态和消息接口统一支持加载、超时、离线、失败、重试和空状态。超时或离线时不读取居民缓存，也不把本地点击展示成服务端成功。
- 安全深链：页面、参数和值均使用显式白名单；拒绝外部网址、脚本协议、路径跳转、未知页面、未知参数、不安全标识、跨居民参数、消息与页面不匹配以及过期消息。
- 消息待办：单批最多一百条，默认每页十条、最多三十条；以稳定消息标识去重并统一计算未读数。过期消息只读展示，不允许跳转或标记。已读写入携带稳定幂等键，只有居民、消息和服务端回执全部匹配后才更新；失败或超时保持原未读状态。
- 平台桥接：仅探测导航、拨号和生命周期能力的布尔值；微信与支付宝调用结果只映射为允许的状态和中文说明。取消、拒绝、超时和失败均不显示成功，也不读取、返回或持久化平台原始对象及无关隐私字段。
- 移动与无障碍：加载骨架、错误门禁、重试按钮、焦点转移、屏幕阅读器播报、大字、高对比和减少动态效果已统一。专项端到端测试覆盖 390×844 无横向溢出和主要触控目标不小于 44 像素。
- 中文门禁：`scripts/resident-mini-program-chinese-scan.js` 自动扫描壳层、业务状态、居民范围原因和平台异常文案；端到端测试继续扫描消息主内容，防止内部英文状态回归。

## 安全与数据边界

居民范围继续调用 `citizen-records-policy`、`citizen-records-v1` 和 `citizen-records-v2` 的关系证据、有效授权及最小化策略。家庭成员只有同时出现在当前服务端确认范围内时才能切换；任何不一致均关闭访问，不提供宽松回退。

本模块不生成永久下载地址、对象键、令牌副本、审计哈希或居民数据导出。平台适配层只在设备侧保存大字和高对比两项布尔偏好。挂号、护理、陪诊、家医、急救、授权和消息操作均不得由前端自行宣称办理成功；当前仅消息已读具备生产写入路径，且必须等待服务端有效回执。

## 验收与回归

### 移动端测试收尾问题记录

中断时的行式输出停在 `[8/8]`，但进程与失败证据表明第 8 项主体变化用例已完成；实际失败发生在第 7 项超时重试。首个被延迟的 `/api/state` 拦截处理器尚未释放时触发第二次请求，导致重试继续排队并再次超时。消息失败回滚用例还错误依赖了会随日期过期的共享基线消息。现在每项写入测试先重置数据，消息用例返回当日且只属于当前居民的确定性消息，超时用例等待首个拦截处理器完成后再重试。

原公共 Playwright 配置在 Windows 下通过命令壳形成 `Playwright → cmd.exe → node test-server.js` 子进程树。诊断时曾观察到浏览器上下文已关闭、5210 已无监听，但测试工作进程和服务子进程仍在收尾，行式输出没有及时给出汇总。T04 专属编排器改为 `shell: false` 直接拥有服务子进程，以 IPC 完成优雅关闭，并将“服务退出且端口释放”作为测试成功条件。

专项命令：

```text
node --test test/resident-mini-program-core.test.js test/resident-mini-program-stage2.test.js test/resident-mini-program-chinese-scan.test.js test/resident-mini-program-static.test.js test/resident-mini-program-readiness.test.js
node scripts/resident-mini-program-chinese-scan.js
node scripts/resident-mini-program-readiness.js
node scripts/resident-mini-program-e2e.js
```

本地预览：

```text
node scripts/resident-mini-program-preview.js
http://127.0.0.1:5173/resident-mini-program.html
```

专属预览脚本从基线数据库复制临时数据后再启动服务，登录、会话和审计写入不会修改工作树中的 `data/db.json`。

登录居民账号后重点验证：启动恢复、后台清空、断网恢复、超时重试、越权深链阻断、消息失败回滚、过期消息、中文状态、焦点播报以及 390×844 布局。

移动端测试必须通过 T04 专属编排器运行。编排器直接创建测试服务子进程，不经过 Windows 命令壳；结束时通过 IPC 请求服务先关闭 HTTP 监听和会话清理计时器，再清理临时数据目录，并断言子进程退出且 5210 端口已释放。任一清理断言失败都会使测试命令失败，避免行式报告器停在最后一项时掩盖服务收尾问题。

## 软件就绪判断

第二阶段代码与专项门禁通过后可交由 T00 集成，但不等同于生产环境已上线。以下外部依赖仍未由本工作树实现：

- T00：将入口加入公共 `server.js` 静态路由白名单和站内导航；将资源加入 `service-worker.js`、公共测试命令、README 与发布总表；确认安全响应头、内容安全策略和版本缓存策略。
- T00/服务端：正式提供小程序登录凭证交换、会话撤销、主体变化通知、居民范围收敛、消息游标或批次协议、过期时间、幂等回执及统一超时约定；接口必须保持失败关闭。
- 现场平台：配置微信和支付宝正式应用标识、服务器域名白名单、隐私协议、用户授权说明及真机能力矩阵；完成取消、拒绝、超时、回前台和弱网真机演练。
- 业务现场：接入权威实名与家庭关系证据、授权有效期及撤权拦截；接入短信、订阅消息、支付、医保、号源、护理、陪诊、家医和急救协同的真实服务端回执。
- 上线前联合验收：完成居民数据脱敏检查、无障碍人工检查、适老化大字真机检查、接口容量与故障演练、审计和投诉处置流程确认。

在这些依赖完成前，软件状态应表述为“第二阶段增量已具备集成条件，生产上线受外部依赖约束”。
