# 试点切换告警运行时闭环

## 完成范围

T00 已完成监控告警从领域能力到中央运行时的集成：

1. 独立 worker 周期性读取切换控制面，只投递技术元数据；
2. 请求路径只提供状态查询和受委员会权限保护的生命周期命令，不同步投递；
3. 告警确认、升级、恢复、死信重放均使用登录账号作为 `actorAccount`；
4. 适配器未就绪、日志链损坏、死信未清零或 P0 未恢复时保持 `blocked`；
5. 所有投影都明确 `productionReady=false`、`cutoverExecutionAuthorized=false`；
6. 部署模板默认禁用 worker，环境管理系统完成账号、日志和 HTTPS 路由注入后方可启用。

## 运行入口

```text
npm run platform:cutover-alert-worker -- status
npm run platform:cutover-alert-worker -- status --require-operational
npm run platform:cutover-alert-worker -- run-once
```

定时运行使用：

```text
deploy/platform-cutover-alert-worker.service.template
deploy/platform-cutover-alert-worker.timer.template
```

不得在 `PLATFORM_PILOT_CUTOVER_ALERT_WORKER_ENABLED=true` 之前启用 timer。worker 使用独立服务账号，不能读取切换签名私钥，也不能直接修改授权账本。

## 组合边界

`src/platform/cutover/pilot-cutover-alert-runtime.js` 是库级运行时，只消费调用方显式提供的
`controlProvider`，不得导入 `server.js`。CLI 入口在自己的组合边界建立懒 provider，并复用
现有 `server.pilotCutoverControlPlaneReadiness`；创建默认 runtime 或执行 `status` 不会加载
组合根，`run-once` 才读取真实控制面。

provider 缺失、不是函数、返回无效投影或执行失败时，worker 保持 `NO-GO`、
`productionReady=false` 与 `cutoverExecutionAuthorized=false`。周期报告 schema 标识仍为
`pilot-cutover-alert-worker-cycle-v1`，仅增加受限的 `controlErrorCode` 作为兼容字段；不得输出
provider 错误正文、响应 payload、端点或凭据。

## API

```text
GET  /api/production-adapters/pilot-cutover/alerts
POST /api/production-adapters/pilot-cutover/alerts/:fingerprint/acknowledge
POST /api/production-adapters/pilot-cutover/alerts/:fingerprint/escalate
POST /api/production-adapters/pilot-cutover/alerts/:fingerprint/recover
POST /api/production-adapters/pilot-cutover/alerts/:fingerprint/redrive
```

以上接口要求委员会角色。命令中的操作者由会话身份确定，调用方不能在请求体中伪造账号。

## 环境变量

中央部署清单至少配置：

```text
PLATFORM_PILOT_CUTOVER_ALERT_WORKER_ENABLED=false
PLATFORM_PILOT_CUTOVER_ALERT_WORKER_ACCOUNT=
PLATFORM_PILOT_CUTOVER_ALERT_JOURNAL_FILE=
PLATFORM_PILOT_CUTOVER_MONITORING_ACCEPTANCE_FILE=
```

SIEM/Webhook 地址、签名密钥、重试次数和路由选择继续使用 `deploy/pilot-cutover-monitoring.env.template`，由密钥和环境管理系统注入，不进入仓库。

## 验收边界

仓库自动化测试只证明软件行为：稳定告警身份、重试与死信、哈希链、防敏感字段、鉴权命令及失败关闭。真实 SIEM/Webhook 回执、值班通知、升级工单、恢复演练和双方签署材料必须从外部受控证据库采集；缺少任一证据时仍为 `NO-GO`。
