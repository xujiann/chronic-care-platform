# 试点切换监控与安全验收闭环

## 交付目标

本迭代把切换控制面的健康状态转换为可投递、可确认、可升级、可恢复的告警生命周期，同时保留完整的哈希链审计。实现仅处理受控引用、摘要、计数和账号等技术元数据，不读取患者数据，不保存接收端原文，不把仓库内配置当作监控验收证据。

覆盖的硬阻断信号：

- 外部证据或审批已过期、即将过期；
- 账本事件已撤销；
- 公钥不存在、过期、账号或职责范围不匹配；
- attestation、nonce、规范化摘要或 Ed25519 签名异常；
- 授权账本链损坏或不可验证；
- 预生产演练缺失、失败或超出新鲜度窗口。

## 状态机

```text
alert-opened
  -> delivery-attempted
     -> delivery-acknowledged
     -> delivery-failed -> retry
                        -> delivery-dead-lettered
                           -> dead-letter-redriven

alert-opened
  -> alert-acknowledged
  -> alert-escalated
  -> alert-recovered
```

恢复必须发生在人工确认或升级之后；死信重放必须有工单或证据引用及 SHA-256 摘要。恢复不是删除，全部状态转换继续保留在追加写日志中。

## 数据最小化与安全边界

- 日志文件必须是绝对路径下的普通文件，拒绝符号链接，并受单事件和总文件大小限制。
- 写入使用独占锁，事件包含连续序号、前序摘要和当前事件摘要；任何篡改都会使读取 fail-closed。
- 接收端错误原文只参与本地即时摘要计算，日志仅保存稳定错误码和 SHA-256。
- 外部回执 ID 不落盘，日志保存 `monitoring://` 受控引用及其摘要。
- SIEM/Webhook 地址、签名密钥和令牌仅从部署环境或密钥管理系统注入，状态查询不返回这些值。
- 接收端未配置、非 HTTPS、日志不可用、链校验失败或投递未全部成功时，适配器保持 `failClosed: true`、`productionReady: false`。

## 部署配置

以 `deploy/pilot-cutover-monitoring.env.template` 为清单，通过密钥管理系统注入真实值。

运行账号需要：

1. 对告警日志所在目录具有最小写权限；
2. 只允许访问批准的 HTTPS 接收端；
3. 无权读取切换签名私钥；
4. 无权直接修改授权账本；
5. 告警日志进入独立备份、留存和完整性巡检。

生产式环境至少启用 SIEM 或 Webhook 中的一条；双路由时，任一路由失败都保持本次投递 `failClosed`，失败路由进入死信。

## 验收步骤

使用 `docs/evidence-templates/pilot-cutover-monitoring-acceptance-v1.json` 在外部受控证据库完成以下真实验证：

1. 注入不含业务明细的测试控制信号，检查接收端仅收到最小化元数据；
2. 验证接收回执和日志摘要一致，且日志中没有接收端原文、凭据和患者标识；
3. 值班人完成确认，检查账号、工单引用与摘要写入审计链；
4. 触发 P0 升级，验证通知、升级策略、值班席位和工单状态；
5. 使接收端真实不可用，验证重试达到上限后进入死信；
6. 经审批恢复接收端并重放死信，验证使用相同告警身份且不重复生成业务事件；
7. 关闭原信号，先确认/升级后执行恢复，验证日志链连续；
8. 将日志头摘要、接收端回执、工单和双方签署的验收材料写入受控证据库。

模板中的 `status` 默认是 `not-collected`，仓库内测试结果不能替代真实接收端、值班、升级和恢复验收。

## T00 集成交接

T03 不修改中央 server、路由顺序、CI、package scripts 或流程所有权清单。T00 集成时需要：

1. 在中央运行时周期性读取切换控制结果，调用 `derivePilotCutoverAlertCandidates`；
2. 由独立 worker 调用 `deliverPilotCutoverAlert`，不要在请求路径同步投递；
3. 为状态查询接入 `buildPilotCutoverAlertProjection`；
4. 为确认、升级、恢复、死信重放提供委员会角色保护的命令 API；
5. 把 `pilotCutoverMonitoringAdapterStatus().adapterReady` 纳入部署就绪检查，但仍不得把它解释为真实监控验收；
6. 把日志链损坏、死信未清零、P0 未恢复作为 `NO-GO` 硬阻断；
7. 将模板环境变量加入受控部署清单，并把实际文件路径和密钥注入留给环境管理系统。

建议的只读与命令接口：

```text
GET  /api/production-adapters/pilot-cutover/alerts
POST /api/production-adapters/pilot-cutover/alerts/:fingerprint/acknowledge
POST /api/production-adapters/pilot-cutover/alerts/:fingerprint/escalate
POST /api/production-adapters/pilot-cutover/alerts/:fingerprint/recover
POST /api/production-adapters/pilot-cutover/alerts/:fingerprint/redrive
```

所有命令必须使用登录账号作为 `actorAccount`，不得接受调用方自行伪造账号。
