# 医学影像云功能说明

本模块依据《辽宁省医学影像云功能规范》和《辽宁省医学影像云技术规范》建设区域医学影像云演示能力，承接医院 PACS/RIS/EMR 影像数据入云、患者手机调阅、授权分享、质控统计和电子病历兼容索引。

## 主要功能

- 医院接入：支持前置网关和无前置采集软件两种模式，记录 DICOM C-STORE/C-MOVE、DICOM TLS、RIS 结构化检查信息、审核报告和对象存储地址。
- 影像云存储：按检查保存诊断级 DICOM 序列和浏览级预览索引，记录序列数、图像数、完整性校验、无损压缩和云端对象路径。
- 患者手机查看：`imaging-cloud.html` 提供移动端影像查看模拟，患者实名登录后查看报告、浏览级序列、诊断级状态和限时分享状态，终端不保存原始 DICOM。
- 授权分享：`POST /api/imaging-cloud/studies/:id/share` 生成二维码或短信链接型分享令牌，可设置有效期并写入访问留痕。
- 质控管理：`POST /api/imaging-cloud/studies/:id/qc` 记录扫描评价、报告评分、质控结论和复核意见。
- 电子病历兼容：医院入库接口会同步生成 `diagnosticReports` 和 `personalRecords` 影像记录，EMR 可通过“医疗机构编码 + 身份证号 + 检查号”主索引授权调阅。

## 当前已实现功能

- 已实现医院影像数据接入：`POST /api/imaging-cloud/ingest` 支持接入 DICOM/RIS/PACS 检查，并同步生成影像云检查、诊断报告和居民影像档案。
- 已实现患者手机查看：`imaging-cloud.html` 提供手机影像查看、序列预览、报告结论、分享状态和终端不保存原始 DICOM 的提示。
- 已实现电子病历兼容索引：影像入云后写入 `diagnosticReports` 与 `personalRecords`，并保留 `mainIndex`、`studyInstanceUID`、`imageCloudStudyId` 等调阅字段。
- 已实现授权分享与质控回写：支持影像检查限时分享、二维码/短信链接渠道、质控评分和质控结论回写。
- 已实现跨机构影像互认闭环：影像云检查可生成县域协同工单、互认记录、报告引用和主索引；医共体或卫健端确认后同步检查状态、报告状态与审计证据。
- 已实现不予互认申诉复核：来源机构以最小化证据引用提交申诉，原判定人和申诉提交人不得复核；独立复核结论同步影像、诊断报告、协同工单、引用哈希和审计记录。
- 已实现角色权限与越权保护：监管端、医疗机构、县域平台、居民端按角色访问；居民只能查看本人或家庭授权范围内影像。
- 已实现自动化证据：`imaging-cloud:readiness`、`test/imaging-cloud-readiness.test.js`、`test/static.test.js`、`test/api.test.js` 覆盖页面、API、PWA、EMR 索引同步和越权拒绝。

## 接口

- `GET /api/imaging-cloud`：返回影像云汇总、网关、检查、分享、质控、EMR 兼容和安全基线。
- `POST /api/imaging-cloud/ingest`：医院或监管端提交影像检查，生成影像云检查、诊断报告和居民健康信息库影像索引。
- `POST /api/imaging-cloud/studies/:id/share`：患者或授权机构生成限时分享。
- `POST /api/imaging-cloud/studies/:id/qc`：机构或监管端回写质控结果。
- `POST /api/imaging-cloud/studies/:id/mutual-recognition`：机构、医共体或卫健端将影像检查纳入跨机构互认，生成协同工单、互认记录和报告引用。
- `POST /api/imaging-cloud/studies/:id/mutual-recognition/decision`：医共体或卫健端确认或拒绝互认，同步更新影像检查、诊断报告、协同工单和审计证据。
- `POST /api/imaging-cloud/studies/:id/mutual-recognition/appeal`：来源机构对不予互认结果提交理由和最小化证据引用，并确认不包含患者可识别信息。
- `POST /api/imaging-cloud/studies/:id/mutual-recognition/appeal/review`：医共体或卫健端由独立复核人通过或驳回申诉，复用互认引用证据链。

## 安全与部署约束

- 计算与存储资源按规范要求落在本地省域可控环境。
- 传输使用 HTTPS、DICOM TLS、专线或 SD-WAN + IPSEC，敏感结构化数据按 AES 加密要求设计。
- 按等保三级基线组织边界防护、主机防护、运维审计、访问控制和日志留痕。
- 患者影像具有属主性，所有调阅、分享和医生访问都必须经过身份认证、授权和审计。
