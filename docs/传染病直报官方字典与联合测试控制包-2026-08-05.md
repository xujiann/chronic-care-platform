# 传染病直报官方字典与联合测试控制包

## 目标

把“代码已实现”和“站点已具备启动条件”分开。独立 Worker 只有在官方字段字典、联合测试证据和信任注册表同时通过校验时才允许执行投递；控制包通过也不等于生产切换获批。

## 三份站点注入文件

| 环境变量 | 内容 | 关键约束 |
| --- | --- | --- |
| `PUBLIC_HEALTH_DIRECT_REPORT_DICTIONARY_FILE` | 官方字段映射和码表 | 绝对路径、普通文件、非符号链接、已批准且在有效期内 |
| `PUBLIC_HEALTH_DIRECT_REPORT_JOINT_TEST_EVIDENCE_FILE` | 联合测试结果 | 8 个场景全部通过、绑定字典摘要和映射指纹、最长 168 小时 |
| `PUBLIC_HEALTH_DIRECT_REPORT_TRUST_REGISTRY_FILE` | 独立签署方公钥 | 疾控业务部门与医院信息中心分别使用有效 Ed25519 公钥 |

模板位于 `docs/evidence-templates/public-health-direct-report/`。模板只能复制到站点受控目录后填写，不可直接用于启用 Worker。

## 必须通过的场景

1. 正常报文接受；
2. 非法码值拒绝；
3. 报文最小化；
4. 幂等重放；
5. 超时有限重试；
6. 拒绝进入死信；
7. 签名回调；
8. 投递与回执对账。

任何场景缺失、摘要漂移、证据过期、签名无效或签署密钥复用都会阻断启动。

## 运维检查

执行 `npm run public-health:direct-report-control:status` 可获取脱敏状态；发布门禁使用 `npm run public-health:direct-report-control:require-ready`。输出不包含码值、公钥、签名、凭据或原始报文。

委级门户和 `/api/public-health/infectious-reporting-control-package` 只显示同一份最小状态投影。界面没有人工“通过”动作。

## 边界

- 控制文件不进入数据库和投递箱；
- 私钥不得写入信任注册表或项目仓库；
- Worker 发送前仍逐条按当前字典校验报文；
- 控制包通过只解除直报 Worker 的局部门禁，生产上线仍受平台统一 Go/No-Go 决策约束。
