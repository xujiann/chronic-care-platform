# 浏览器安全响应头与 CSP 治理

## 当前结论

SEC-004 已建立 `browser-security-headers.v1` 集中端口和 `browser-security-risk-inventory.v1` 机器清单，并完成显式发布图内联脚本/样式外移；严格 CSP 尚未强制，平台仍不是生产就绪。

- 动态 HTML、静态资源、JSON、下载和错误响应继续通过同一服务端响应头端口。
- 兼容 CSP 仍强制 `base-uri 'self'`、`object-src 'none'`、`frame-ancestors 'self'`、`script-src-attr 'none'`，并在动态样式验证完成前暂时保留 inline 兼容。
- 严格目标通过 `Content-Security-Policy-Report-Only` 下发，不含 `unsafe-inline` 和 `unsafe-eval`。
- `X-Frame-Options: SAMEORIGIN`、`X-Content-Type-Options: nosniff`、`Referrer-Policy: no-referrer`、受限 `Permissions-Policy` 和生产 HSTS 由集中端口生成。
- 静态发布制品显式包含 `browser-security-policy.json`；它是托管配置合同，不证明实际静态托管响应头已生效。

## 资产清单

`npm run security:browser:inventory` 扫描 `config/static-publication.json` 的显式发布图，不扫描仓库中未发布的文件。首批 58 项风险已迁移，当前基线：

| 优先级 | 类型 | 数量 | 处置 |
|---|---|---:|---|
| P0 | executable inline script | 0 | 37 项已迁至共享页面守卫和页面外部脚本 |
| P0 | event handler / javascript URL / eval / Function / string timer | 0 | CI 禁止新增 |
| P1 | inline style block | 0 | 8 项已迁至外部样式表 |
| P1 | style attribute | 0 | 13 项已迁为受控 class |
| P2 | inert inline data script | 0 | 保持盘点，不作为可执行脚本放行依据 |

基线按资产、风险类型和规范化片段 SHA-256 记录。新增任何 P0/P1 高风险片段会以 `BROWSER_SECURITY_HIGH_RISK_ADDITION` 失败关闭。页面守卫统一由 `page-auth-bootstrap.js` 读取 `data-roles`/`data-account-types`，角色后账户类型的失败关闭顺序由测试锁定；PWA 注册和手机预览运行时也已外部化。

## 命令与验收

```powershell
npm.cmd run security:browser:inventory
npm.cmd run security:browser:verify
npm.cmd run static:check
npm.cmd run static:test
npm.cmd run build
```

下一仓库内阶段必须完成动态 CSSOM、全角色浏览器和恶意输入回归，再独立移除兼容 `unsafe-inline`。生产验收还必须在仓库外完成动态入口和真实静态托管/CDN 的响应头抓取、严格 CSP 强制试点、独立 XSS/点击劫持评估和严重发现关闭。仓库测试、Report-Only 控制台信息或策略 JSON 均不能替代这些证据。

## 非目标

- 不重写 44 个页面或全局前端控制器；本次只迁移发布图中的静态高风险构造。
- 不引入 `unsafe-eval`、通配脚本源或任意 frame 来源。
- 不建立仓库内伪造 CSP 上报、扫描或渗透证据。
- 不因兼容 CSP 存在而宣称严格 CSP 已强制。
