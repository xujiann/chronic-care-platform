# 浏览器安全响应头与 CSP 治理

## 当前结论

SEC-004 第一切片建立了 `browser-security-headers.v1` 集中端口和 `browser-security-risk-inventory.v1` 机器清单，但没有关闭 CSP，也没有把平台标记为生产就绪。

- 动态 HTML、静态资源、JSON、下载和错误响应继续通过同一服务端响应头端口。
- 兼容 CSP 仍强制 `base-uri 'self'`、`object-src 'none'`、`frame-ancestors 'self'`、`script-src-attr 'none'`，并暂时保留 inline 脚本/样式兼容。
- 严格目标通过 `Content-Security-Policy-Report-Only` 下发，不含 `unsafe-inline` 和 `unsafe-eval`。
- `X-Frame-Options: SAMEORIGIN`、`X-Content-Type-Options: nosniff`、`Referrer-Policy: no-referrer`、受限 `Permissions-Policy` 和生产 HSTS 由集中端口生成。
- 静态发布制品显式包含 `browser-security-policy.json`；它是托管配置合同，不证明实际静态托管响应头已生效。

## 资产清单

`npm run security:browser:inventory` 扫描 `config/static-publication.json` 的显式发布图，不扫描仓库中未发布的文件。首批基线：

| 优先级 | 类型 | 数量 | 处置 |
|---|---|---:|---|
| P0 | executable inline script | 37 | 按页面迁移到外部脚本，保持加载顺序与角色行为 |
| P0 | event handler / javascript URL / eval / Function / string timer | 0 | CI 禁止新增 |
| P1 | inline style block | 8 | 逐页迁移到外部样式 |
| P1 | style attribute | 13 | 迁移为受控 class/token |
| P2 | inert inline data script | 0 | 保持盘点，不作为可执行脚本放行依据 |

基线按资产、风险类型和规范化片段 SHA-256 记录。P0/P1 当前风险可以减少；新增、复制或替换为新的高风险片段会以 `BROWSER_SECURITY_HIGH_RISK_ADDITION` 失败关闭。更新基线必须与实际风险减少、页面测试和 review 同一 PR 完成，不能为让 CI 通过而扩大。

## 命令与验收

```powershell
npm.cmd run security:browser:inventory
npm.cmd run security:browser:verify
npm.cmd run static:check
npm.cmd run static:test
npm.cmd run build
```

生产验收还必须在仓库外完成动态入口和真实静态托管/CDN 的响应头抓取、严格 CSP 强制试点、全角色浏览器回归、独立 XSS/点击劫持评估和严重发现关闭。仓库测试、Report-Only 控制台信息或策略 JSON 均不能替代这些证据。

## 非目标

- 不一次性重写 44 个页面或全局前端控制器。
- 不引入 `unsafe-eval`、通配脚本源或任意 frame 来源。
- 不建立仓库内伪造 CSP 上报、扫描或渗透证据。
- 不因兼容 CSP 存在而宣称严格 CSP 已强制。
