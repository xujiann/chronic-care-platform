# 体检系统创新亮点设计与验收（2026-07-17）

## 1. 产品定位

体检系统不再只保存一次性报告，而是将体检结果转换为连续健康管理服务。所有亮点沿用居民主索引、`personalRecords[physical-exam]`、角色/机构/居民授权、访问审计和现有慢病、家医、预约及居民待办能力。

医学边界：趋势、居民解释、检查计划、家庭风险和情景模拟属于健康管理辅助；诊断、危急值、药物调整、检查适应证和是否复用既往结果必须由执业医师确认。

## 3. 关键数据结构

### 3.1 计算结果

`GET /api/physical-exams` 的 `highlights` 字段包含：

- `trajectories`
- `translations`
- `actionCards`
- `examPlans`
- `repeatAvoidance`
- `radiationLedger`
- `criticalPaths`
- `familyRiskMaps`
- `achievements`
- `healthPassports`
- `simulations`
- `qualityReviews`
- `institutionBenchmarks`
- `cityRadar`
- `standardsImpact`

这些结果均从授权范围内的体检报告和异常任务实时派生，不另建居民体检数据孤岛。

### 3.2 可审计动作

统一接口：`POST /api/physical-exams/highlights/actions`

支持动作：

- `acknowledge-action`：居民确认已了解异常行动；
- `request-review`：生成幂等复查申请，进入号源确认队列；
- `create-passport`：按选择范围创建1～30天健康护照授权；
- `revoke-passport`：居民撤销授权；
- `authorize-family-map`：记录家庭风险线索授权版本、范围和期限。

持久化集合：

- `physicalExamReviewRequests`
- `physicalExamHealthPassports`
- `physicalExamFamilyRiskConsents`
- `physicalExamHighlightActions`

所有动作执行居民数据权限检查，并写入访问日志和安全事件。

## 4. 隐私与安全控制

- 家庭健康地图按成员逐人授权，未授权时不显示姓名、疾病或指标。
- 城市健康雷达使用去标识化聚合，低于最小样本阈值的单元不显示人数。
- 健康护照仅保存授权范围、目的、期限和审计引用，不生成绕过认证的公共访问地址。
- 机构质量画像在样本不足时不排名；正式比较前必须按年龄、风险和项目结构校正。
- AI/规则解释保存来源报告、参考范围、规则版本和安全边界。

## 5. 验收方法

```powershell
npm.cmd run physical-examination:test
npm.cmd run physical-examination:readiness
node --test test/static.test.js
```

核心自动验收：

1. 同一共享引擎在Node和浏览器加载；
2. 15类亮点均有数据结构或空状态；
3. 复查申请幂等；
4. 健康护照可创建和撤销；
5. 越权居民操作返回403；
6. 家庭地图未授权成员保持锁定；
7. 城市雷达小样本抑制；
8. 情景模拟包含非诊断免责声明；
9. 管理端与居民端均有可验收页面；
10. 真实生产阻断仍在就绪报告中明确展示。

## 6. 生产边界

代码完成不代表正式上线。仍需接入真实体检问卷、医院号源、机构项目字典、危急值目录、PACS/设备剂量、医师与机构主数据、CA签名、对象存储、短信/电话送达回执以及机构现场验收证据。
