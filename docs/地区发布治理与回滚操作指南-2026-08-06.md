# 地区发布治理与回滚操作指南

日期：2026-08-06

## 1. 目标与安全边界

本模块为每个地区提供不可变发布身份、受控状态转换、版本差异和回滚判定。它解决“发布了什么、由谁操作、引用了哪份外部决定、可以回到哪里”的可审计问题。

本模块不签发生产许可：

- 注册表及每一条事件都固定为 `productionReady: false`。
- `approved-candidate` 只表示技术候选已引用受控外部证据并完成独立复核，不等同于批准投产。
- `deployed` 只记录外部主管机构已经作出的决定；工具不能创建或替代该决定。
- 注册表只保存 `controlled://` 引用、SHA-256 摘要、操作者和时间，不保存证书、密钥、患者数据、原始接口消息或签字文件。
- 应用回滚和数据回滚是两个决定；工具只给出判定，不执行部署或恢复。

## 2. 状态机

```text
new
 └─ draft
     └─ validation
         └─ approved-candidate
             └─ deployed
                 ├─ verified
                 │   └─ rolled-back
                 └─ rolled-back
```

不支持跳级、重复转换和从 `rolled-back` 恢复。要再次发布，必须产生新的不可变地区发布身份。

关键门禁：

| 转换 | 必要条件 |
| --- | --- |
| `new → draft` | 地区发布身份完整，平台、组合发布和地区内容摘要均为 SHA-256 |
| `draft → validation` | 当前身份未变化 |
| `validation → approved-candidate` | 生产级地区包、受控外部证据引用和摘要、与操作者不同的独立复核者 |
| `approved-candidate → deployed` | 受控外部授权决定引用和摘要，决定记录人必须独立于部署操作者 |
| `deployed → verified` | 部署后的验证工作已经由责任人完成并记录原因 |
| `deployed/verified → rolled-back` | 存在上一稳定版本；数据回滚为“不需要”或已有受控快照 |

## 3. 不可变发布身份

每个地区发布身份绑定：

- 地区代码、地区版本、部署级别；
- 平台版本和平台制品摘要；
- 地区组合发布摘要；
- 地区内容摘要；
- 数据变更级别；
- 可选的受控回滚快照引用和摘要。

身份计算后不能改变。相同 `releaseId` 不能绑定另一组摘要，相同组合发布摘要也不能绑定另一个发布身份。注册表使用全局追加事件链；修改历史事件会导致校验失败。

配置文件：

```text
config/regional-release-registry.json
```

该仓库文件是本地受控账本。正式生产还应将同一发布身份同步至具备保留策略、访问控制和签名能力的外部不可变制品库。

## 4. 建议的 npm 命令

由 T00 集成时加入：

```json
{
  "regional:release-governance": "node scripts/regional-release-governance.js",
  "regional:release-governance:test": "node --test test/regional-release-governance.test.js",
  "regional:release-governance:check": "node --check src/platform/regional/regional-release-governance.js && node --check scripts/regional-release-governance.js"
}
```

未完成集成前，可将下列示例中的 `npm run regional:release-governance --` 替换为：

```powershell
node scripts/regional-release-governance.js
```

所有写命令默认只生成计划。只有显式增加 `--write` 才会落盘。

## 5. 标准操作

### 5.1 校验和查看状态

```powershell
npm run regional:release-governance -- verify
npm run regional:release-governance -- status
```

### 5.2 注册不可变草稿

先由地区组合发布流程生成：

```text
release/regions/210200/composite-release.json
```

预览注册计划：

```powershell
npm run regional:release-governance -- register `
  --composite=release/regions/210200/composite-release.json `
  --platform-digest=sha256:<平台制品64位摘要> `
  --data-impact=none `
  --actor=release-operator `
  --reason=注册地区组合发布
```

确认计划中的平台、地区和组合发布摘要后，以相同参数增加 `--write`。

数据变更级别只能是：

- `none`：不改变持久化数据；
- `backward-compatible`：有向后兼容迁移；
- `breaking`：有不兼容迁移。

若不是 `none`，注册时应同时绑定回滚快照：

```powershell
--snapshot-ref=controlled://regional/backups/210200/release-002 `
--snapshot-digest=sha256:<64位摘要> `
--snapshot-at=2026-08-06T08:00:00.000Z `
--snapshot-by=backup-custodian
```

### 5.3 进入验证

```powershell
npm run regional:release-governance -- transition `
  --region=210200 `
  --release=<releaseId> `
  --to=validation `
  --actor=validation-operator `
  --reason=进入地区验证环境 `
  --write
```

### 5.4 形成生产候选

外部联合测试、安全评估、灾备演练和现场验收应先在受控证据系统形成证据包。仓库只登记其引用和摘要：

```powershell
npm run regional:release-governance -- transition `
  --region=210200 `
  --release=<releaseId> `
  --to=approved-candidate `
  --actor=release-operator `
  --reason=外部证据齐备并提交生产候选 `
  --evidence-ref=controlled://regional/evidence/210200/package-20260806 `
  --evidence-digest=sha256:<64位摘要> `
  --evidence-at=2026-08-06T09:00:00.000Z `
  --evidence-by=evidence-custodian `
  --reviewer=independent-reviewer `
  --reviewed-at=2026-08-06T09:30:00.000Z `
  --write
```

`reviewer` 不能等于 `actor`。

### 5.5 记录外部投产决定

主管机构在仓库外完成授权后，记录该决定：

```powershell
npm run regional:release-governance -- transition `
  --region=210200 `
  --release=<releaseId> `
  --to=deployed `
  --actor=deployment-operator `
  --reason=记录外部批准后的部署结果 `
  --authorization-ref=controlled://regional/authority/210200/decision-20260806 `
  --authorization-digest=sha256:<64位摘要> `
  --authorization-at=2026-08-06T10:00:00.000Z `
  --authorization-by=site-authority `
  --write
```

`authorization-by` 不能等于部署 `actor`。登记成功仍然不会产生 `productionReady: true`。

### 5.6 部署后验证

完成应用健康、地区上下文、关键业务、监控和备份验证后登记：

```powershell
npm run regional:release-governance -- transition `
  --region=210200 `
  --release=<releaseId> `
  --to=verified `
  --actor=site-verifier `
  --reason=部署后验证项目全部通过 `
  --write
```

## 6. 版本差异

```powershell
npm run regional:release-governance -- diff `
  --region=210200 `
  --from=<上一releaseId> `
  --to=<本次releaseId>
```

报告明确列出：

- 平台版本和平台制品摘要变化；
- 地区版本和地区内容摘要变化；
- 地区组合发布摘要变化；
- 数据变更级别；
- 是否必须进行数据回滚复核。

差异报告不替代数据库迁移评审和现场变更审批。

## 7. 回滚判定和登记

先生成判定：

```powershell
npm run regional:release-governance -- rollback `
  --region=210200 `
  --release=<当前releaseId>
```

判定规则：

1. 只能对该地区当前活动发布生成回滚，不能回滚已经被后续版本替代的历史发布。
2. 应用回滚目标是同一地区、当前发布部署之前最近一个未回滚的 `verified` 发布。
3. 当前发布 `dataImpact=none` 时，数据恢复标记为 `not-required`。
4. 当前发布有数据变更且绑定了受控快照时，数据动作是 `restore-controlled-snapshot`。
5. 没有上一稳定版本或数据变更没有快照时，`executable=false`，拒绝登记回滚。

满足条件后登记：

```powershell
npm run regional:release-governance -- transition `
  --region=210200 `
  --release=<当前releaseId> `
  --to=rolled-back `
  --actor=rollback-operator `
  --reason=现场回滚决定和执行结果已确认 `
  --write
```

登记事件会固化上一稳定版本、应用动作和数据动作，但不会执行回滚。实际操作仍按部署和数据库恢复手册实施。

## 8. 并发和失败处理

转换计划绑定当前注册表摘要和链头摘要。写入时会再次读取注册表并比较：

- 期间已有其他事件写入：以“计划已陈旧”拒绝；
- 计划内容被修改：以“计划被修改”拒绝；
- 注册表历史被改动：校验失败；
- 另一进程持有锁：不抢占、不删除他人的锁；
- JSON 损坏或写入失败：不追加事件。

遇到陈旧计划时应重新执行预览、重新复核差异，再使用新计划写入，不能绕过 CAS 校验。

## 9. 上线交接清单

- [ ] 地区组合发布自身校验通过且 `productionReady=false`。
- [ ] 平台制品 SHA-256 来自受控制品库，而不是手工猜测。
- [ ] 发布注册后平台、组合发布和地区内容摘要未漂移。
- [ ] 外部证据包存放在受控系统，只登记引用和摘要。
- [ ] 生产候选复核者独立于发布操作者。
- [ ] 部署事件引用真实外部决定，记录人独立于部署操作者。
- [ ] 数据变更发布已绑定可验证的回滚快照。
- [ ] 回滚前分别确认应用目标和数据动作。
- [ ] 生产许可、现场签字和生产变更单仍在仓库外完成。
