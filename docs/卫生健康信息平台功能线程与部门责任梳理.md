# 卫生健康信息平台功能线程与部门责任梳理

生成日期：2026-07-04

事实来源：`README.md`、`docs/system-flow.md`、`release/health-dashboard-summary.json`、`release/release-report.md`。

## 1. 总体判断

当前系统已经从单一慢病管理演示扩展为覆盖居民服务、医疗协同、医保监管、医政妇幼、质量安全、医院运行、科研治理和平台运维的综合卫生健康信息平台 MVP。

从发布证据看，当前发布报告为 131 项检查全部通过；健康驾驶舱汇总 8 个优先应用，其中 7 个为源业务应用，合计 351 条源记录、12 个开放事项、10 个高风险事项、9 条接口轨道和 9 条证据记录。系统已经具备本地演示、静态预览、Node API、角色权限、数据快照、审计证据和发布报告基础。

当前边界也很清晰：静态预览可以展示页面和脱敏快照，但真实上线必须补齐政务统一身份、居民实名关系、HIS/EMR/LIS/PACS/医保/证照/妇幼/疾控等外部接口、生产数据库、安全测评、监控告警、灾备演练和现场签字。

## 4. 居民端优先上线建议

第一批建议上线“居民健康服务试点版”，范围控制在可解释、可回退、低风险的服务能力：

| 功能 | 上线方式 | 当前基础 | 上线前必须补齐 |
| --- | --- | --- | --- |
| 健康档案 | 只读展示 | 居民健康信息库、指标、来源、风险提示已具备。 | 真实实名、主索引、健康档案接口、访问审计和来源机构展示。 |
| 电子病历 | 只读摘要 | 电子病历、检查检验、用药、出院摘要分类展示已具备。 | EMR/LIS/PACS/文档存储授权、院内接口字段映射和免责声明。 |
| 互联网护理 | 可申请、可跟踪 | 居民申请、机构评估、护士派单接单、定位轨迹、护理记录、质量回访已具备。 | 护士/机构资质核验、服务价格、耗材结算、保险、线下签到和投诉处理。 |
| 陪诊服务 | 可预约、可回访 | 服务主体、陪诊人员、预约、合同保险、风险回访和居民提交前校验已具备。 | 服务人员资质、价格公示、合同附件、保险凭证、履约签到和补贴结算。 |
| 慢病随访 | 可提醒、可反馈 | 慢病随访、筛查宣教、固定取药、家庭医生协同和居民反馈已具备。 | 公卫/家庭医生接口、真实随访计划、药房回调和异常升级规则。 |
| 授权共享 | 试点启用 | 授权共享、撤销、访问历史和审计证据已具备。 | 授权对象实名核验、关系证明、撤销即时生效、第三方调用阻断。 |

暂不建议第一批承诺在线诊疗、处方支付、医保实时结算、正式挂号退号、PACS 原图下载和第三方自由调阅居民健康档案。这些事项依赖强监管、支付、影像存储、真实身份和外部系统签字。

## 6. 当前剩余风险

1. 真实外部接口尚未完成现场联调，系统当前主要证明“平台侧建模、API 和演示闭环”，不能替代医院、医保、证照、公卫等源系统签字。
2. 居民端虽然已经具备健康档案、电子病历、护理、陪诊和慢病待办预览，但正式上线仍依赖实名、短信、HTTPS、移动端发布、隐私协议、授权关系和生产监控。
3. 静态预览只能读取 `data/db.json` 脱敏快照，不能证明 Node API 写入、会话、审计和工作流动作。
4. 生产数据库、审计保全、国密传输、等保密评、灾备演练和运维值守仍属于正式上线阻断项。
5. 第一批上线应采用“居民健康服务试点版”口径，先开放只读档案、服务申请、服务跟踪、授权审计和反馈投诉，不宜直接承诺支付结算、正式处方、在线诊疗和第三方自由调阅。
