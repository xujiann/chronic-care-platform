日期：2026-08-06

## 一、交付结论

平台已从“地区配置可切换”推进到“同一核心可被多个地区独立部署、独立发布、集中观测并受控回滚”的产品线底座。四条开发线均已完成代码、测试、命令和操作文档接线。

仓库内自动化只能证明技术交付就绪，不能制造现场联调、等保密评、商用密码评估、灾备演练或签字批准，因此所有地区发布、复制演练、运维报告和 PostgreSQL 主存储状态都继续明确保持 `productionReady=false`。

## 三、六个迭代

1. 建立严格、无密钥的多站点部署描述和逐站点制品生成。
2. 建立 Docker/Compose 单站点验证模板、服务账号隔离和跨站点资源冲突门禁。
3. 建立地区发布注册表、受控状态机、证据复核、版本差异和回滚计划。
4. 建立集中运维清单、最小化探测回执和管理端 API。
5. 建立 PostgreSQL 主存储契约、正式驱动、数据库结构及生产就绪报告接线。
6. 以生产类地区和测试类第二地区完成同核复制演练，验证地区内容、运行资源、发布账本和生产边界相互隔离。

## 四、统一技术边界

- 一个进程只能激活一个 `REGION_CODE`，并同时锁定地区类别和地区内容摘要。
- 站点描述不得保存口令、令牌、私钥或连接串；秘密只允许由 Vault、KMS 或编排平台注入。
- 运维探测目标只能来自服务端 `REGIONAL_SITE_<地区代码>_BASE_URL`，HTTP 请求不能指定或覆盖目标。
- 最近备份时间只能来自服务端 `REGIONAL_SITE_<地区代码>_BACKUP_CHECKED_AT`，不能由探测请求伪造。
- 探测只允许 HTTPS 根地址，并拒绝重定向、超限响应、本地/私网/链路本地地址和不安全 DNS 结果。
- PostgreSQL 请求路径直接双写永久关闭；影子和主存储演练只接受已提交的 SQLite 事务 outbox。
- `primary-read` 和 `primary-write` 只是受证据约束的演练模式，不代表生产主库已启用。
- 数据变更版本没有受控快照时，不得生成可执行的数据回滚决定。

## 五、常用操作

```powershell
npm.cmd run regional:check
npm.cmd run regional:test
npm.cmd run regional:deploy-plan -- --descriptor=config/regional-replication-sites.json
npm.cmd run regional:release-governance -- status
npm.cmd run regional:operations
npm.cmd run regional:replication
npm.cmd run postgres:primary-storage-contract:check
npm.cmd run postgres:primary-storage-contract:test
npm.cmd run production-db:readiness
npm.cmd run deployment:package
npm.cmd run deployment:verify
```

管理端运维 API：

- `GET /api/regional/deployments`
- `POST /api/regional/deployments/:regionCode/probes`

两个接口均要求平台管理权限；探测接口要求空查询和空请求体。
