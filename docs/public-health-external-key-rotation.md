# 公共卫生外部适配器密钥轮换与回调防重放

## 范围

本增量覆盖八领域外部适配器的请求签名、运行时状态签名、worker 租约、逐任务审计链和外部回执验签。`public-health-external-keyring-service.js` 负责密钥生命周期判定；业务服务只接收瞬时密钥环，不把密钥写入出站箱、审计或就绪报告。

兼容用的字符串静态密钥会映射到 `legacy-static`，可继续执行现有测试和迁移期任务，但 `summarizeKeyring()` 始终把这种配置标为 `productionReady=false`。生产接线必须提供托管密钥环。

## 密钥环契约

请求与回执使用彼此独立的密钥环：

```json
{
  "purpose": "public-health-request",
  "activeKeyId": "request-2026-08",
  "keys": [
    {
      "keyId": "request-2026-07",
      "secret": "<由密钥服务瞬时注入，不得持久化>",
      "status": "grace",
      "notBefore": "2026-07-01T00:00:00.000Z",
      "expiresAt": "2026-08-01T00:00:00.000Z",
      "revokedAt": ""
    },
    {
      "keyId": "request-2026-08",
      "secret": "<由密钥服务瞬时注入，不得持久化>",
      "status": "active",
      "notBefore": "2026-07-23T08:00:00.000Z",
      "expiresAt": "2026-09-01T00:00:00.000Z",
      "revokedAt": ""
    }
  ]
}
```

约束如下：

- 每个密钥环必须且只能有一个 `active` 密钥，且 `activeKeyId` 必须指向它。
- 新签名只使用当前 `active` 密钥；`grace` 密钥只验证轮换前的记录。
- 未知、尚未生效、已经过期或 `revoked` 的密钥一律拒绝。
- `keyId` 被纳入请求、回执、运行时状态和审计签名载荷；签名后修改 `keyId` 无法通过验签。
- 请求、运行时状态和审计记录分别持久化 `requestSignatureKeyId`、`runtimeStateKeyId` 和 `auditKeyId`，因此一次合法轮换前后的审计链仍可逐项验证。
- `secret` 只能由 T00 的生产密钥提供器在调用控制器时注入，不得进入 JSON 数据文件、日志、接口响应或发布报告。

## 回调时间窗与重放边界

外部回执签名绑定 `signingKeyId`、`issuedAt`、`expiresAt` 和 `nonce`。默认回调有效期为 300 秒，允许最多 30 秒时钟偏移；服务端可在 30–3600 秒范围内收紧或放宽有效期，在 0–300 秒范围内配置时钟偏移。

以下情况在任何状态写入之前拒绝：

- `issuedAt` 超过服务端当前时间与允许偏移；
- `expiresAt` 已过，或签发年龄超过服务端回调窗口；
- `nonce`、时间、状态、证据、任务绑定或 `keyId` 在签名后被修改；
- 同一 `signingKeyId + nonce` 使用不同幂等键再次提交。

服务端仅在审计中保存回执重放键哈希 `receiptReplayKeyHash`。相同幂等键和相同结果仍按原有契约幂等返回；换用不同幂等键重放同一可信回执会显式报错。

## T00 集成边界

T00 在公共路由和 worker 接线中需要：

1. 从生产密钥服务按领域加载 `requestKeyring` 与 `receiptKeyring`，然后传给 T08 控制器；不得把密钥环并入共享数据状态。
2. 入队时必须提供服务端 `at`，使请求签名绑定 `issuedAt` 与 `expiresAt`。
3. worker 领取、尝试、死信恢复和运行巡检必须提供完整请求密钥环，以便验证轮换前的 `grace` 记录。
4. 公网回调必须使用服务端接收时间作为 `at`，不得信任客户端自报的校验时间。
5. 轮换顺序必须是：发布新密钥为 `active`、旧密钥改为 `grace`、确认跨密钥审计链和回调冒烟、宽限期结束后再过期或吊销旧密钥。
6. 紧急吊销后，所有引用被吊销密钥的请求、状态、租约、审计和回执都应进入安全处置，不得自动重签或自动恢复。

T00 仍负责 `server.js`、`package.json`、`portal.css`、`README.md`、公共发布总表和共享持久化写入器。本线程不修改这些公共文件。

## 验收清单

- 托管密钥环只有一个有效 `active` 密钥，摘要不包含密钥正文。
- 轮换后历史请求、运行时状态和审计项可通过 `grace` 密钥验证，新写入全部使用新 `active` 密钥。
- 未知、过期、吊销及签名后篡改的 `keyId` 全部失败关闭。
- 审计链可跨两个合法密钥连续验证，删除、修改、重排或无签名追加仍被拒绝。
- 过期回调、未来回调、篡改时间/nonce 和不同幂等键的同 nonce 重放全部在写入前拒绝。
- 兼容静态密钥与全部功能验收通过后，`productionReady` 仍保持 `false`，直到 T00 接线、生产密钥服务、端点联调和可信现场证据均完成。
