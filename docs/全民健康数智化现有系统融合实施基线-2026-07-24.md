# 全民健康数智化现有系统融合实施基线

## 首期实施范围

首期不新建另一套业务系统，直接复用现有全民健康信息平台、医院连接器、区域数据共享、影像云、居民健康档案和县域互认能力。试点选择一家综合医院及其县域医共体，先打通以下四条业务链：

1. LIS审核检验报告后，向平台发布结构化报告。
2. PACS/RIS完成检查后，向平台发布报告和影像索引。
3. 医生在现有EMR工作站按诊疗关系查询居民跨机构历史结果。
4. 医生引用结果或登记复查原因后，将互认决定回写HIS/EMR。

患者身份登记与主索引匹配是上述链路的前置能力。居民电子健康档案、公卫、医保和医药数据在首个闭环稳定后分批接入。

## 新旧系统责任边界

| 对象 | 继续负责 | 本次新增 |
|---|---|---|
| HIS/EMR | 挂号、诊疗、医嘱、病历和业务记账 | 单点登录、共享结果查询、互认决定回写 |
| LIS | 检验申请、标本、审核和报告版本 | 结构化报告发布、修订和撤销事件 |
| PACS/RIS | 影像存储、检查流程和诊断报告 | DICOMweb索引、授权调阅和报告回调 |
| 全民健康信息平台 | 区域共享、主索引和审计 | 接口编排、互认规则、共享包和失败补偿 |
| 电子健康档案 | 居民健康信息展示 | 检验检查索引和本人授权查询 |

现有业务系统始终是业务事实来源。平台不得直接写入现有系统数据库，不保存未纳入建设范围的患者明细，不自动替代医生作出诊疗决定。

## 接口实施台账

| 接口编号 | 来源→目标 | 触发时点 | 现有能力复用 | 首期验收 |
|---|---|---|---|---|
| MPI_PATIENT_UPSERT | HIS→平台 | 建档或身份变更 | 主索引、签名连接器 | 匹配、合并、越权拒绝 |
| LIS_LAB_REPORT_PUBLISH | LIS→平台 | 审核、修订、撤销 | 医院连接器、诊断报告、个人档案索引 | 正常、修订、撤销、幂等 |
| PACS_IMAGING_MANIFEST_PUBLISH | PACS→平台 | 报告审核或影像入库 | 影像云、DICOM索引、授权分享 | 入云、调阅、回写、越权拒绝 |
| SHARED_RESULT_QUERY | EMR→平台 | 打开病历或开申请单 | 区域共享包、居民范围校验 | 跨机构查询、性能、审计 |
| MUTUAL_RECOGNITION_DECISION_CALLBACK | 平台→HIS | 引用结果或登记复查原因 | 互认规则、质控复核、签名回执 | 引用、不互认、失败重放 |

完整字段、幂等键、安全要求和验收证据位于 `config/existing-system-integration-baseline.json`，不得在该文件中填写真实密钥。

## 已落地的首批运行能力

统一入口 `POST /api/integration/events` 已将以下两个运行合同接入现有数据闭环：

- `lis-report-v1`：签名验收后生成或更新`diagnosticReports`、`countyMutualRecognitionRecords`和`personalRecords`。
- `pacs-report-v1`：除上述记录外，保留模态、检查部位、Study Instance UID、检查号和受控浏览地址。

两类接口当前共同支持：

1. HMAC签名校验和接口必填字段校验。
2. 幂等键重放；同一幂等键携带不同载荷时返回冲突。
3. `reportVersion`严格递增，拒绝旧版本和同版本内容冲突。
4. `final`首次发布、`corrected/amended/revised`修订和`revoked/cancelled/withdrawn`撤销。
5. 修订后自动将既有互认结论转为待复核，避免继续使用旧报告结论。
6. 撤销后同步撤回互认记录、隐藏居民档案摘要并停止未完成的危急值处置。
7. 校验医院机构编码范围；越权来源进入死信并保留审计事件。

接口成功回执包含平台事件编号、报告编号、互认记录编号、档案记录编号、报告版本和落地状态。当前HMAC为通用接入鉴权，不能替代医学电子文档签名。

## 数据标准首版

首版优先统一以下标识：

- 机构编码、科室编码和医务人员标识；
- 居民主索引与院内患者标识映射；
- 就诊、申请、报告和影像检查唯一标识；
- 检验项目代码、结果单位、参考区间和异常标识；
- 检查项目、部位、设备、模态和Study Instance UID；
- 报告状态、报告版本、互认决定和不互认原因；
- 请求编号、幂等键、回执编号和审计事件编号。

接口字段采用“平台标准字段＋院内原字段＋映射版本”管理。未完成字典映射的项目不得自动互认。

## 现场启动清单

实施组到场前应准备：

1. 试点医院及HIS、EMR、LIS、PACS/RIS厂商联系人。
2. 系统版本、部署拓扑、接口文档和测试环境。
3. 机构、科室、人员、检验项目和检查项目字典。
4. 首批互认项目、有效期、质控条件和不互认原因。
5. 脱敏测试居民、检验报告和影像检查样例。
6. 网络白名单、证书和密钥交付流程。
7. 联调时间窗、故障联系人和回退方案。

## 四周执行安排

| 周期 | 工作 | 退出条件 |
|---|---|---|
| 第1周 | 现状访谈、系统登记、字典收集、接口字段映射 | 四个院内系统责任人签字确认 |
| 第2周 | 前置适配器配置、签名联调、主索引及报告发布 | 测试环境产生有效接口回执 |
| 第3周 | 工作站查询、影像调阅、互认回写和异常重放 | 五个首期验收场景通过 |
| 第4周 | 性能、安全、灾备、审计抽查和灰度评审 | 四方联调验收单完成 |

## 首个闭环验收场景

1. 同一居民在来源医院产生检验报告，目标医院工作站能够查询并引用。
2. 影像检查生成平台索引，授权医生能够调阅报告和影像。
3. LIS修订或撤销报告后，平台同步更新并保留完整版本链。
4. 不满足互认条件时，医生登记标准原因并成功回写原系统。
5. 无当前诊疗关系或无授权的访问被拒绝并生成安全审计记录。

## 生产边界

当前代码和基线可以用于开发、演示及测试环境联调，但不能据此直接开放生产服务。以下事项全部完成并签字前，生产状态必须保持阻断：

- 真实接口地址、证书、密钥及网络白名单配置；
- 各厂商字段映射、状态语义和失败补偿机制确认；
- 互认目录、质控规则和例外原因业务确认；
- 性能、安全、灾备、回退及日志留存演练；
- 医院、平台、业务和安全四方联调验收。

运行 `npm run integration:kickoff-readiness` 可生成工程准备度报告。报告通过仅代表代码与实施基线完整，不代表生产就绪。
