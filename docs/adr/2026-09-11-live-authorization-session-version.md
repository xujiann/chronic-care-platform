# ADR：实时授权版本与旧会话失败关闭

- 状态：Accepted
- 日期：2026-09-11
- Owner：T00 决策与组合接线；T01 身份命令；T02 通用写入边界
- 人工决策：用户对角色、机构、账号类型、永久或临时权限变更失效策略明确回复“确认”；证据来自任务 01a07a80-db1d-7572-a534-f363708bc55b 的批准原文回报。
- 生效范围：下述授权策略；各实施段仍须独立编号、精确写范围、前置验收及 T00 准入。
- 复审日期：2027-03-11
- 替代：无；不替代既有生产身份、审计与数据 owner 合同。
- 对应代码与测试：src/http/routes/state-data.js、test/state-data-identity-boundary-api.test.js；后续身份实现路径以独立批准 PLAN 登记，代码存在不代表完成。

## Problem

当前会话只比较部分身份字段，临时授权尚未成为系统级授权证据。通用全状态写入保护仅覆盖 authUsers/authOrganizations，未保护审批请求、临时授权、回执与版本。直接接入临时权限会使通用写入口形成审批旁路。全局 grant 裁剪还可能删除其他账号的权威记录。

## Options

1. 保持现状，只补局部测试。
2. 在每次请求静默替换权限并立即增权。
3. 先封堵通用写旁路，再引入授权版本与独立权限快照，变更后失败关闭并重新认证。

## Advantages

方案 3 保留既有身份事实源、审计和 session store；旧会话不被静默增权，领域与中央接线可以分阶段验证。方案 1 成本低但不解决缺口；方案 2 使用方便但会突破人工确认的重新认证边界。

## Disadvantages

方案 3 增加重新登录及异常拒绝，需覆盖所有身份命令、目录入口、容量与旧账号兼容。请求期校验不是主动推送；无法凭仓库测试证明生产时钟、跨节点传播或存储回滚安全。

## Migration cost

中到高，分段实施。第一段只把四项既有身份管理字段加入现有通用写入保护，不新增 API、schema、权限或数据 owner。后续授权字段初始化、临时权限、目录审计和 session 接线必须另行完成精确 PLAN；如需 schema/session-store 变更须重新核定，不预先授权。

## Risk

- 用户确认：角色、机构、账号类型、永久或临时权限变化使旧会话下一请求失效；增权须重新登录，生产须满足既有可信强认证；停用、恢复、目录安全变更单调递增版本；账号变更与成功审计同权威事务。
- 授权版本须为非负安全整数，异常或溢出失败关闭；旧账号/旧会话的版本零兼容须由测试验证，首次安全变更使旧会话失效。
- 基础权限变化摘要与有效临时权限摘要分开，不能将合并后的会话权限误当永久权限，也不改变各消费者原有授权语义。
- 临时授权阶段指纹必须区分每条授权的 scheduled/active/expired，覆盖跨越整个窗口及同权限重叠；它不天然抗时钟回拨。已检测异常须通过现有撤销端口永久拒绝该会话，撤销失败须失败关闭且不声称撤销完成。未观察的整体时钟回拨、权威状态回滚仍需生产可信时钟与存储证据。
- 上限 5000 不可静默裁剪：满额新增拒绝，历史超限加载失败关闭；不在本批清理/归档。所有未来删除或状态变更须原子更新受影响账号版本。
- SQLite 账号与审计需实证同事务；JSON 演示同步写不等于崩溃原子。外部 session 撤销与主状态写之间仅允许明确的保守失效副作用，不称跨存储事务。
- 非生产 reset 不作为黄金场景或生产证明；跨 reset 会话保证必须另行核定接线和测试，不能默认为已解决。

## Recommendation

采用方案 3。实施前置 SEC-014：T02 对 accountLifecycleRequests、accountTemporaryGrants、accountLifecycleCommandReceipts、accountLifecycleVersion 实施既有身份 owner 写入拒绝。full-state 省略或深相等保留服务器值，显式变化用既有 409；collection 写用既有 403。不改读取授权、身份命令、容量或 session。

SEC-012 身份版本/临时授权、中央组合接线、SEC-013 居民身份旅程继续排队，不因本 ADR Accepted 自动获得写权限。真实 PostgreSQL 跨实例验证与生产准入独立，GS-01/04/06 保持未建设。

## Validation

第一段必须先 RED 后 GREEN，真实应用 HTTP 或现有真实路由 harness 验证四字段的替换、注入、删除/置空、数组重排拒绝，标量按实际类型验证；省略与深相等保留权威值；collection 写拒绝且零持久化。保持原角色、authUsers 脱敏兼容、其他 owner 与非生产 reset 边界。独立 review、legacy、精确 head CI 后串行集成。

## Rollback

每段独立回退代码，不删除审批、授权、回执或审计。前置保护如回退，后续临时授权接线不得放行；运行时安全保证依赖该前置，不允许仅回退保护后继续增权。
