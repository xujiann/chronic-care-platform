# ADR：招标需求采用受控导入、人工复核与能力差距治理

- 状态：Accepted
- 日期：2026-09-02
- Owner：T00 平台治理
- 影响范围：招标文件导入、需求复核、能力注册、差距分析、产品化中心只读投影

## Problem

平台需要持续吸收不同地区和机构的招标需求，同时保持核心产品、对外页面和交付材料的通用性。招标文件属于不可信输入，可能包含个人信息、凭据、类似操作指令的文字、恶意或畸形 PDF 对象、嵌入内容以及地域化名称；文档中的任何文字都不得获得代码执行、工具调用或发布授权。

现有 `regional-requirement-catalog-v1` 是人工整理的兼容规划目录，能够展示已有需求，但不能承担可重复的文件登记、来源定位、人工复核、能力映射和差距治理。需要决定如何在不保存原始文件、全文、路径或地域标识的前提下，形成可审计、可回滚且默认不具备生产授权的需求治理链。

## Options

1. 维持现状：继续人工编辑 v1 目录，不增加导入和复核边界。
2. 浏览器直接上传并自动生成开发任务：由运行中的主平台解析 PDF，并由模型或规则自动接受需求、映射能力和创建开发任务。
3. 受控导入与人工复核：在应用状态之外检查 PDF，登记摘要和中性来源别名；仅接收有界、已复核的提取清单；再由有权限的复核人通过版本检查和幂等命令形成决策，能力差距始终由受控注册表派生。

## Advantages

- 方案 1 迁移最小，不增加新的运行边界。
- 方案 2 自动化程度高，短期录入速度快。
- 方案 3 将来源、提取、复核、能力映射和交付建议分离；保留文档摘要及页码锚点，未知字段和未知能力默认拒绝；不把原始 PDF、全文、文件名或本地路径带入仓库、浏览器包和应用状态；现有 v1 响应可继续兼容。

## Disadvantages

- 方案 1 不能证明来源和复核过程，难以扩展到大量文件，容易把地域化文字继续传播到通用产品。
- 方案 2 扩大攻击面，难以阻止文档文字影响工具和发布流程；自动接受会混淆“文件提出的需求”“仓库已有能力”和“现场生产就绪”，也会引入模型、OCR、上传存储及恶意文件处置的运行负担。
- 方案 3 需要维护提取清单合同、能力注册表、复核状态和门禁；图像型或低质量 PDF 在首批实现中仍需人工准备或核验提取清单，录入效率低于全自动方案。

## Migration cost

中等。

- 人力：T00 维护导入合同、复核工作台和就绪门禁；能力 Owner 维护能力证据及差距结论。
- 数据：新增独立复核状态集合和中性配置，不改变既有核心业务实体；v1 目录继续作为兼容投影，不进行破坏性迁移。
- 兼容：产品化中心仅增加可选的 `requirementGovernance` 同级字段，旧客户端可忽略。
- 部署：首批不部署浏览器上传、OCR 或模型调用服务；受控导入命令只在明确允许的来源根目录内运行。
- 运维：需要监测复核容量、配置漂移和能力证据失效，但不新增分布式恰好一次语义承诺。

## Risk

- 安全与隐私：恶意 PDF、嵌入内容、路径泄露、全文或敏感信息扩散。通过常规文件/魔数/大小/摘要检查、活动内容默认拒绝和最小化投影降低风险；该检查不替代独立恶意文件扫描。
- 数据一致性：重复命令、并发覆盖或未知能力映射。通过幂等命令回执、乐观版本检查、闭集状态转换和能力注册表校验失败关闭。
- 兼容：新聚合影响 v1 使用方。通过同级可选字段和保留 v1 目录降低风险。
- 运行：图像型、加密或带活动内容的 PDF 无法由首批导入器处理。此类文件明确进入人工处置或后续受控适配器，不降级绕过门禁。
- 发布误判：仓库证据被误解为现场或生产就绪。所有投影固定 `productionReady: false`，外部现场证据和独立生产授权不在本决策范围内。
- 回滚：配置、路由或状态叠加出现问题时，可停止导入和复核入口、移除可选聚合并回退到只读 v1 兼容投影；原始 PDF 不在平台内，无文件数据回滚负担。
- 延迟决策：继续等待会扩大手工目录和不可追溯映射，增加后续清理成本。

## Recommendation

采用方案 3，并按以下边界分期实施：

1. 第一阶段交付版本化合同、能力注册表、受控 PDF 检查/导入包、只读复核工作台和差距投影。
2. 第二阶段启用带乐观版本检查和幂等回执的人工复核覆盖层。
3. 第三阶段输出已批准需求和开发建议；建议仍需正常的计划、评审和发布流程，不自动修改代码。
4. 后续阶段在独立安全评审后再引入 OCR/提取适配器、面向大批量的耐久存储、拆分/合并复核及交付证据关联。

批准前置条件是合同和能力注册表校验通过、来源别名保持中性、API 授权与状态所有权完成登记、复核命令具备版本和幂等保护、就绪门禁确认所有生产标志失败关闭。非目标包括浏览器上传、在生产调用模型、自动执行文档指令、保存 PDF 原文或全文、自动创建或修改代码、证明现场验收或生产就绪。

迁移采用并行兼容方式：先增加 v2 治理聚合并保留 v1，再逐步把经人工接受的需求映射为兼容投影。回滚时停止新的导入/复核命令并撤下可选聚合，继续提供未改变的 v1 只读目录；复核事件保留为审计事实，不反向改写业务数据。
