# 主存储独立持久 checkpoint 首切片

- 状态：Accepted
- 决策：ADR-OPS-046；2026-09-23 用户批准限定切片。
- 任务：GOV-020 / OPS-046；基线 `origin/main@717550d9`。

## Problem

源端已有不可变提交凭证与身份，目标端已有绑定的已应用批次账本，但缺少独立持久进度。目标提交后进程崩溃时，不能把内存游标当作恢复依据。

## Options

1. 仅重用目标批次账本：无新持久状态，但不能单独记录消费者进度。
2. 独立 SQLite checkpoint 账本（本切片采用）：合成环境可验证崩溃/重放与单写事务；不承担生产信任锚。
3. 目标库新增 checkpoint 表或外部强一致服务：更适合多实例生产，但扩大迁移、凭据和部署边界，另行准入。

## Decision and scope

增加独立 SQLite v1 checkpoint 文件与版本标记，仅由显式合成调用方使用。显式初始化要求已绑定目标的批次账本为空，写入不可变源/目标身份元数据；进度行只存技术身份、outbox 序号、批次标识和摘要，不含业务 payload。每次推进必须持有 `loadBoundSqliteOutboxBatches` 的原始品牌 envelope，并从目标只读事务核对完整已应用凭证。文件内 `BEGIN IMMEDIATE` 串行写、前游标 CAS、不可变进度行及幂等重放；目标已应用而 checkpoint 未写时可重新核对后推进。读取（包括空进度）重新核验源身份、目标身份及源链游标；丢失、漂移或回退必须失败关闭，不自动补历史。

不新增自动 relay/worker、HTTP、业务请求、生产配置或真实数据迁移。checkpoint 仅为本地技术进度，不能替代目标账本、独立信任锚或现场验收。单进程/单机 SQLite 锁不能证明多实例能力。

## Advantages / disadvantages / migration cost / risk

优势：独立持久进度、崩溃窗口可复现、无需改变现有生产主 schema。代价：新增专用文件 schema v1 与验证逻辑；调用方必须管理独立文件生命周期。风险：本地管理员可复制/回滚整套文件，完整物理克隆不可识别；目标与 checkpoint 不同事务，故必须以目标账本为权威并允许安全重放。不得将此本地组件包装成生产就绪。

## Verification and recovery

覆盖空账本、连续推进、精确重放、错源/错目标、缺目标批次、凭证漂移、跳号、并发 CAS、文件重启、目标提交后 checkpoint 失败再恢复、schema 漂移及失败零进度。停止调用并保留源/目标及 checkpoint 事实；不自动删除或重绑。仅合成测试自建临时文件可清理。独立审查、冻结后完整串行门禁，生产继续 NO-GO。
