# ADR：现有 AI/CDSS 中心与规则治理写入保护整合

- 状态：Accepted
- 日期：2026-09-06
- 授权：用户确认以最新 main 为基础，保留现有中心，逐项补入 PR #248 缺失保护并重新验收。
- Owner：T00 跨域装配；T01 治理策略；T06 临床事实、范围与回执。

## Problem

main 的 PR #249、#250 已提供临床安全治理和平台跨域元数据中心；PR #248 含规则状态机及临床回执保护，却创建重叠页面。直接合并会造成清单冲突、重复入口和不一致的权限/来源漂移判定。

## Options

1. 覆盖主线两个中心，整体采用 #248。
2. 同时保留三套页面、投影与治理状态判定。
3. 保留主线页面和查询 schema，选择迁入 #248 的缺失领域端口、写入协议和测试，在现有平台页加入规则命令区。

## Advantages

选择方案 3。既有四场景来源白名单、Owner 待移交禁读、临床最小投影和导航保持。规则登记/送审/独立批准或退回/暂停/回滚使用 `ai-governance.v1`；临床范围、医生回执与版本化重放使用 `clinical-decision-support.v1`。临床中心消费同一可信机构/医生范围端口和同一治理策略，不按旧审批文本绕过暂停或来源漂移。

## Disadvantages

运行时仍为共享模块化单体，进程锁和 JSON/SQLite 不提供多实例 exactly-once。平台中心仍承担只读跨域汇总，规则审批只针对已存在的临床规则，不是模型注册、推理或生产授权。

## Migration cost

在现有规则中按命令写入可选 `governance` 元数据、历史和重放回执；现有提醒按命令增加版本，回执增加内部命令快照。不新增集合、DDL、依赖或启动回填，不直接编辑数据库。旧无键回执保留兼容模式但不宣称严格幂等。新增审批强制 expectedVersion、幂等键、来源摘要、独立操作者和增强认证。回滚保留元数据，禁止旧版本重新放开已治理规则。

## Risk

医生编号可能跨机构重复，访问必须同时满足可信目录代码与医生范围；缺目录、歧义名称、未绑定医生均拒绝。暂停/漂移同时抑制提醒建议、规则默认动作和临床中心推荐字段。保留或拒绝必须记录真实理由。通用 state 禁止改写四个临床集合；旧 config 生产拒绝，非生产也禁止修改已治理规则。请求体在锁外解析，业务和审计校验成功后一次持久化；错误不污染原状态。幂等快照重放前重验当前范围与策略，内部回执不进入公开投影。历史达到容量上限时拒绝新命令，不驱逐幂等记录。

## Recommendation

以 `main@7de328e0` 建立独立 T00 工作树，保留 #249/#250 所有原有测试，增加跨中心一致性和来源漂移负向测试。完成全部工程门禁、关键边界覆盖和完整浏览器 E2E 后建立替代 PR；未合并前保留 #248 作为来源，不自动关闭或覆盖它。生产固定 NO-GO，真实医学验证、外部系统接入、签名、数据库演练与现场批准独立待办。
