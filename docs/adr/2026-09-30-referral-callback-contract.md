# ADR-GS03-CALLBACK-001：跨机构转诊回调的资源、授权与回执合同

- 状态：Proposed
- 说明：设计评审；不授权实施
- 日期：2026-09-30
- 决策 Owner：T00 跨域集成；T05 会诊资源与业务状态；T08 外部回调与供应方信任。居民授权事实 Owner、存储 Owner 及外部调用方须在接受前确认。
- 影响范围：`POST /api/referral-teleconsultations/:id/{feedback,schedule,report}-callback`、三份 `referral-*-callback-v1` 合同、授权事实、回调回执与既有会诊/档案/通知持久化
- 依据：GOV-026 设计任务；`.codex-platform-evidence/pr325-closure-20260930/callback-design-review.json` 的五项独审阻断；冻结基线 `4e75611c`。本 ADR 不把审查建议写成已接受决策。

## Problem

GS-03 当前只有 T05 本地转诊命令的隔离 HTTP 回归。外部反馈、排期、报告三类回调虽有既有接口和旧套件正向样本，尚无独立跨机构、撤权、签名资源绑定、异载荷重放及耐久回执合同。仓库测试不证明医院接入、现场签署或生产可用。

当前行为须与下文建议区分：

| 边界 | 冻结基线现状 | 证据 |
|---|---|---|
| 身份与范围 | HTTP 允许 `institution`、`county`、`commission`。`canAccessReferralTeleconsultation` 先检查居民范围；区县和主管部门分支与机构分支不同，机构可因来源/接诊机构或匹配医生取得范围。回调没有专属的有效授权检查。不能把来源机构 403 当成现行合同。 | `src/http/routes/care-coordination.js:489-513`；`server.js:15627-15634` |
| 签名 | 使用同一集成网关 HMAC 对规范化请求体签名；URL 资源 ID、认证主体没有天然进入签名内容。没有本回调专属的时间戳、nonce 或供应方密钥轮换合同。 | `server.js:13631-13643`；`src/http/routes/care-coordination.js:497-501` |
| 字段与幂等 | 目录合同声明 `externalId` 为幂等键及若干必填字段；实际路由用 `idempotencyKey`，normalizer 对若干目录字段使用回退值，也不要求 body `teleconsultationId` 与 URL 一致。重复命中只比较 `contractId + idempotencyKey`，不比较资源或意图摘要；同键异载荷目前返回 200 重放，并非 409。 | `server.js:2593-2595,21758-21816`；`src/http/routes/care-coordination.js:516-529` |
| 副作用与回执 | 首次成功修改会诊并追加网关事件；报告另追加居民档案；三种回调均可能追加机构/居民通知、安全审计及数据访问日志，随后一次 `writeDatabase`。`integrationGatewayEvents` 最多保留 200 项，不能作为耐久去重或回执权威。 | `src/http/routes/care-coordination.js:532-614`；`server.js:21819-21904` |
| 已有证明 | 巨型 API 套件覆盖同一账号的三类正向签名、同载荷重放、报告归档/通知及报告缺签名 401；T05 的 GS-03 专项仅覆盖本地命令。 | `test/api.test.js:6608-6736`；`test/gs03-referral-collaboration-api.test.js` |

须先选择可复核的调用方身份、幂等作用域、授权事实和持久回执权威。若这些前提未定，添加测试或一个新的回调服务名称均不能建立安全合同。

## Options

1. **维持 v1 行为，仅刻画现状。** 保留现有角色、body HMAC、全局 `contractId + idempotencyKey` 与 200 项事件窗口；增加不晋升的现状测试和风险记录。
2. **分片升级现有协议（推荐讨论方向，尚未决定）。** A 片先明确可信调用方命名空间、资源与意图绑定、准确授权及重放语义；B 片另行定义供应方认证的 v2 envelope、密钥轮换、时钟与 nonce 策略。各片依赖须独立满足，不能将 A 片所需的耐久回执迁移推迟到 B 片。
3. **直接新增完整外部回调服务与独立账本。** 一次替换三条 API、信任边界和持久化实现。

### 五项待审批决策

以下各项为推荐和备选，均尚未被接受；缺少的输入是设计阻断，不由本 ADR 虚构。

| 决策 | 具体推荐 | 备选及代价 | 审批人与缺失输入 |
|---|---|---|---|
| 1. 可信调用方命名空间 | 从已认证且稳定的 principal/机构或管理主体标识建立受控命名空间；机构、区县、主管部门分别定义其可提交的回调类型与资源范围。先刻画现有角色分支，不静默取消来源机构权限。绝不从可编辑 `sourceSystem` 派生命名空间。 | 维持共享网关密钥与宽角色仅能继续表述为 v1 风险；直接限定接诊机构可能破坏现有来源机构、区县与主管部门调用方。更改角色需迁移、负向测试及调用方通知。 | T05 资源 Owner、T08 信任 Owner、T00 跨域审批；缺可信 principal 目录、三类真实调用方清单、主体与机构绑定及来源机构业务用例。 |
| 2. 幂等键作用域与回执可见性 | 推荐在同一可信 principal 命名空间及合同版本内使 key 唯一，记录目标资源、版本化确定性 `intentDigest` 与回执；读取旧回执前重新校验当前资源权限，目标不匹配或异意图失败关闭，公共响应仅投影当前资源允许的最小回执。摘要只取规范化的显式客户端意图及资源/合同版本，不含生成的当前时间或可变 item 回退值。 | 资源局部 key 允许同 key 跨会诊使用，但跨资源误投更难发现；全局无主体 key 保留相互抢键和信息泄露。任何改动均须定义 v1 键兼容和错误映射，不能把现有异载荷 200 直接称为 409 合同。 | T05/T08/T00；缺调用方 key 生成与重试约定、principal 稳定性、历史冲突样本及最小公共回执字段清单。还须批准缺失字段、嵌套别名、未知字段和授权 ID 的规范化/拒绝规则，避免同一意图因回退或别名漂移得到不同摘要。 |
| 3. 签名资源绑定 | 新版本签名输入须含合同版本、规范化 body 内的 `teleconsultationId`，并在处理前与 URL ID 精确一致；明确缺 ID、额外字段及旧 body 的受控兼容或拒绝政策。仅签 body 而不含资源 ID 不能阻止首次签名请求被移到另一 URL。 | 保留 v1 body-only HMAC 迁移低但风险继续；直接按原 URL 字符串签名受代理编码/规范化差异影响。双版本窗口需要明示版本、调用方清单、截止条件和回滚。 | T08 协议与信任 Owner、T05 目标语义、T00 装配；缺供应方字段版本、URL 规范化、部署顺序及旧 body 比例。 |
| 4. 精确授权及竞态 | 将许可绑定会诊的**确切** `residentAuthorizationId`、居民、用途及有效状态；首次提交与重放均重验。撤销与回调并发时，在同一受控提交边界内以版本/CAS 解决先后；续授权生成新授权 ID 后，旧 key 不得绕过当前授权，新意图需按批准的恢复流程提交。 | 只检查“居民存在任一有效授权”会误用其他授权；仅入口检查会发生检查后撤销竞态；一律拒绝历史回执可能改变客户端重试行为。需要 T04 授权事实、T05 状态和存储语义共同决定。 | T04 授权事实 Owner、T05、T00，T08 核对调用方；缺精确授权事实读取端口、撤销/续授权的序列化能力、旧 key 重试政策与居民同意目的定义。 |
| 5. 耐久回执权威与保留 | 先评估既有持久命令 inbox/UoW 或其他已批准存储机制能否承载回调 key、principal、资源、版本、意图摘要、结果及审计引用，并与业务副作用原子提交。明确回执保留期与过期后的失败/人工对账。若 A 片需要 schema/receipt 迁移，必须先有单独 Accepted ADR、版本迁移、恢复与回滚验证；不得以 B 片为延期理由。 | 继续用最多 200 条网关事件不能承诺长期去重；新建平行账本增加迁移、双写及一致性成本。旧无摘要事件只能经受控对账或失败关闭，不自动回填“已证明”摘要。 | 存储/data Owner、T05、T08、T00；缺持久权威候选、事务边界、历史记录规模、保留期限、恢复目标与数据治理批准。 |

## Advantages

- 方案 1 不改变既有客户端，可低成本生成真实的 v1 行为基线，但不能解除设计阻断。
- 方案 2 可沿用既有三条路径和业务事实源，按可验证的依赖顺序收紧资源、授权与回执合同；A/B 分片让调用方迁移和供应方信任建设分别审查。
- 方案 3 可统一新协议及存储模型，前提是调用方、数据 Owner、迁移与运行团队已明确并能承担切换。

## Disadvantages

- 方案 1 保留跨资源复用签名、同键异载荷 200 和事件截断后的重放风险，不能据测试晋升 GS-03。
- 方案 2 需要兼容窗口、多个 Owner 的同一事务/授权接口协商；若既有持久化不能安全承载 receipt，A 片也必须等待迁移决策。分片不意味着先宣称耐久、原子或生产可用。
- 方案 3 改动大，容易形成第二个会诊/转诊写轨和请求路径双写；在信任及授权事实未确定前只会转移风险。

## Migration cost

- 方案 1：低。仅现状测试、合同差异记录及治理，不改接口；残余风险高。
- 方案 2：中到高。A 片涉及版本化请求、可信 principal、资源/授权/幂等一致性与调用方兼容；若需要持久 receipt，则附加高成本版本迁移、历史无摘要对账、回滚及故障恢复。B 片涉及供应方凭据、密钥轮换、时间/nonce 与部署联调；其成本不能掩盖 A 片的存储前置条件。
- 方案 3：高到极高。新增服务/账本、旧数据迁移、双版本运行、监控及灾备均须独立架构批准；本轮没有这些输入。

## Risk

- 安全：共享 body HMAC 不证明 URL 目标或调用方；`sourceSystem` 可由请求填写，不能充当身份。回执若在当前权限检查前返回，可能泄露另一资源的结果。
- 授权：会诊创建时的授权事实不等于回调时有效授权。单次入口检查与持久提交之间的撤销竞态须经同一受控提交边界解决，不能靠合成测试时间顺序宣称解决。
- 数据一致性：事件列表 200 条截断、无摘要旧记录及失败提交都可能使重放失真。除非选定并验证耐久 UoW，不承诺持久 exactly-once 或业务/回执/通知原子性。
- 兼容：目录 `externalId` 与运行时 `idempotencyKey` 差异、缺 body 资源 ID、旧客户端及旧 key 均需明确版本政策。回滚只能撤销新协议入口或未生效迁移，保留已提交业务事实和历史审计，不通过删除回执制造可重放窗口。
- 外部证据：真实调用方、信任根、保留期限、供应方字段和现场签署尚未提供。生产六域继续 `NO-GO`。

实施前置按 A 合同/存储、B 供应方信任、生产现场三层分别审查，不能把 B 或生产材料误写成 A 的全部开发前置。五项尚未解除的阻断如下：

1. **A 合同：**T08/T05/T00 确认可信调用方命名空间、v1/v2 路由分流、旧请求兼容策略、调用方迁移清单与期限；缺少期限时不能假定可永久双轨。
2. **A 存储：**T05/T08 与存储 Owner、T00 确认回调业务事实和 receipt 的唯一数据 Owner、同一 UoW 原子边界及失败恢复；200 项网关事件不是该权威。
3. **A 迁移：**存储 Owner 与 T00 决定旧无 digest 回执的失败关闭/人工对账、版本迁移、回滚与保留期限；不得自动补写历史证明。A 片需要迁移时，先取得单独 Accepted ADR。
4. **B 信任：**T08 与外部调用方确认 provider 信任锚、凭据保管、密钥轮换及失效窗口；本地演示 HMAC 密钥不构成该材料。B 的供应方信任设计可与 A 评审并行，A 不能假称 B 已完成。
5. **生产现场：**T00 与现场责任方确认真实供应方联调、权限/密钥配置、监测、容量、灾备和签署的放行条件；仓库合同测试仅是代码证据，GS-03 维持“未建设”，生产六域维持 `NO-GO`。

## Recommendation

建议优先评审方案 2 的五项决策及其调用方/存储输入，按批准后的依赖顺序拆分实施任务。首先形成 v1 角色与副作用刻画；随后选择 v2 envelope、principal/key 语义、精确授权与持久权威。A 片如需耐久 receipt 迁移，先批准迁移 ADR 并验证历史兼容与恢复；B 片独立设计供应方信任，不替 A 片存储缺口兜底。只有 ADR 转为 Accepted 且每个切片另行准入后，才可修改运行时。

拟议测试矩阵：三合同 × 来源/接诊/区县/主管部门/外机构的当前权限刻画；无签名、改 body、URL/body ID 不同及旧 body；精确授权有效、撤销、续授权、撤销与提交并发；同 key 同意图/异意图/异目标/跨 principal；重放前权限改变；成功与持久失败后的会诊、档案、事件、通知、审计、回执一致性；超过旧 200 事件窗口与旧无摘要记录。测试须以隔离合成真实 HTTP 和受控故障注入证明实际实现，不能把拟议 403/409 预写为当前通过事实。现有 `test/api.test.js` 正向路径须保持。

若后续获准，候选写范围须逐片锁定：T05 独占 `src/http/routes/care-coordination.js` 的回调业务/授权适配及其新增专项测试；T08 独占外部 envelope、供应方认证/验签的经批准模块与专项测试；T00 独占 `server.js` 既有 normalizer/合同装配、中央持久化/迁移接线及 `config/lifecycle-governance.json`、六图、API/数据合同登记。具体新模块、migration 文件和接口由 Accepted 决策及 Owner 计划定名；未定名前不得创建平行服务或数据集合。跨域文件由 T00 协调单写者，不共同编辑同一文件。

本 ADR 作者写范围仅为这份 Proposed ADR 及索引；同轮 GOV-026 总账与六图由 T00 其他单写者登记。本设计不修改 runtime、DDL、凭据、部署或生产状态，未执行回调业务或运行时验证；文档治理校验由集成责任人按本轮门禁执行。不宣称 GS-03 全场景完成。后续实施若失败，应停在失败证据和受控恢复，保留旧业务/审计事实；生产验收仍需要真实环境、供应方联调与签署。
