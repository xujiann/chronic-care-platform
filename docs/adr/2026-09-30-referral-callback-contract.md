# ADR-GS03-CALLBACK-001：跨机构转诊回调的资源、授权与回执合同

- 状态：Proposed
- 说明：设计评审；不授权实施
- 日期：2026-09-30
- 本轮细化：2026-10-01；只更新设计与已证 v1 行为，不改变状态
- 决策 Owner：T00 跨域集成；T05 会诊资源与业务状态；T08 外部回调与供应方信任。居民授权事实 Owner、存储 Owner 及外部调用方须在接受前确认。
- 影响范围：`POST /api/referral-teleconsultations/:id/{feedback,schedule,report}-callback`、三份 `referral-*-callback-v1` 合同、授权事实、回调回执与既有会诊/档案/通知持久化
- 依据：GOV-026 设计任务；`.codex-platform-evidence/pr325-closure-20260930/callback-design-review.json` 的五项独审阻断；TEST-024/025 的冻结隔离真实 HTTP 现状证据。PR327/328 已保护合并；主线 CI 与门禁的最终状态以 T00 总账及证据登记为准，不在本 ADR 声称后续结果。合并与测试均不等于本 ADR 已接受。

## Problem

GS-03 现已用 TEST-024/025 对反馈、排期、报告三类 v1 回调补齐隔离合成真实 HTTP 行为刻画，包括角色、签名、持久副作用、跨资源重定位、跨主体同键、真实撤权后的首次请求与旧键重放。这些测试揭示风险，不是资源绑定、授权或耐久回执的安全验收。尚无获批的新版本协议、真实供应方联调、现场签署或生产放行。

当前行为须与下文建议区分：

| 边界 | 当前 v1 行为与已证边界 | 证据 |
|---|---|---|
| 身份与范围 | HTTP 允许 `institution`、`county`、`commission`。`canAccessReferralTeleconsultation` 先检查居民范围；区县和主管部门分支与机构分支不同，机构可因来源/接诊机构或匹配医生取得范围。回调没有专属的有效授权检查。不能把来源机构 403 当成现行合同。 | `src/http/routes/care-coordination.js:489-513`；`server.js:15627-15634` |

须先选择可复核的调用方身份、幂等作用域、授权事实和持久回执权威。若这些前提未定，添加测试或一个新的回调服务名称均不能建立安全合同。

## Options

1. **维持 v1 行为，仅刻画现状。** 保留现有角色、body HMAC、全局 `contractId + idempotencyKey` 与 200 项事件窗口；TEST-024/025 已给出不晋升的现状基线，风险仍在。
2. **分片升级现有协议（推荐讨论方向，尚未决定）。** A 片定义显式版本的新请求 lane、稳定认证 principal 命名空间、签名目标与意图绑定、确切授权、受控回执及其必要持久迁移；其安全断言只适用于新 lane。B 片单独设计真实外部 provider 信任锚、凭据分发/轮换与时间/nonce 防重放。两片分别审批；A 所需的耐久回执迁移不能推迟到 B。
3. **直接新增完整外部回调服务与独立账本。** 一次替换三条 API、信任边界和持久化实现。

### A 新 lane 的拟议请求与判定顺序（非当前 v1 合同）

1. **显式版本和字段。** 推荐在现有三条路径上用经审批的显式版本标识分流。新 lane 顶层必须是对象，显式携带合同 ID/版本、`teleconsultationId`、`residentId`、`residentAuthorizationId`、`idempotencyKey`、`externalId`；反馈、排期、报告分别要求明确的反馈正文及发生时间、排期窗口与目标机构/医生标识、报告摘要及返回时间。`externalId` 是会进入事件/报告档案的外部业务标识，不替代幂等键。可选字段须列白名单、类型、长度、持久副作用及重试可变性；`sourceSystem` 仅作诊断/审计来源标签，不是身份。最终字段清单、时间格式和排期标识仍待 T05/T08 与真实调用方确认。
   **降级边界：**推荐缺失/未知版本均失败关闭；新 lane 验签、字段或授权失败不得自动转 v1。未迁移的旧无版本请求仅在已批准 principal allowlist 与明确截止期内走隔离 legacy lane；已迁移 principal 不得删除版本标识重新进入 v1。allowlist、迁移状态权威及期限目前缺真实调用方输入，不能预填。
2. **一次规范化。** 推荐缺失/空值/错误类型、未知字段、嵌套 `payload` 别名、顶层与别名并存或相互冲突一律拒绝，除非另有已批准的唯一映射表。新 lane 不从当前时间、会诊原值、默认 `sourceSystem` 或旧 normalizer 的可变回退补足客户端意图；不把服务端生成的时间戳写入摘要。URL ID 解码与规范化规则固定后，body `teleconsultationId` 必须与 URL 目标精确相等，body 授权 ID 必须与案例当前绑定 ID 精确相等。建议上述请求错误为 400；未知目标按批准的隐藏策略给 404，不能经 receipt 泄露既有目标。
3. **先认证/验签与当前许可，再回执。** 推荐先确定已认证 principal、角色、居民和会诊 scope，验证版本化签名覆盖方法、规范化路径、合同版本、由认证上下文重建的 principal 命名空间与规范 body；再在提交边界读取案例绑定的确切授权记录，核居民、用途、目标机构、有效/未撤销、有效期及非 hold 业务状态。现有来源/接诊机构、区县、主管部门路径应分别迁移评审，不擅自将来源机构判 403。缺认证/签名建议 401，已认证但 scope 或确切授权无效（包括撤权后旧键）建议 403；拒绝可以记录安全审计，但不得产生回调业务、档案、两类通知或成功 receipt。共享 v1 密钥即使按上述规则验过，也不证明真实 provider 身份，后者属于 B。
4. **确定性意图与重放。** 推荐 `intentDigest = SHA-256(已批准的规范化算法版本、合同 ID/版本、目标 ID、居民 ID、确切授权 ID、externalId、全部显式业务字段及显式客户端时间、允许的显式持久元数据)`；算法版本入 receipt。`externalId` 会影响事件和报告档案，必须参与摘要；若允许 `sourceSystem`，因其影响审计/通知说明，也必须作为显式值参与摘要，不得在重试时悄悄变化；若允许 `performance` 或其他会改变案例/消息/审计的元数据，也须逐项列入白名单与摘要，否则拒绝。只有经 Owner 证明完全不影响持久业务、回执、通知、审计的纯传输追踪字段，才可另批为可变且排除摘要；本 ADR 尚无该清单。摘要不依赖生成的当前时间、可变 item fallback 或字段输入顺序。推荐以稳定认证 principal 命名空间 + 合同版本/ID + key 查 receipt；同 namespace、同目标、同授权、同摘要的重试只返回经当前权限允许的最小结果，无重复业务副作用；异目标/异摘要建议 409，响应不含旧目标、旧 `receivedBy` 或原 payload。最小公共投影候选为本次资源 ID、回执 ID、合同版本、处理状态及可公开提交时间，具体字段须经权限/隐私 Owner 批准；v1 的完整网关 event 不是该投影。跨 principal 同 key 的业务去重责任尚待真实调用方归属确认。
5. **撤权与并发。** 撤权、续授权和回调须在同一已选定的事实/存储权威中序列化：提交顺序先撤权，则新键首次与旧键重放都拒绝；先回调提交，则已产生的业务和 receipt 保留，但随后撤权后的旧键请求不再披露旧回执。续授权须产生新授权 ID，先经现有批准的恢复命令解除 hold，旧授权/旧键不能借新授权重放，新意图用新键。不得以到达顺序或单次入口检查代替事务/CAS。存储冲突建议返回无部分业务提交的明确可重试冲突，具体 409/5xx 映射与重试上限待存储 Owner 批准。
6. **失败、未知结果与受控对账。** 只有存储权威明确回滚且确认未提交，才能断言该次业务/receipt 零写；提交已成功但响应丢失，或提交结果未知时，不得宣称零副作用，也不得换新 key 盲重发。同一 key 只能在当前授权仍有效时依已批准的最小 receipt 查询/重试机制核实；撤权后公共接口不披露旧 receipt，历史事实仍保留，并需由授权的 T05/存储与隐私责任人经受控对账渠道处理。查询接口、责任人、留痕及未知结果恢复时限尚缺审批输入；回滚不得删除已提交 receipt 造出可重放窗口。

候选权威须由存储/data Owner 选定并验证唯一索引、授权/会诊版本 CAS、同事务 receipt/业务/档案/通知/审计、已回滚与结果未知的可区分恢复、长期保留与过期后对账。保留期限、容量、隐私删除规则、恢复目标、受控对账 Owner/渠道及历史规模当前没有已批准值；本 ADR 不填写生产数值。旧 v1 无 `intentDigest` 的事件不得自动回填为“已验证”，须先选失败关闭或人工对账策略及版本迁移。兼容期内 v1 只能按已批准未迁移 principal allowlist 和截止期作为显式隔离的 legacy lane；缺/未知版本及新 lane 失败不得降级，已迁移 principal 不得靠去掉版本回流。A 的资源/授权/回执安全断言只属于新 lane，旧 lane 风险不会因新 lane 存在而消失；实际名单、期限、关停条件待真实调用方签认。

## Advantages

- 方案 1 不改变既有客户端；TEST-024/025 已生成真实的 v1 行为基线，但不能解除设计阻断。
- 方案 2 可沿用既有三条路径和业务事实源，按可验证的依赖顺序收紧资源、授权与回执合同；A/B 分片让调用方迁移和供应方信任建设分别审查。
- 方案 3 可统一新协议及存储模型，前提是调用方、数据 Owner、迁移与运行团队已明确并能承担切换。

## Disadvantages

- 方案 1 保留跨资源复用签名、同键异载荷 200 和事件截断后的重放风险，不能据测试晋升 GS-03。
- 方案 2 需要兼容窗口、多个 Owner 的同一事务/授权接口协商；若既有持久化不能安全承载 receipt，A 片也必须等待迁移决策。分片不意味着先宣称耐久、原子或生产可用。
- 方案 3 改动大，容易形成第二个会诊/转诊写轨和请求路径双写；在信任及授权事实未确定前只会转移风险。

## Migration cost

- 方案 1：低。仅现状测试、合同差异记录及治理，不改接口；残余风险高。
- 方案 2：中到高。A 片涉及版本化请求、可信 principal、资源/授权/幂等一致性与调用方兼容；若需要持久 receipt，则附加高成本版本迁移、历史无摘要对账、回滚及故障恢复。B 片涉及供应方凭据、密钥轮换、时间/nonce 与部署联调；其成本不能掩盖 A 片的存储前置条件。
- 方案 3：高到极高。新增服务/账本、旧数据迁移、双版本运行、监控及灾备均须独立架构批准；本轮没有这些输入。

## Risk

- 安全：共享 body HMAC 不证明 URL 目标或调用方；`sourceSystem` 可由请求填写，不能充当身份。回执若在当前权限检查前返回，可能泄露另一资源的结果。
- 授权：会诊创建时的授权事实不等于回调时有效授权。单次入口检查与持久提交之间的撤销竞态须经同一受控提交边界解决，不能靠合成测试时间顺序宣称解决。
- 数据一致性：事件列表 200 条截断、无摘要旧记录及失败/未知提交都可能使重放失真。除非选定并验证耐久 UoW，不承诺持久 exactly-once 或业务/回执/通知原子性；响应丢失或结果未知时不能推断零写或换键重发。
- 兼容：目录 `externalId` 与运行时 `idempotencyKey` 差异、缺 body 资源 ID、旧客户端及旧 key 均需明确版本政策；失败不得自动退 v1。回滚只能关闭尚未生效的新 lane 或按迁移方案恢复，保留已提交业务事实、receipt 和历史审计，不通过删除回执制造可重放窗口。
- 外部证据：真实调用方、信任根、保留期限、供应方字段和现场签署尚未提供。生产六域继续 `NO-GO`。

实施前置按 A 合同/存储、B 供应方信任、生产现场三层分别审查，不能把 B 或生产材料误写成 A 的全部开发前置。五项尚未解除的阻断如下：

1. **A 合同：**T08/T05/T00 确认可信调用方命名空间、显式版本失败关闭与不可降级分流、未迁移 legacy allowlist、调用方迁移状态及期限；缺名单或期限时不能假定可永久双轨。
2. **A 存储：**T05/T08 与存储 Owner、T00 确认回调业务事实和 receipt 的唯一数据 Owner、同一 UoW 原子边界及失败恢复；200 项网关事件不是该权威。
3. **A 迁移：**存储 Owner 与 T00 决定旧无 digest 回执的失败关闭/人工对账、版本迁移、回滚与保留期限；不得自动补写历史证明。A 片需要迁移时，先取得单独 Accepted ADR。
4. **B 信任：**T08 与外部调用方确认 provider 信任锚、凭据保管、密钥轮换及失效窗口；本地演示 HMAC 密钥不构成该材料。B 的供应方信任设计可与 A 评审并行，A 不能假称 B 已完成。
5. **生产现场：**T00 与现场责任方确认真实供应方联调、权限/密钥配置、监测、容量、灾备和签署的放行条件；仓库合同测试仅是代码证据，GS-03 维持“未建设”，生产六域维持 `NO-GO`。

## Recommendation

建议优先评审方案 2 的五项决策及其调用方/存储输入，按批准后的依赖顺序拆分实施任务。TEST-024/025 已完成 v1 角色、持久副作用和三项边界风险刻画；下一步是审批 A 新 lane 的版本化请求、principal/key 语义、签名目标、精确授权与持久权威，不把这些留给 B。A 如需耐久 receipt 迁移，先批准单独迁移 ADR 并验证历史兼容与恢复；B 独立设计供应方信任、凭据轮换和时间/nonce 政策，不替 A 存储缺口兜底。只有本 ADR 转为 Accepted 且每个切片另行准入后，才可修改运行时；A 安全断言不能覆盖仍开放的 v1 legacy lane。

已完成的现状测试是 `test/gs03-referral-callback-v1-api.test.js`（TEST-024）与 `test/gs03-referral-callback-boundaries-api.test.js`（TEST-025），只刻画 v1。将来获批的新 lane 验收矩阵须另测：三合同 × 既有来源/接诊/区县/主管部门/外机构的迁移后权限；缺/未知版本、已迁移 principal 去版本降级、legacy allowlist/到期拒绝、新 lane 验签/字段/授权失败不回退 v1；缺字段、未知字段、嵌套别名冲突、`externalId`/`sourceSystem`/批准元数据改值重试、改 body/URL/认证 principal；确切授权有效/撤销/续授权、撤销与提交并发；同 namespace 同键同意图/异意图/异目标、跨 principal 及重放前权限变化；成功、明确回滚、已提交响应丢失与未知结果四态下会诊、档案、receipt、两类消息、审计的一致性和受控对账；超过旧 200 事件窗口和旧无摘要记录的迁移/回滚。测试须以隔离合成真实 HTTP、并发与受控故障注入证明实际实现，不能把拟议 403/409 预写为 v1 当前通过事实；既有 `test/api.test.js` 正向路径须保持。

若后续获准，候选写范围须逐片锁定：T05 独占 `src/http/routes/care-coordination.js` 的回调业务/授权适配及其新增专项测试；T08 独占外部 envelope、供应方认证/验签的经批准模块与专项测试；T00 独占 `server.js` 既有 normalizer/合同装配、中央持久化/迁移接线及 `config/lifecycle-governance.json`、六图、API/数据合同登记。具体新模块、migration 文件和接口由 Accepted 决策及 Owner 计划定名；未定名前不得创建平行服务或数据集合。跨域文件由 T00 协调单写者，不共同编辑同一文件。

本 ADR 作者只改这份 Proposed ADR；GOV-026 总账与六图由 T00 其他单写者登记。ADR 作者未运行回调业务测试，也未修改 runtime、DDL、测试、凭据、部署或生产状态；TEST-024/025 的冻结执行证据、本轮 T00 门禁与主线 CI 结果须由集成责任人分别登记，不从本段推断全轮未测试或 CI 已绿。不宣称 GS-03 全场景完成。后续实施若失败，应停在失败证据和受控恢复，保留旧业务/审计事实；生产验收仍需要真实环境、供应方联调与签署。
