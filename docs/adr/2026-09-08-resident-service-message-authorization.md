# ADR：居民服务评价投诉消息按角色与订单机构失败关闭

- 状态：Accepted
- 日期：2026-09-08
- 决策 ID：ADR-SEC-011
- 决策 owner：T05 care-coordination security owner
- 受保护路径集成 owner：T00
- 评审人：平台治理需求批准方、T00 安全集成评审
- 影响范围：居民护理与陪诊评价消息列表、消息回执、历史消息兼容
- 关联问题：REQ-SEC-011、RISK-SEC-011、SEC-011、OPS-017
- 复审日期：2027-03-08
- 替代：无
- 被替代：无

## Problem

既有 `canAccessTaskMessage` 对非主管部门账号允许“角色相同”“可访问居民”或“消息创建人”任一条件通过。居民提交护理或陪诊评价后生成的机构目标消息因此可能被居民读取或回执，也可能被同角色但非订单责任机构的账号读取或回执。回执接口还接受任意状态字符串。客户端过滤只是纵深防御，不能替代服务端授权。

SEC-011 独立于 OPS-017 的前端增量，因而只依赖已集成的 GOV-002；先合入本安全边界，再由 OPS-017 rebase，避免形成互相等待的集成死锁。

## Options

### Option A：维持通用角色或居民范围兼容

保留当前消息列表和回执逻辑，只依赖居民端过滤机构消息。

### Option B：所有历史消息立即要求已持久化 `targetOrgCode`

新旧机构消息都必须已有精确机构字段，否则全部拒绝。

### Option C：评价投诉消息绑定权威订单并对历史记录唯一派生

新生成的护理与陪诊评价消息写入 `messageType` 和 `targetOrgCode`。读取与回执同时要求目标角色、目标机构及权威订单访问范围；历史记录缺少机构字段时，只从其 `sourceCollection + sourceId` 指向的权威订单及机构目录唯一派生。缺订单、缺代码或出现多个不同机构代码时失败关闭。

## Advantages

| 选项 | 优点 |
|---|---|
| A | 无兼容成本 |
| B | 规则最简单，所有消息都使用显式字段 |
| C | 关闭当前越权，同时允许机构归属可唯一证明的历史评价消息继续使用；不新增第二订单或投诉事实源 |

## Disadvantages

| 选项 | 缺点 |
|---|---|
| A | 保留个人敏感投诉信息越权与跨机构处置风险 |
| B | 历史消息大面积不可见，需要先完成数据迁移 |
| C | 读取时需要查询来源订单；归属冲突的历史或新消息会保持不可处理，需人工治理来源数据 |

## Migration cost

采用 Option C，迁移成本为中。无 schema 或 migration；新字段为 JSON 加法兼容。现有读取方可忽略新增字段。历史记录不批量回写，只在访问时从权威订单推导；无法唯一推导的记录不得由机构读取或回执。

## Risk

| 风险 | 影响 | 缓解与停止条件 |
|---|---|---|
| 订单机构归属冲突 | 消息无法由机构处理 | 陪诊订单的订单机构、服务商机构和就诊机构代码只要不唯一即失败关闭；不得任选一个代码 |
| 主管部门越权处置 | 监督账号改变机构处置状态 | 主管部门可查看监督投影，但不是目标角色时不得提交回执 |
| 回执被误作投诉结案 | 投诉状态错误关闭 | 回执仅允许 `read`、`acknowledged`、`handled`，且不得修改订单 `complaintStatus` |
| 历史消息扩大授权 | 旧记录泄露 | 只从精确来源订单唯一派生；缺失、孤儿或冲突均拒绝 |
| 拒绝事件泄露投诉正文 | 二次敏感信息暴露 | 拒绝审计只记录消息 ID、操作者、角色与稳定原因，不记录标题或正文 |

## Recommendation

采用 Option C。非主管部门访问评价投诉消息必须同时满足：消息目标角色等于账号角色、角色为机构、唯一机构代码等于账号 `orgCode`，并且账号仍可访问该权威订单。居民、县域、医保、错误机构和其他错误角色均不得读取或回执。主管部门保留列表监督可见性，但不得代机构写回执。

本轮用户在已获知高风险阻塞后明确要求“继续开发，完成各线程缺口，闭环完善”，T00 随后确认该指令作为人工方向批准，并完成受保护路径安全评审；因此本 ADR 状态为 Accepted。批准仅覆盖 SEC-011 所列边界，不授权生产发布或扩大投诉状态机。

## Compatibility and historical messages

- 新护理评价消息从互联网护理订单及其机构目录唯一派生机构代码。
- 新陪诊评价消息同时核对订单机构、服务商机构和就诊机构代码；不同非空代码冲突时不写入可授权机构代码，访问失败关闭。
- 历史评价消息以来源订单仍保留的 `taskAction=quality-feedback` 识别；缺少 `targetOrgCode` 时使用同一唯一派生算法。
- 显式 `targetOrgCode` 仍须通过目标角色和订单访问范围校验，不能单独授予权限。
- 其他既有消息保持原兼容策略，本 ADR 不借机重写全平台消息模型。

## Implementation plan

1. 在组合根的 T05 消息安全函数中增加评价消息识别、权威订单定位与唯一机构推导。
2. 生成护理与陪诊评价消息时写入加法字段 `messageType`、`targetOrgCode`。
3. 列表使用角色、机构和订单范围联合判断；回执额外禁止主管部门代办并限制机构回执状态。
4. 授权拒绝写入既有链式安全审计；不记录投诉正文。
5. 运行真实 HTTP 负向矩阵、相关 T05 特征测试、静态质量、分级门禁与 required CI。
6. SEC-011 先独立合入主线，再由 OPS-017/#264 rebase；PWA 由 OPS-019 独立处理。

## Rollback

回退 SEC-011 单一提交即可恢复原消息筛选与回执逻辑。没有 schema、migration、外部系统调用或不可逆数据操作；已写入的加法字段可被旧代码忽略。回退会重新暴露已确认的高风险越权，因此只能在停止相关消息入口并由安全 owner 批准的情况下执行。

## Security considerations

角色判断以服务端可信身份为准，机构判断使用账号 `orgCode` 与订单/目录代码，不接受客户端提供机构。授权在读取回执 body 之前执行。失败事件不写居民 ID、投诉内容、凭据或机构名称。真实外部身份映射、持续告警、容量、灾备和现场安全验收仍未完成，生产保持 `NO-GO`。
