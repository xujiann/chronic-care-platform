# 隔离环境主存储单批次 relay

- 状态：Accepted
- 批准：2026-09-23 用户批准限定切片。
- 范围：T00 单写的显式 rehearsal 组件及合成、真实 PostgreSQL 专项测试；生产 NO-GO。

## 背景与备选

已绑定的 SQLite 提交凭证、PostgreSQL 精确重放和独立持久 checkpoint 均已交付，但尚无协调它们的单批次调用方。可以继续手动组合（容易遗漏故障窗口）、直接启用自动 worker（超出当前授权），或先建立显式单批次 rehearsal 端口。本轮采用第三种。

## 决策

调用方须预先完成隔离目标身份绑定及空目标 checkpoint 初始化。`runOnce` 首先读取并核对持久进度，再从原始品牌化源凭证取下一批，仅向已绑定正式合同投递这一批；只有目标返回匹配批次的成功或精确重复状态，才推进 checkpoint。目标已提交、checkpoint 未写的窗口依靠目标批次账本重放恢复。无下一批返回 idle；结果只包含状态和技术序号，不输出业务正文。

不挂载 HTTP、业务请求或常驻 worker，不自动初始化、重绑、补历史或连接真实数据。不能把本地 checkpoint 当作外部信任锚；单进程测试不证明多实例、TLS、容量、灾备或现场准入。

## 兼容、迁移、回滚与安全

不修改既有 API、数据库 schema、生产配置或依赖。新模块为显式可选调用，旧流程不变。发生失败时停止调用并保留源、目标账本和 checkpoint，不自动删改或回退已提交目标；仅清理测试自建且已核实身份的隔离库和临时文件。真实 PostgreSQL 用例必须在专用 CI 零跳过执行，本地跳过不算证据。独立审查、冻结与串行门禁后方可考虑保护集成；生产仍为 NO-GO。

## Advantages, disadvantages, migration cost, risk and recommendation

优势是已有三个受控组件以单批次显式方式串联，可复现跨库故障窗口。缺点是没有常驻调度、运行遥测或多实例协调；迁移成本仅为可选模块与测试，无 schema 迁移。主要风险是误把 rehearsal 当作生产 relay，故推荐保持无服务挂载、失败关闭，并在独立生产 ADR 及现场证据之前维持 NO-GO。
