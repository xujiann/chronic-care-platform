# ADR：建立平台全生命周期治理控制塔

- 状态：Accepted
- 日期：2026-09-07
- 决策 owner：T00
- 评审人：平台治理需求批准方
- 决策范围：需求、任务组合、六图状态、分级门禁、黄金场景与生产准入
- 关联问题：REQ-GOV-001、RISK-GOV-001、GOV-002
- 复审日期：2027-03-07
- 替代：无
- 被替代：无

## Problem（问题）

现有主线已建立 process 隔离、PLAN、架构地图、最小补丁、CI、证据和生产 NO-GO，但强项集中在单项代码变更。T00 同时承担总控和实施语义，六张地图缺统一状态层，需求至证据没有单一机器链，测试门禁缺少明确的四级入口，生产 NO-GO 的解除条件分散。因此局部代码存在可能被误报为能力完成，仓库通过也可能被误解为生产就绪。

## Options（可选方案）

### Option A：维持分散文档和现有 CI

继续由各任务自行描述依赖、状态和证据，T00 人工汇总。

### Option B：建立独立外部项目管理平台

把需求、风险、任务、证据和准入迁至新的外部系统，并由仓库只保存链接。

### Option C：在仓库建立 T00 机器控制塔

建立一个版本化、可执行的治理事实源，复用现有 process、ADR、测试、PR、CI 和生产 preflight；T00 只管理组合与放行，领域实施继续使用独立任务和 worktree。

## Advantages（优点）

| 选项 | 优点 |
|---|---|
| A | 无迁移成本 |
| B | 可获得成熟的组合管理界面和组织协作能力 |
| C | 与代码、测试和 CI 同版本；可以失败关闭；不引入新依赖或第二业务事实源 |

## Disadvantages（缺点）

| 选项 | 缺点 |
|---|---|
| A | 依赖人工记忆，不能阻止状态越级或无证据完成 |
| B | 需要账号、权限、同步、供应商和数据出境评估，仓库与外部平台可能漂移 |
| C | JSON 事实源需要持续维护；首版没有图形化组合管理界面 |

## Migration cost（迁移成本）

| 选项 | 总体等级 | 代码与测试 | 数据与兼容 | 部署与运维 |
|---|---|---|---|---|
| A | 低 | 无 | 无 | 人工成本持续增加 |
| B | 高 | 需要同步适配器 | 需要迁移治理元数据 | 新增外部服务和权限体系 |
| C | 中 | 新增配置、校验器、测试和 CI 接线 | 不修改业务数据或 schema | 新增夜间/手动门禁，不激活生产能力 |

## Risk（风险）

| 风险 | 可能性 | 影响 | 缓解措施 | 退出/停止条件 |
|---|---|---|---|---|
| 台账成为第二业务待办中心 | 中 | 中 | 明确只管理研发组合，不接业务运行待办 | 出现业务记录或居民数据立即停止 |
| 仓库证据被当作生产证据 | 中 | P0 | GO 只接受外部 production evidence | 任一准入域缺外部证据即 NO-GO |
| 门禁重复导致反馈变慢 | 中 | 中 | quick/PR/nightly/release 分层，影响分析选择范围 | 同类门禁无收益重复时独立优化 |
| 状态和实现漂移 | 中 | 高 | CI 校验引用、状态晋级、ADR 和证据 | 无法机器验证时不得晋级 |
| 延迟决策 | 高 | 高 | 继续存在局部完成、整体不可判断 | 不适用 |

## Recommendation（建议）

采用 Option C。用户已批准建立该工作流，T00 可实施机器事实源、校验器、测试、PR 模板和 CI 门禁。该批准不授权修改业务运行时、数据库、外部系统或执行生产发布。

## Compatibility and migration（兼容与迁移）

首批只登记治理任务自身、六张地图状态层、十条黄金场景和六域生产准入；既有领域任务按后续独立 PLAN 分批导入。现有 T00–T09、业务待办中心、API、数据库和部署拓扑保持不变。合并后以 PR/CI 证据把 GOV-002 从“已验证/待集成”晋级为“已集成”。

## Rollback（回滚）

回退本任务提交，移除新增配置、脚本、测试、文档、package 入口和 workflow 接线即可。没有业务数据、schema、migration、外部状态或不可逆点。

## Security considerations（安全考虑）

事实源只保存治理元数据和受控引用，不保存居民、患者、凭据、私钥、供应商原始载荷或现场证据正文。外部生产证据必须使用既有摘要、签名、有效期、职责分离和防重放边界；控制塔不得创建模拟 GO。

## Validation（验证）

- `node --test test/lifecycle-governance.test.js`
- `npm run governance:lifecycle`
- `npm run process:verify`
- `npm run repository:governance:verify`
- `npm run architecture:test`

## Decision outcome（决策结果）

2026-09-07 由需求批准方明确要求建立上述工作流，T00 接受 Option C 的仓库治理范围。生产资格、外部证据和现场授权不在本批准范围，继续 `NO-GO`。
