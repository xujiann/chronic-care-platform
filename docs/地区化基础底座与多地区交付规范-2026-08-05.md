# 地区化基础底座与多地区交付规范

## 目标

平台核心只承载跨地区稳定共性。行政区划、机构名称、地方字典、政策规则、界面品牌、外部接口参数和现场流程放入 `regions/<regionCode>`。地区实现不得复制平台核心，也不得把地方判断重新散落到 `server.js` 或领域路由中。

默认运行 `regions/template`，使核心平台不依赖大连配置。大连作为首个兼容迁移样板位于 `regions/210200`。存量硬编码按领域迁移，新增硬编码由自动审计直接阻断；只有对应领域回归、地区矩阵和现场验收全部通过后才能删除兼容路径。

## 目录与职责

```text
config/regions.json                   已注册、可启用地区
regions/template/                     新地区最小模板和核心 CI 基线
regions/210200/                       大连地区包
  manifest.json                       身份、兼容范围、特性和扩展声明
  config/*.json                       无密钥的地区配置
  extensions/index.js                 约定入口，注册白名单扩展
src/platform/regional/
  region-manifest.js                  清单/配置校验与只读加载
  extension-registry.js               扩展权限、归属和版本校验
  regional-runtime.js                 地区上下文与领域隔离视图
  regional-values.js                  组织、行政区、术语与兼容本地化解析
  active-region.js                    Node 业务模块统一读取当前部署地区
  composite-release.js                平台版本+地区版本组合制品
regional-context.js                   浏览器端地区上下文和动态界面本地化
scripts/regional-foundation.js        状态、矩阵与组合包命令
scripts/regional-hardcode-audit.js    存量基线与新增硬编码阻断
```

T00 负责地区协议、装配、注册表、CI 和组合发布。各领域进程仍只负责自己的领域实现；新增地区扩展必须声明 `ownedDomain`，跨领域协议变更交由 T00 集成。

## 新地区接入流程

1. 从 `regions/template` 复制为六位行政区划代码目录。
2. 在 `config/regions.json` 注册地区，初始保持最少特性。
3. 填写机构、区划、字典、政策、界面与接口配置；只保存环境变量名称或受控证据引用，不保存真实地址中的认证信息、密钥或业务原文。
4. 如需扩展，在 `manifest.json` 声明类型、ID、版本、归属领域和启用状态，再由 `extensions/index.js` 注册同名实现。JSON 清单不能指定任意代码路径。
5. 运行地区窄测试、通用模板测试、目标地区测试和全量回归。
6. 生成组合版本。平台版本、地区版本和地区全部文件摘要共同决定不可变 `releaseId`。
7. 技术就绪不等于生产就绪。联合测试、安全与商密评估、监控、容灾、现场验收和正式审批必须来自真实环境。

## 开发与验证命令

```powershell
npm run regional:check
npm run regional:test
npm run regional:hardcodes
npm run regional:status -- --region=template
npm run regional:status -- --region=210200
npm run regional:matrix
npm run regional:package -- --region=210200
```

CI 独立执行 `core`、`template` 和 `dalian-210200` 三个矩阵目标。生产部署包同时包含地区注册表、地区运行时和已注册地区包。

## 业务模块读取规则

- Node 领域服务通过 `src/platform/regional/active-region.js` 取得当前部署的只读地区值，不自行解析 `REGION_CODE`，也不直接读取地区 JSON。
- 浏览器页面必须在 `auth.js` 和领域脚本之前加载 `regional-context.js`；组织使用 `organization(id)`，行政区使用 `area(id)`，平台术语使用 `term(id)`。
- `regions/*/config/organization.json` 保存相同业务角色在不同地区对应的机构；`geography.json` 保存行政区角色；`localization.json` 保存平台术语和受控兼容映射。
- 业务记录的主键、历史证据编号和已签名原始载荷不做字符串替换。展示名称、默认机构、默认行政区和新建演示数据必须从地区上下文取得。
- 兼容旧输入时只能通过中央 `legacyReplacements` 解析，业务模块不得再次维护地区别名表。

## 当前领域迁移状态

首批已迁移医保支付、院前急救、血液创新、公共卫生亮点、数智医院公卫协同、体检、互联网护理、影像云和质量运营治理。上述模块的机构名称与行政区默认值已由地区上下文提供。

其余存量主要位于平台旧版页面、居民端旧演示数据、`server.js` 聚合种子和历史联调脚本。`config/regional-hardcode-baseline.json` 只允许受审计的运行时 JS/HTML 既有匹配保持或下降：既有文件数量增加、或新文件出现大连/210200/Dalian 直接字面量，`npm run regional:hardcodes` 均失败。

## 安全与发布门禁

- 地区代码只允许 `template` 或六位行政区划代码。
- 配置引用只能指向地区目录内的 `config/*.json`，并校验真实路径以阻止穿越和符号链接逃逸。
- 清单和配置拒绝口令、令牌、密钥、凭据、签名等敏感字段。
- 扩展只能使用受支持类型、归属领域、显式权限和受控数据集合。
- 未声明实现、未注册声明、版本或归属不一致均启动失败。
- 地区接口默认不激活；大连适配器的 `productionEnabled` 为 `false`。
- 组合包 `technicalReady` 只表示结构、兼容性和摘要通过；`productionReady` 固定为 `false`，直到外部证据与批准完成。

## 部署锁定与配置契约

- 每个地区运行时同时生成 `manifestDigest` 和 `contentDigest`。后者覆盖地区注册信息、清单、全部 JSON 配置和扩展代码，配置或代码任一字节变化都会得到不同摘要。
- 组合发布包的 `activation` 字段直接给出 `REGION_CODE`、`REGION_DEPLOYMENT_CLASS` 和 `REGION_CONTENT_DIGEST`。部署环境应使用同一发布包中的三个值，不人工重新拼写。
- 设置 `REGION_DEPLOYMENT_CLASS` 后，运行时会校验注册表中的地区类别；设置 `REGION_CONTENT_DIGEST` 后，运行时会校验完整地区内容。类别或摘要不一致时启动失败。
- `feature-flags`、`geography`、`localization` 和 `organization` 是所有地区包的强制公共配置。运行时校验其 schema、必填目录、实体字段、唯一代码、字符串映射和清单特性一致性。
- 地区目录只允许 `.json` 和 `.js` 普通文件，不接受符号链接或未纳入摘要的旁路文件。
