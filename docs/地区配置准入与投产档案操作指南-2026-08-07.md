# 地区配置准入与投产档案操作指南

## 1. 目标

本能力把“地区包是否满足平台契约”和“单地区是否具备候选投产条件”拆成两层检查：

1. 地区配置准入审计检查配置契约、公共配置、能力映射、扩展声明、内容摘要和生产类别策略。
2. 地区现场证据准入验证服务端指定且 SHA-256 锁定的外部清单，检查五类证据、发布绑定、有效期和独立复核。
3. 单地区投产档案把配置审计、现场证据、组合发布、不可变发布账本、多地区运维状态、备份/证书状态和 PostgreSQL 主存储契约聚合成一份最小化档案。

两层检查都只证明本地技术控制是否完整。工具和接口始终输出 `productionReady=false`，真实接口联调、安全与商密测评、监控值守、灾备演练、现场验收和外部生产批准仍由相应责任方提供。

## 2. 生成配置准入报告

生成全部已启用非模板地区的报告：

```powershell
npm.cmd run regional:configuration
```

只检查一个地区：

```powershell
npm.cmd run regional:configuration -- --region=<六位地区代码>
```

默认输出：

- `release/regional-configuration-readiness.json`
- `release/regional-configuration-readiness.md`

报告只包含配置文件声明、条目数量、能力覆盖、内容摘要和检查结果，不包含机构、区划、字典、政策、适配器参数或其他配置值。`technicalReady=true` 表示地区包符合平台契约；只有 `deploymentClass=production` 的地区才可能获得 `candidateEligible=true`，但该字段仍不构成投产批准。

## 3. 验证地区现场证据

以 `deploy/regional-site-evidence.template.json` 为结构模板，在仓库之外的受控目录准备地区证据清单。模板中的占位值和过期时间不会通过验证，必须替换为当前地区组合发布的真实绑定和真实证据摘要。

每个地区必须配置：

```text
REGIONAL_SITE_<地区代码>_EVIDENCE_FILE=<绝对路径>
REGIONAL_SITE_<地区代码>_EVIDENCE_SHA256=sha256:<文件字节摘要>
```

运行验证：

```powershell
npm.cmd run regional:evidence
npm.cmd run regional:evidence -- --region=<六位地区代码>
```

默认输出 `release/regional-site-evidence-readiness.json` 和 `release/regional-site-evidence-readiness.md`。五类必备范围为：身份与机构、医院接口联调、安全与合规、运维与灾备、独立现场验收。

验证器要求每类范围恰好出现一次、仍在有效期内、证据保管角色与复核角色不同，且证据主体摘要与当前组合发布摘要一致。文件路径、受控引用、角色名称和证据正文不会进入报告或 API。

## 4. 生成投产档案

生成全部地区档案：

```powershell
npm.cmd run regional:dossier
```

只生成一个地区档案：

```powershell
npm.cmd run regional:dossier -- --region=<六位地区代码>
```

默认输出：

- `release/regional-cutover-dossier.json`
- `release/regional-cutover-dossier.md`

`candidateReady=true` 必须同时满足：

- 地区为生产类别且配置候选资格通过；
- 当前组合发布已进入不可变发布账本；
- 发布状态已达到批准候选、已部署或已验证；
- 运维清单健康且地区内容摘要与发布绑定一致；
- 备份检查时间和证书有效期存在且通过；
- PostgreSQL 主存储契约处于可切换模式。
- 五类地区现场证据均通过摘要锁定、时效、独立复核和发布绑定检查。

任一条件缺失都会输出稳定阻断码并保持关闭。即使全部条件通过，也只会打开 `candidateReady`，不会改变 `productionReady=false`。

## 5. 管理端接口

卫健委管理端身份可读取：

```text
GET /api/regional/deployments/:regionCode/dossier
```

接口要求六位地区代码且不接受任何查询参数。响应仅返回：

- 地区代码、类别和组合发布摘要；
- 本地控制状态、候选状态和生产边界；
- 配置、发布、治理、运维、备份、证书、存储门禁；
- 五类现场证据的存在性、时效、独立复核和发布绑定状态；
- 稳定阻断码和档案摘要。

接口不返回站点 URL、解析地址、配置值、密钥、签名、人员身份或证据正文。未知地区与不可读取状态使用不透明的 404 响应，读取成功与拒绝都会写入现有审计链。

## 6. 发布流水线

推荐顺序：

```powershell
npm.cmd run regional:check
npm.cmd run regional:test
npm.cmd run regional:configuration
npm.cmd run regional:evidence
npm.cmd run regional:dossier
npm.cmd run release:manifest
npm.cmd run release:report
npm.cmd run deploy:check
```

`release:report` 已包含四项地区产品线门禁：

- `regionalConfiguration:readiness`
- `regionalConfiguration:valueBoundary`
- `regionalSiteEvidence:verifier`
- `regionalSiteEvidence:minimizedBoundary`
- `regionalDossier:control`
- `regionalDossier:productionBoundary`

这些门禁检查本地控制链和信息最小化边界。候选尚未就绪可以作为真实阻断状态存在；结构错误、摘要漂移、敏感值泄露或生产边界失效会阻断发布检查。

## 7. 处置原则

| 阻断类型 | 责任方 | 处理方式 |
| --- | --- | --- |
| 配置契约、能力映射或扩展缺失 | 地区配置开发线 | 修改地区包后重新生成组合发布摘要 |
| 组合发布未登记或状态不足 | 发布治理线 | 追加不可变发布事件，不修改历史记录 |
| 摘要漂移 | T00 集成线 | 停止投产，核对制品与地区内容绑定并重新登记 |
| 运维、备份或证书未通过 | 部署运维线 | 补齐真实检查记录和受控探测回执 |
| 现场证据未配置、过期或摘要漂移 | 现场责任方与发布治理线 | 在仓库外更新真实证据清单和 SHA-256 锁定值，不得修改报告结果绕过 |
| PostgreSQL 主存储未就绪 | 数据存储线 | 完成契约模式、迁移、容量、备份和恢复验证 |
| 外部生产证据未齐 | 现场责任方 | 完成真实联调、测评、值守、灾备和签字；不得用本地模拟数据替代 |
