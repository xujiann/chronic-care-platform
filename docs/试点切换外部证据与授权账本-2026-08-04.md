# 试点切换外部证据与授权账本

## 目标

在不可变试点切换包之外维护一条独立、追加式、元数据化的证据与授权记录链。账本支持外部证据登记、撤销和四方授权，但不保存原始报告、凭据、患者数据，也不执行生产切换。

## 安全边界

- 账本和命令输入必须使用绝对路径。
- 账本必须是普通文件，目录不得是符号链接。
- 单个事件上限 32 KiB，账本上限 4 MiB。
- 写入使用同目录独占锁、追加写入和 `fsync`。
- 每个事件包含序号、前一事件摘要和自身 SHA-256 摘要。
- 撤销通过新事件表达，不修改或删除历史事件。
- 外部证据必须绑定当前试点包指纹，签发者与验证者必须不同。
- 四个授权角色必须使用不同账号，并绑定同一试点包指纹、回滚负责人和有效期。
- HTTP 控制面只读，始终返回 `cutoverExecutionAuthorized: false`、`productionPrimary: false` 和 `productionReady: false`。

## 操作

```text
npm run platform:cutover-authorization -- register-evidence --ledger=<absolute-ledger-path> --input=<absolute-command-path>
npm run platform:cutover-authorization -- record-approval --ledger=<absolute-ledger-path> --input=<absolute-command-path>
npm run platform:cutover-authorization -- revoke --ledger=<absolute-ledger-path> --input=<absolute-command-path>
npm run platform:cutover-authorization -- status --ledger=<absolute-ledger-path> --package=<absolute-package-path>
```

模板位于 `docs/evidence-templates/platform-iterations/`。模板只描述字段，不能作为真实证据或授权。

## 判定

只有以下条件同时满足时才返回非执行性的 `GO-CANDIDATE`：

1. 试点包全部本地和外部证据绑定通过；
2. 账本摘要链完整；
3. 安全评估、告警演练、灾备演练、现场验收均已登记、未撤销且未过期；
4. 平台运维、安全合规、数据平台、项目负责人四个角色独立授权；
5. 所有授权均未过期并绑定当前试点包指纹。

`GO-CANDIDATE` 仍不表示生产已切换。真实身份核验、现场委员会决策和执行操作继续由仓库外受控流程负责。
