# 陪诊信息平台研发报告

生成日期：2026-07-08

系统范围：慢病医防融合管理平台助医陪诊模块，包含居民端陪诊预约、机构/监管端服务管理、医院回执接口、消息审计和上线证据。本文用于研发汇报、试点沟通和上线评审准备，不替代正式项目立项、采购、等保测评或业务主管部门批复。

## 一、研发结论

陪诊信息平台已在统一平台架构内形成可运行的受控试点版本。当前系统复用 `server.js`、统一登录、居民家庭关系、消息中心、任务流、审计日志和发布门禁，不建议第一阶段单独建设平行系统或单独购买陪诊专用服务器。

居民端只展示已经完成并可验证的上线功能：陪诊预约、家庭成员代办、关联挂号、服务主体选择、预约前核对、订单进度、医院回执通知、取消申请和质量反馈。实名身份、短信网关、电子健康卡、陪诊师移动端、电子签章、补贴结算、投诉工单和真实医院 HIS/导诊台接口仍作为生产上线前或后续阶段开发项管理，不在居民端提前暴露。

当前版本适合开展内部测试、业务演示、医院接口联调和小范围试点准备；正式上线仍需完成身份短信、HIS/导诊台、合同保险附件、补贴结算、监控审计、现场签字和安全合规验收。

## 三、已实现功能

| 家庭成员代办 | 已实现 | 居民端按本人和家庭授权成员展示预约对象，API 按居民范围裁剪订单 |

## 五、下一步开发计划

### 第一阶段：测试服务器与试点联调

目标：让业务部门、社区、服务机构和医院信息科在统一测试地址完成闭环验证。

1. 部署测试服务器：租用 2 vCPU / 2 GiB 或 2 vCPU / 4 GiB 轻量云服务器，使用独立 `DATA_DIR` 和模拟数据。
2. 建立测试账号：居民、家庭成员、服务机构、医院信息科、卫健委监管账号按角色发放。
3. 完成医院联调包：确认 `hospitalCode`、科室/医生字典、就诊号、队列号、门诊服务台联系人和退回补证规则。
4. 完成居民端真机验收：覆盖预约、取消、医院确认、退回补充、通知、进度和反馈。
5. 固化试点证据：输出测试记录、问题清单、截图、接口日志和 `launch:smoke -- --base-url` 结果。

### 第二阶段：生产外部能力接入

目标：补齐正式上线必须依赖的外部通道。

1. 接入统一身份、实名核验、电子健康卡和家庭/监护关系核验。
2. 接入短信验证码、服务变更通知和订阅消息模板。
3. 与医院 HIS/预约挂号/门诊导诊台完成正式接口联调。
4. 建立合同、保险、授权和验收附件存储，准备电子签章能力。
5. 将审计日志接入日志平台或 SIEM，明确告警联系人和值守机制。

### 第三阶段：履约与监管闭环

目标：从“可预约”升级为“可监管、可结算、可追责”。

1. 建设陪诊师移动端签到、轨迹留痕、到院确认、异常上报和服务记录。
2. 建设投诉工单、黑名单、服务主体年度复核和星级评价。
3. 建设补贴资格核验、费用明细、结算对账和财务导出。
4. 建设质量监测报表：预约量、履约率、取消率、退回补证率、投诉率、满意度。
5. 建设街镇/社区协助申请台账和志愿者/时间银行扩展接口。

### 第四阶段：正式上线运行标准

目标：形成可持续运维和监管取证能力。

1. 完成域名、HTTPS、ICP备案、隐私协议、用户协议和现场上线公告。
2. 完成等保测评、密评或主管部门要求的安全验收。
3. 完成生产数据库、对象存储、备份恢复和灾备演练。
4. 完成生产监控、日志归档、告警值守、应急预案演练。
5. 完成上线签字：老龄健康、卫健信息、医院信息科、社区、服务机构、医保/民政补贴经办和运维安全部门。
