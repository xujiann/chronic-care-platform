适用范围：`chronic-care-platform` 现已开发平台、卫生健康综合管理服务系统、居民端、公共卫生、医共体、接口治理、发布证据和生产上线准备。

## 一、总体判断

现平台已经从慢病医防融合演示系统扩展为覆盖卫健管理端、机构端、居民端、县域医共体、公共卫生、影像云、免疫规划、妇幼证照、互联网护理、陪诊、挂号、数据治理、科研沙箱、信用绩效和发布门禁的一体化研发平台。当前代码库具备 Node API、SQLite/JSON 双路径、统一登录、角色权限、审计事件、接口契约、发布报告、部署检查和专项 readiness 脚本，能够支撑方案汇报、受控演示、联调准备和阶段验收。

对照二期可研，当前主要不足不是“没有页面”，而是“未达到正式项目建设口径”：真实医疗机构和区县平台对接尚未完成，检验结果互认确权链、辽事通/健康大连统一入口、综合监管统计、区域绩效正式指标、商用密码改造、生产数据库、容灾备份、等保密评和现场签字仍缺生产级证据；家庭医生签约履约已形成演示闭环，但统一入口、电子签章、真实团队名册和服务包政策仍需现场接入。下一步应从“演示闭环”转入“可联调、可监管、可测评、可上线”的工程化建设。

### P2：补齐安全测评、运维和运营体系

1. 商用密码和密评

   当前代码已提供 `GET /api/commercial-crypto/center`、能力动作 API、平台“商用密码能力适配中心”和 `security:commercial-crypto-readiness` 发布证据。运行时发现 SM2/SM3/SM4 仅表示本机 OpenSSL 兼容性，不表示产品认证或密评通过；生产门禁继续由设备资质、证书密钥、现场验证和第三方报告阻断。
   - 建立国密能力适配层，预留 SM2/SM3/SM4、USBKey、签名验签服务器、时间戳、服务器密码机调用接口。
   - 与第三方密评和政务云资源确认后，完成综合监管和区域绩效系统密改证据。

   - 接入数据库审计、SIEM 或审计导出路径。
   - 实施本地 30 天、远程 7 天保留策略，形成热备、远程备份和恢复演练报告。

3. 运维运营
   - 已建立值班交接、事件确认/升级/演示关闭、恢复演练、灰度回滚证据和现场申请动作；下一步接真实呼叫、热线工单、实名排班和月度运行报告签字。

## 五、验收原则

1. 每个新增能力必须同步页面入口、API、数据对象、审计事件、测试、readiness、release report、deploy check 和现场验收材料，形成统一的 release gate。
2. 演示数据、模拟接口和本地签名只能标为“演示可用”或“联调准备完成”，不能标为“生产 ready”。
3. 真实上线前必须具备统一身份、生产数据库、真实接口、等保密评、国密设备、监控灾备、审计留存和多方签字。
4. 当前最稳妥的推进方式是“先最小现场样板，再扩面”，避免在没有接口窗口和安全测评资源时同时铺开所有医院和区县。
