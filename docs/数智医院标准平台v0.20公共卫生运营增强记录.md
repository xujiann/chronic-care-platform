# 数智医院标准平台 v0.20 公共卫生运营增强记录

## 一、建设目标

v0.20 在 v0.19 公共卫生八通道和事件闭环基础上，补齐试点运营所需的专业系统关联、医院范围筛选、SLA 超时升级、处置统计和批量导出能力。数智医院协同账本继续承担跨部门协同，不替代公共卫生专业系统。

## 二、已实现能力

### 2.1 专业系统只读关联

- 协同事件可引用公共卫生专业事件编号、交换任务、交换运行、证据包和探测通道。
- 服务端读取专业系统最新状态并生成最小必要摘要。
- 关联摘要包括专业事件状态、交换回执状态、补偿状态、可信探测判定和证据完成度。
- 不返回端点地址、网络明细、密钥、签名、nonce、凭据、证书、私钥或原始载荷。
- 缺少可信探测时明确显示阻断原因，不以受控演示探测替代生产证据。

### 2.2 SLA 运营

- 对开放和关闭事件分别计算 `overdue`、`due-soon`、`within-sla`、`closed-overdue` 和 `closed-within-sla`。
- P0、P1、P2 分别使用红、黄、提示三级升级路径。
- `escalate-overdue` 使用乐观修订号，仅允许超时且未升级的开放事件执行。
- SLA 升级单独留痕，不跳过“待核查 -> 处置中 -> 待复核 -> 已关闭”状态机。

### 2.3 筛选、统计与导出

- 按医院、业务通道、级别、状态和是否超时筛选。
- 统计开放、关闭、超时、即将超时、已升级和专业关联事件数。
- 提供按医院、通道、级别和状态的分组统计。
- 支持受鉴权的 JSON 和 CSV 批量导出。
- CSV 输出防止公式注入，导出内容仅包含事件元数据和安全摘要。

## 三、正式接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/api/digital-hospital/public-health/coordination` | 获取筛选后的运营工作台、SLA、统计与专业关联 |
| `POST` | `/api/digital-hospital/public-health/incidents` | 登记最小化协同事件 |
| `POST` | `/api/digital-hospital/public-health/incidents/{incidentId}/actions` | 推进生命周期或执行 `escalate-overdue` |
| `GET` | `/api/digital-hospital/public-health/incidents/export` | 按当前筛选条件导出 JSON/CSV |

## 四、安全与投产边界

1. 专业系统保持事实数据源，数智医院平台仅保存引用并返回摘要。
2. 专业探测摘要复用现有可信验证结果，不读取或导出受限原始回执。
3. 导出接口要求卫健委角色，并记录安全审计事件。
4. 现场证据、真实回执、灾备演练和多方审批未完成前，`productionReady` 始终为 `false`。
5. 页面中的受控样例仅用于验收演示，不作为生产连通性证明。
