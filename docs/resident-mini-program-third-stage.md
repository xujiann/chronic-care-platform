# T04-MP 第三阶段：上线前安全硬化与真机适配契约

## 交付结论

第三阶段在第二阶段失败关闭模型上新增运行时安全策略层 `resident-mini-program-runtime-policy.js`。该策略只定义和执行居民端契约，不替代服务端安全校验，也不修改 T00 管理的公共服务、样式、构建、离线缓存或发布文件。

软件通过专项门禁后可进入 T00 集成和微信、支付宝真机联调，但在正式应用标识、服务端登录码交换、签名验签公钥、通知模板和权威居民关系证据接入前，不得表述为生产上线完成。

## 安全契约

### 平台登录码

- 微信 `code`、支付宝 `authCode` 仅在适配器内存中短暂存在，并立即交给注入的服务端交换函数。
- 原始登录码不得作为适配器返回值、缓存值、日志字段或错误文案。
- 服务端回执必须包含稳定交换标识、平台、主体指纹、签发时间、消费时间、过期时间和“服务端已消费”确认。
- 登录码最长有效五分钟；主体、平台、消费窗口或回执不匹配时失败关闭。
- 已消费交换标识只保存在当前内存防重放表中；重复回执拒绝。
- 服务端不得在交换回执中返回原始登录码、访问令牌或刷新令牌。

### 平台能力矩阵

- 项目最低版本契约：微信基础库 `2.27.0`、支付宝运行环境 `2.9.0`。
- 导航和前后台生命周期为必要能力；登录码、拨号按功能单独探测。
- 版本过低、必要能力缺失、权限拒绝或能力探测异常时，不调用对应桥接接口。
- 桥接成功、取消、拒绝、超时、参数异常和失败只返回白名单字段及中文状态，不透传平台原始对象。
- 最低版本是本项目试点基线，不代表平台官方最新版本；正式发布前由现场依据目标客户端覆盖率复核。

### 网络与接口

- 生产仅允许 HTTPS；本地预览仅允许 `localhost`、`127.0.0.1` 或 `::1` 的 HTTP。
- 默认只允许同源请求；额外来源必须由现场显式配置，不能通过页面参数扩大。
- URL 禁止用户名、密码、片段以及登录码、令牌、居民或账号标识查询参数。
- 写操作必须携带十二至二百四十字符的稳定幂等键。
- 所有请求继承父级取消信号，并受统一超时控制。
- 居民集合响应最多一百条；跨居民行逐行失败关闭并直接丢弃，不进入页面状态。畸形行、敏感返回字段或超量响应仍导致整个响应拒绝。

### 签名深链

- 无参数的首页、消息页和“我的”可作为站内公共入口；业务页面或任何业务参数必须带签名安全信封。
- 安全信封包含签发时间、过期时间、随机标识、居民标识和签名；最长有效五分钟。
- 验签函数由现场注入，必须使用服务端管理私钥、客户端配置公钥的非对称签名方案。
- 参数最多九个，总长度最多一千二百字符；键名、值长度和重复键均受限制。
- 外部网址、脚本协议、双斜线、反斜线和编码路径穿越拒绝。
- 验签通过后仍须执行页面、参数和居民范围白名单；随机标识在当前会话内只能消费一次。

### 本地缓存

- 居民缓存仅允许“通知同意”和“服务导航”两类非医疗正文信息，最长有效三十分钟。
- 每条缓存必须同时绑定账号和居民；任一绑定不匹配、过期、版本异常或内容敏感时删除并返回空。
- 病历、诊断、处方、结果、正文、令牌、登录码、对象键、下载地址和审计哈希禁止写入。
- 退出、家庭成员切换、进入后台和主体失败关闭时清理全部居民缓存。
- 大字和高对比偏好仍是非居民数据，只保存布尔值。

### 通知

- 未取得明确订阅同意时不接收通知。
- 通知必须同时绑定账号和居民，并包含稳定标识、创建时间和过期时间。
- 撤回、撤权、过期、未来创建、错居民或重复通知全部抑制。
- 锁屏固定显示“新的健康服务消息”，不显示疾病、检查、病历、处方或机构详情。
- 应用内正文仍执行中文最小化映射，点击后重新执行安全深链和居民范围校验。

## 性能、韧性与真机适配

- 恢复请求使用单航班保护，重复重试不会并发加载居民数据。
- 后台、断网和主体变化会取消在途请求；回前台或网络恢复重新核验。
- 消息单批和页面展示继续执行一百条总上限、十条默认分页及稳定标识去重。
- 消息已读按钮在等待回执时禁用；重复点击只允许一个幂等写请求。
- 页面支持 320、375、390 和 430 像素宽度；最小交互目标四十四像素。
- 顶部、底部和左右使用安全区变量；软键盘出现时隐藏固定底栏并恢复内容底部空间。
- 大字、高对比、屏幕阅读器播报和减少动态效果继续保留。

## T00 与现场外部依赖

- T00 将新增运行时策略文件加入公共静态路由、内容安全策略、离线资源版本和发布清单。
- 服务端实现微信、支付宝登录码交换端点，执行一次性消费、五分钟内过期、平台和主体绑定，并保证日志脱敏。
- 服务端或统一链接服务生成非对称签名深链；现场注入验签公钥和验签函数，配置密钥轮换与吊销。
- 微信和支付宝后台配置正式应用标识、服务器域名、业务域名、隐私协议、订阅消息模板和最低客户端提示。
- 服务端按账号与居民过滤消息和业务响应，落实幂等表、通知撤回、授权撤销和居民主体变更通知。
- 现场在微信与支付宝真机覆盖最低版本、主流版本、拒绝授权、弱网、后台恢复、锁屏通知、安全区、软键盘、系统字体两倍和减少动态效果。

## 残余风险

- 当前仓库没有正式微信或支付宝应用标识，无法在本地证明平台登录码真实消费和客户端版本分布。
- 当前没有生产验签公钥和签名服务，自动测试使用注入式验签器验证契约，而不验证现场密钥管理。
- 浏览器无法完整模拟刘海屏、系统锁屏通知、系统权限弹窗和不同厂商软键盘，必须真机验收。
- 公共服务端尚未声明 T04-MP 专属响应字段契约；上线前需由 T00 和接口方完成联合契约测试。
