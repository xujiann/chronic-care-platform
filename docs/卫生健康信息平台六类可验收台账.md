# 卫生健康信息平台六类可验收台账

平台把项目建设文件和卫生健康信息化标准要求统一收敛为六张运行台账：项目文件、政策法规与标准、数据标准与主数据、接口与交换服务、安全合规与授权审计、验收上线与运维。

每张台账必须同时记录责任方、标准依据、来源集合、验收口径、自动检查、证据引用、功能状态、正式上线状态和现场阻断项。`implemented` 仅表示平台结构和功能可测试，不等同于正式生产上线；真实接口样例、测评报告、现场演练和多方签字未完成时，`formalGoLiveState` 必须保持 `blocked-until-onsite-evidence`。

运行入口：

- 汇总 API：`GET /api/platform/standards-ledgers`，支持 `?format=markdown` 导出。
- 明细 API：`GET /api/platform/standards-ledgers/:id`，支持 `q`、`status`、`collection` 筛选和 `format=markdown` 导出；未知台账返回 `404`。
- 页面：`platform.html` 的“六类可验收台账”面板可切换台账、筛选治理摘要、审查四项验收口径和现场阻断边界。
- 报告：`npm.cmd run platform:standards-ledgers` 生成 `release/platform-standards-ledgers.json` 和 `release/platform-standards-ledgers.md`。
- 门禁：`npm.cmd run check`、`npm.cmd test`、`npm.cmd run deploy:check`、`npm.cmd run release:report`。

六类台账不是六份孤立表格。它们复用 `digitalHospitalPolicyRegister`、`standardDataDictionaries`、`dataGovernanceAssets`、`dataLineageControls`、`integrationContracts`、`platformInterfaces`、`securityAcceptanceLedger`、`siteLaunchEvidence`、release manifest 和 readiness 报告，形成从标准要求到平台控制、自动检查、证据和正式上线阻断的追溯链。

明细接口只输出规范化治理字段：来源集合、事项、责任方、状态和证据摘要。它不输出原始业务记录或患者可识别数据。筛选后的导出继续保留 `functionalState` 与 `formalGoLiveState`，因此不会把平台功能可验收误报为生产正式上线。
