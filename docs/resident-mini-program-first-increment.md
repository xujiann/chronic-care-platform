# T04-MP 居民端小程序首个可运行增量

## 交付范围

本增量提供微信小程序、支付宝小程序和移动网页共用的居民端壳层。入口为 `resident-mini-program.html`，首屏包含当前居民、健康概览、八项服务导航、消息待办和“我的”设置。

已覆盖：

- 平台适配：识别微信、支付宝和移动网页运行环境；仅在设备侧保存大字、高对比两项偏好。
- 安全会话：必须同时通过本地会话结构检查和 `/api/auth/me` 服务端主体核验；本地角色字符串、过期会话、主体不匹配和接口失败均阻断。
- 居民范围：复用 `citizen-records-v1/v2` 与 `citizen-records-policy` 的关系核验、有效授权和最小化投影；本人之外必须同时具备有效关系证据和健康档案范围授权。
- 家庭切换：只允许切换当前会话可访问成员；切换前中止在途请求，并重建筛选、详情、草稿、消息选择和临时操作状态。
- 服务导航：健康档案、电子病历、挂号、护理、陪诊、家庭医生、急救和健康待办均有中文移动端入口。
- 消息闭环：只展示面向居民且属于当前居民的消息；英文内部状态和已知英文业务文案映射为中文；已读仅在 `/api/messages/:id/receipt` 返回匹配回执后更新。
- 适老化与无障碍：390×844 单列布局、主要触控目标不小于 44 像素、跳转主内容、语义标题、实时播报、大字、高对比和减少动态效果支持。

## 安全边界

本模块不在浏览器永久保存居民标识、健康资料、消息、令牌副本或表单草稿；内存中仅保留当前服务端会话允许居民的最小投影。

本模块不生成下载地址、对象键、访问令牌、审计哈希或居民数据导出。挂号、护理、陪诊、家医、急救、授权和消息操作均不得由前端自行显示成功，必须等待服务端正式回执。本增量仅实现消息已读写入，其余办理入口保持只读导航或明确说明生产边界。

## 验收方法

1. 启动现有本地服务后，以居民账号安全登录。
2. 访问 `http://127.0.0.1:5173/resident-mini-program.html`。
3. 在 390×844 视口检查首页无横向滚动、按钮高度、家庭成员不可越权切换、大字与高对比。
4. 打开消息页，确认居民可见文本为中文；标记已读后确认服务端回执返回前按钮保持等待状态，失败时仍显示未读。
5. 执行专项单元、静态、就绪门禁和端到端测试。

## 软件就绪判断

首个可运行增量具备 T00 集成条件，但不等同于生产上线。生产上线需要 T00 与现场团队完成以下外部依赖：

- T00 将新入口纳入公共 `server.js` 路由清单、导航、`service-worker.js` 离线缓存、`package.json` 脚本、README 和发布总表。
- 配置微信和支付宝正式应用标识、服务器域名白名单、隐私协议、订阅消息模板与平台登录凭证交换。
- 接入居民实名核验、公安或权威家庭关系证据、授权有效期、撤权强制拦截和审计留痕。
- 接入真实短信、支付、医保、医院号源、护理、陪诊、家庭医生和急救协同服务端回执，并完成现场失败补偿演练。
