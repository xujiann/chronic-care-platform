# 数据治理底座

本切片把平台现有的接口映射、数据质量、居民主索引、诊疗报告、健康统计采集和互联网护理/随访记录串成一个可验收的数据治理入口。目标不是宣称外部系统已经生产接通，而是把已实现能力、待现场联调项和发布证据放到同一条链路中。

## 运行入口

- 页面：`platform.html` 的“数据治理底座”面板展示数据资产、标准字典/主数据、质量与血缘摘要。
- API：`GET /api/data-governance` 面向卫健委管理端返回资产台账、标准字典、血缘控制、质量问题和 onsite/external blocked 清单。
- 门禁：`npm run data-governance:readiness` 生成 `release/data-governance-readiness-report.json` 与 `release/data-governance-readiness-report.md`。
- 发布归档：`release:report` 和 `release:manifest` 会同步归档数据治理 readiness 产物。

## 本线程开发计划

已将《浪潮方案4.1立即采纳开发任务分派表.md》中的“数据治理底座”任务列入本线程执行计划。当前顺序为：先收口 API 探测、静态检查、测试、readiness、deploy check、release report 和发布验证；随后继续扩展主数据目录、标准字典、血缘和接口阻断项证据到平台总线，供后续指标中心和智慧医院管理线复用。

## 数据资产台账

当前台账覆盖 HIS、EMR、LIS、PACS、医保核心、公卫/统计、随访/互联网护理等来源系统，记录责任人、接入状态、数据域、更新频率、质量评分、平台落点和阻塞项。医保核心、院内真实接口地址、生产签名样例、影像云凭证等未完成现场联调的内容必须保留为 external/onsite blocked。

## 标准字典与主数据

标准字典入口覆盖：

- `personIndex`：居民主索引、证件号、手机号、账号绑定。
- 机构/科室/人员：机构编码、机构 ID、医生/护士 ID、机构类型。
- 疾病/手术/药品/耗材：诊断、手术、药品、耗材与医保目录映射。
- 检查/检验/影像：报告号、项目编码、互认标识、影像云 study。
- 统计指标：健康统计采集与运营指标口径。

## 质量与血缘

readiness 报告复用 `interface:mapping` 和 `data-quality:report`，要求每条血缘控制同时具备字段映射、必填项覆盖、幂等键、签名校验和平台集合落点。真实外部系统未接通时，血缘可以作为联调准备证据，但不得作为生产接入完成证据。

## 平台总线

`platformDataBusChannels` 将治理底座沉淀为四类复用出口：主数据目录、标准字典、血缘质量、外部接口阻断项。每条总线通道都记录生产集合、消费模块、责任人、证据引用和阻塞来源，避免后续指标中心、智慧医院、公卫闭环重复定义口径。
