# 生产安全发布执行包

## 目的与边界

本执行包把生产部署、安全测评、国密、审计留存、监控告警、灾备、现场验收和四方 Go/No-Go 收敛为五份最小化证据。它提供环境矩阵、责任门禁、证据字段和只读校验入口，但不保存密钥值、患者数据或正式报告正文，也不替代测评机构、医院、变更委员会和政府主管部门的正式结论。

模板位于 `docs/evidence-templates/production-security-release/`。模板只能作为字段说明；实际证据应复制到仓库外的受控目录，附件只登记受控引用和 SHA-256，不得把真实密钥、证书私钥、令牌或患者数据放入 JSON。

## 实施顺序

1. 冻结生产拓扑、域名、证书、变更单、割接窗口、回滚责任人、发布编号和制品摘要。
2. 由 Vault、KMS 或编排平台注入生产密钥；证据仅记录提供方和交接回执，不记录密钥值。
3. 完成等保、密评、渗透测试、漏洞整改和独立复测，填写安全证据。
4. 配置审计外送与 SIEM/WORM 留存，验证导出、查询、访问权限和防篡改。
5. 接通生产监控，完成告警投递、重复/乱序、失败重试、值班升级、恢复关闭和首日观察演练。
6. 完成数据库原生备份、异地副本、隔离恢复、故障切换、应用/数据回滚及回切，记录 RPO/RTO 实测值。
7. 按 P0-01 至 P0-10 收集现场回执和四方签字；任何附件变化都必须更新摘要并重新复核。
8. 执行生产 profile 发布检查、10/10 切换清单和至少两个非本机 HTTPS smoke 检查。
9. 生成当前四份前置证据的指纹，四个不同账号分别批准，独立决策人签发 GO。
10. 割接后观察；触发阈值时由回滚责任人按批准方案回滚并归档结果。

## 证据填写规则

- `artifactDigest` 和附件 `digest` 使用 `sha256:<64-hex>`。
- 附件引用使用 `controlled://`、`evidence://` 或 `archive://`，不得填本机绝对路径或公开 URL。
- `ownerDepartment` 与 `independentVerifier` 不得相同。
- `containsPatientData` 和 `containsSecretValues` 必须为 `false`；校验器还会扫描明显的口令、令牌和私钥材料。
- 所有账号字段记录可审计账号，不记录显示名；同一门禁需要独立签字时账号必须唯一。
- 模板中的尖括号、`pending` 和负数是故意设置的阻断值，填写完成前不得删除 NO-GO 结论。
- `go-no-go.json` 的 `evidenceFingerprint` 必须由当前四份前置证据计算；任何前置证据变化都会使旧 GO 失效。

## 只读校验

校验仓库外受控目录，默认只向标准输出返回报告，不写文件：

```powershell
node scripts/production-release-evidence-readiness.js --evidence-dir="D:\controlled-evidence\release-2026-001"
```

需要显式生成脱敏报告时才指定输出：

```powershell
node scripts/production-release-evidence-readiness.js `
  --evidence-dir="D:\controlled-evidence\release-2026-001" `
  --output="release/production-release-evidence-readiness.json" `
  --markdown="release/production-release-evidence-readiness.md"
```

校验通过必须同时满足：五份证据存在且可解析、公共字段完整、附件引用和摘要有效、无占位符和敏感材料、专项门禁全部通过、四方签字账号唯一、GO 使用当前证据指纹且决策人独立。

## 失败处置与回滚

- 任一检查失败即输出 `no-go-evidence-incomplete`，不得通过手工修改汇总结果绕过。
- 证据内容或附件摘要变化后重新计算证据指纹，撤销旧审批并重新签署。
- 严重/高危安全问题、真实告警不可达、RPO/RTO 超标、现场验收不完整或签字重复均为硬阻断。
- 已割接后出现回滚条件时，先冻结写入和流量，再按已批准的上一制品、数据恢复点和健康检查执行；实际操作记录作为新的受控附件归档。

## 验收标准

首个增量验收标准如下：

1. 空目录和未填写模板稳定输出 NO-GO。
2. 完整合成证据通过全部结构校验，但报告保留“不代表正式批准”的边界声明。
3. 重复签字、证据漂移、患者数据声明、嵌入口令/令牌/私钥、无效附件摘要均被阻断。
4. 校验器默认不写仓库；只有显式指定输出参数才生成报告。
5. 实现不修改 `server.js`、`portal.css`、`package.json`、`README.md` 或发布总表。
