# 按病种付费系统实施说明

## 政策基线

本模块依据国家医保局《医疗保障按病种付费管理暂行办法》（医保发〔2025〕18号）建设，覆盖总额预算、DRG/DIP分组、权重/分值与费率/点值、特例单议、月度结算、年度清算、智能监管、监测评估、意见反馈和数据安全。

政策原文：https://www.nhsa.gov.cn/art/2025/8/15/art_104_17573.html

补充政策基线：国家医保局《按病组（DRG）和病种分值（DIP）付费2.0版分组方案政策解读》（2024年7月23日）：https://www.nhsa.gov.cn/art/2024/7/23/art_105_13316.html

## 已实现闭环

1. 医保结算清单必填项、金额和住院日期质控。
2. DRG与DIP双模式联调目录、方案版本和支付参数版本。
3. 可解释分组、支付标准、费用差额和预计结余测算。
4. 未入组、高倍率、低倍率、分解住院和高编高套线索识别。
5. 特例单议申报、智能/专家评审、通过与不予通过状态。
6. 月度结算、年度清算批次、对账与拨付状态。
7. 总额预算、机构费用、支付标准与风险线索监测。
8. 医疗机构意见反馈、操作审计和生产外部依赖台账。
9. DRG/DIP 2.0版切换日期、30个工作日结算和次年6月底清算期限控制。
10. DRG 5%、DIP 5‰特例单议申报比例控制。
11. 约1个月预付金审批、信用及药耗追溯码倾斜依据。
12. 历史应付未付费用清理、谈判协商、医保数据工作组和分级培训。
13. 禁止将病组/病种支付标准作为医务人员限额考核或绩效分配指标。
14. 固化DIP 2.0版9520组目录元数据：保守治疗3209组、手术操作6311组，其中仅主要操作5211组、主要操作加相关操作1100组。
15. 实现“主要诊断+主要手术操作+相关手术操作”成组轨迹，相关操作费用达到病例原费用10%以上时纳入独立组合。
16. 标记肿瘤基因治疗、分子治疗、免疫治疗和放射治疗等2.0版补充范围。
17. 建立结算清单格式、编码、业务、费用、时序、关联、完整性七类质控。
18. 使用机构编码、结算清单号和出院日期生成幂等键，并将费用明细唯一关联至清单。
19. 批量导入支持接收、拒绝、重复识别、错误队列和补正重试。
20. 模拟分组结果明确标记为不具结算效力；正式分组必须提供有效官方回执、方案版本和签名验证结果。
21. 分组运行与支付测算结果写入带前序哈希的不可变账本，支持篡改检测。
22. 固化DRG 2.0版公开结构元数据：26个MDC、409个ADRG、634个DRG，其中外科手术组251个、非手术室操作组57个、内科诊疗组326个。
23. 本地模拟分组输出MDC、ADRG、DRG三级轨迹，并按MCC、CC、无并发症细分；既有持久化目录通过版本化合并自动补齐新字段。
24. 对本地预览排除的主要诊断和不作为ADRG条件的操作给出可解释原因；正式排除清单仍以医保正式分组器及其版本为准。
25. 增加DRG入组率、CMI、总权重、MDC/ADRG/DRG覆盖数、MCC/CC病例数和高低倍率病例分析。
26. 增加DRG目录查询、单病例试分组和运行分析API，并在工作台显示三级目录、绩效指标和非结算效力提示。
27. 正式分组回执必须绑定当前病例输入摘要、允许的方案版本、签发时间和适配器验签证明；同一回执编号不得重复用于正式入组。
28. 支付参数按草案、影响试算、提交、双人复核、批准、发布流转；同一人员不得重复签署。
29. 参数试算输出病例明细、机构汇总、当前/候选支付总额、差额、变化率和输入摘要，供谈判协商及发布决策使用。
30. 新参数发布后，同模式旧参数自动冻结并记录替代版本、冻结人和冻结时间。

## DRG专项接口

- `GET /api/disease-payment/drg/catalog`：返回DRG 2.0版结构档案、本地版本、参数和MDC/ADRG/DRG预览目录。
- `POST /api/disease-payment/drg/simulate`：按已有病例ID或临时病例执行不具结算效力的可解释试分组。
- `GET /api/disease-payment/drg/analytics`：返回入组率、CMI、权重、倍率病例和病组分布。
- `GET /api/disease-payment/parameters`：返回参数版本、当前生效参数、影响报告和审批流程。
- `POST /api/disease-payment/parameters`：创建绑定分组方案的参数草案。
- `POST /api/disease-payment/parameters/:id/simulate`：生成病例和机构影响试算报告。
- `POST /api/disease-payment/parameters/:id/submit`：提交参数复核。
- `POST /api/disease-payment/parameters/:id/review`：由不同复核人签署通过或驳回意见。
- `POST /api/disease-payment/parameters/:id/publish`：双人批准后发布新参数并冻结旧版。

## 生产边界

本地分组目录是可解释的联调实现，不得作为正式基金结算依据。正式上线必须完成：

- 国家或地方医保认可的分组器联调及版本验签；
- 医保核心结算、即时结算、清算和拨付接口联调；
- HIS、EMR、住院病案首页、医保结算清单和费用明细的全量质控；
- 当地DRG细分组或DIP病种库、权重/分值、费率/点值及调整系数审批发布；
- 数据安全、权限、审计、备份恢复和现场验收。
