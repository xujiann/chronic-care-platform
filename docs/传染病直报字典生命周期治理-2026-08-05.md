# 传染病直报字典生命周期治理

## 目标

在直报 Worker 已具备官方字典硬门禁的基础上，增加“当前版本—候选版本—独立复核—到时激活—受控回滚”的治理闭环。任何仓库内状态都不能替代现场字典文件、联合测试证据或平台 Go/No-Go。

## 状态模型

- `active`：唯一允许绑定新投递的字典版本；
- `candidate`：待复核、已批准或已拒绝的下一版本，不能参与投递；
- `previousActive`：最近一次被替换的版本摘要，只用于受控回滚；
- `rollbackRequest`：回滚申请及独立复核状态；
- `events`：SHA-256 前序链审计事件；
- `commands`：幂等命令摘要与结果收据。

同一投递只能绑定一个确定的字典摘要和映射指纹，不存在客户端选择版本或两个版本同时自动生效。

## 正向升级

1. 字典责任人提交新版本、受控材料引用和材料摘要；
2. 系统比较字段映射与五类码表版本，仅输出差异字段和码表标识，不输出具体码值；
3. 与提交人不同的复核人批准或拒绝；
4. 到达 `effectiveAt` 后，由平台运行岗提交激活证据；
5. 当前版本转入 `previousActive`，候选版本成为唯一 `active`。

## 回滚

回滚必须经过“申请—独立复核—执行”三步。申请人与复核人不得相同；执行时必须再次提供受控证据引用和 SHA-256 摘要。回滚后被替换的新版本成为新的 `previousActive`，便于后续调查，但不会自动重新激活。

## 安全边界

- 状态只保存字典摘要、映射指纹、码表版本/摘要和受控引用；
- 不保存码值、公钥、签名、凭据、原始报文或居民信息；
- 所有写命令要求 `expectedVersion` 和幂等键；
- 审计链篡改、活动字典漂移、自审、提前激活和未审批回滚均失败关闭；
- 字典到期后 `dictionaryLifecycleReady=false`，但任何就绪状态仍保持 `productionReady=false`。

## 验证

执行：

```powershell
npm run public-health:direct-report-dictionary-lifecycle:test
```

测试覆盖候选差异、四眼复核、到时激活、幂等冲突、版本冲突、拒绝后替换、独立回滚、审计链篡改和到期门禁。
