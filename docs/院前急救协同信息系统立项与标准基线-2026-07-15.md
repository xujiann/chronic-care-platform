# 院前急救协同信息系统立项与标准基线

> 版本：0.1（2026-07-15）
> 定位：面向居民、120急救中心、救护车与接诊医院的院前—院内一体化协同系统立项输入。

## 一、立项结论

建议建设“一中心、三端、一平台”：以现有120急救中心统一受理和调度为业务主中心，建设居民辅助呼救端、急救中心调度端、救护车移动急救端和医院急诊协同端，通过市级院前急救协同平台实现事件、患者、车辆、生命体征、救治记录和接诊资源的实时同步。

居民端不能替代或另设急救特服号码。全国统一院前医疗急救呼叫号码为120，正式出车必须进入急救中心统一指挥调度。App/小程序应定位为一键拨打120、位置和健康资料授权补充、无声/文字辅助呼救、视频连接、急救指导及进度告知入口；必须保留电话、人工坐席和断网降级通道。

## 二、政策与标准基线

### 2.1 必须遵循的业务政策

| 文件 | 对系统的约束 |
| --- | --- |
| 《院前医疗急救管理办法》（国家卫生计生委令第3号） | 120为统一呼叫号码；急救中心设置呼叫受理和指挥中心；通信系统应具备定位追踪、号码和位置显示、计算机辅助指挥、移动数据传输、无线语音等能力。 |
| 《关于进一步完善院前医疗急救服务的指导意见》（国卫医发〔2020〕19号） | 建设政府主导、覆盖城乡、运行高效的省、市、县三级体系，强化急救网络、调度和院前院内衔接。 |
| 《全国医院信息化建设标准与规范（试行）》（国卫办规划发〔2018〕4号） | 医院侧应通过医院信息平台承接院前急救数据，与急诊、电子病历、检验检查、影像和危急重症救治流程衔接。 |
| 《医院信息平台应用功能指引》《医院信息化建设应用技术指引》 | 二级以上医院应具备院前急救知识支持、移动监护与音视频采集、急救信息共享协作、车辆定位和路径引导等能力。 |
| 《医疗卫生机构网络安全管理办法》（国卫规划发〔2022〕29号） | 落实网络安全责任制、等级保护、风险监测、事件处置以及重要数据和个人信息安全措施。 |

### 2.2 建设时直接引用的标准

| 标准 | 用途 | 项目落点 |
| --- | --- | --- |
| WS/T 451—2014《院前医疗急救指挥信息系统基本功能规范》 | 规定总体、呼叫受理、调度指挥、通信、GIS、资源和接口等基本功能 | 产品需求和验收清单的主基线 |
| WS 542—2017《院前医疗急救基本数据集》 | 5个子集、144个数据元，覆盖受理、调度、突发事件、质控、患者院前记录 | 事件模型、数据库字典和交换报文的主基线 |
| WS/T 621—2018《院前急救机构与医院急诊科患者病情交接单》 | 规范患者、任务、诊疗、交接时间及三方交接内容 | 电子交接单及院内接诊确认 |
| WS/T 815—2023《严重创伤院前与院内信息链接标准》 | 要求严重创伤信息及时、准确、完整，并支持电子录入和无线实时链接 | 创伤绿色通道、生命体征与救治措施实时推送 |
| WS/T 790.1—2021及其分册《区域卫生信息平台交互标准》 | 规定居民、机构、人员注册，健康档案存储/调阅、通知和审计等平台交互 | 对接市级全民健康信息平台，复用主索引和审计服务 |
| WS 363、WS 364、WS 445、WS/T 500 | 数据元、值域、电子病历数据集和共享文档 | 统一疾病、症状、处置、机构、人员及文档语义 |
| GB/T 22239—2019 | 网络安全等级保护基本要求 | 按三级系统目标开展定级论证、建设和测评 |
| GB/T 45574—2025 | 敏感个人信息处理安全要求 | 约束医疗健康、精准位置、音视频等敏感信息处理 |

说明：2026年3月公开征求意见的《院前医疗急救质量控制与评价标准》尚不应作为已生效标准引用，但其指标应纳入预研和指标映射，待正式发布后升级。

## 三、目标业务闭环

1. 居民拨打120；若从App/小程序发起，同时提交经授权的手机定位、联系人、基础健康摘要和现场文字/图片。
2. 120坐席来电弹屏，核实地址、主诉、人数和现场风险；调度员创建事件并派出车辆。
3. 救护车接令导航，车组回传出车、到达、接触患者、离开现场、到院等时间节点。
4. 急救人员建立临时或实名患者身份，记录主诉、初步诊断、生命体征、评分、用药和处置；监护设备数据可自动采集。
5. 调度中心结合病情、距离、医院能力、床位/导管室/卒中与创伤中心状态确定接诊医院，医院确认接收。
6. 医院在患者到达前获取病情摘要、连续生命体征、心电图、影像/照片、预计到达时间和已实施处置，提前启动绿色通道。
7. 到院后完成电子交接、身份归并和院前记录入院内电子病历；院内回传接诊结果和关键结局用于闭环质控。

## 四、产品范围

### 4.1 居民辅助呼救端

- 一键拨打120；禁止把互联网请求伪装为已经受理的120任务。
- 高精度定位、地址校正、楼层/门禁/地标补充及定位置信度展示。
- 文字/无声辅助呼救、听障适配、紧急联系人和多人伤情填报。
- 经明确授权调取姓名、年龄、过敏、既往史、用药、植入物等最小健康摘要。
- 坐席发起的音视频连接和分步骤急救指导；录制状态必须显著提示。
- 展示“已接通、已受理、车辆已派、车辆接近”等有限状态，不公开敏感车辆或人员信息。
- 弱网缓存、短信/电话降级；未登录、未实名也必须可以拨打120。

### 4.2 急救中心调度端

- CTI来电弹屏、录音关联、号码与位置显示、重复事件识别。
- 结构化受理、分级分类、调度生命支持指导、重大事件升级。
- GIS一张图、车辆/站点/人员/设备状态、智能推荐但人工确认派车。
- 跨区增援、110/119/122联动、改派/撤单/并单和全过程留痕。
- 医院能力与资源状态、目的医院推荐、医院确认和绿色通道触发。
- 实时运行监测、质控指标、录音/操作回放及事件证据包。

### 4.3 救护车移动急救端

- 接令、导航、节点打卡、状态自动/手动上报。
- 临时患者建档、居民主索引匹配和到院后身份归并。
- 生命体征、GCS/创伤等评分、心电、用药、耗材、操作和病情变化记录。
- 监护仪、除颤仪、呼吸机等设备接入；保留设备原始值、人工修订值和来源。
- 音视频会诊、医院沟通、电子交接单、医患签名或无法签名原因。
- 断网可工作、恢复后幂等补传；关键指令需回执。

### 4.4 医院急诊协同端

- 任务预告、预计到达时间、患者摘要及连续生命体征趋势。
- 胸痛、卒中、创伤、孕产妇、新生儿、中毒等专病绿色通道。
- 接诊能力和关键资源状态上报；接收、暂缓或建议转送需记录原因。
- 急诊预建档、院前患者与院内患者身份归并、电子交接确认。
- 将院前记录归档至医院信息平台/电子病历，回传接诊时间、分诊级别、主要诊断和关键结局。

## 五、总体技术架构

平台复用现有统一身份、居民主索引、机构/人员主数据、授权审计、消息中心、区域健康档案和医院连接器，不另建孤立用户体系。

核心领域服务包括：急救事件、呼叫受理、调度与任务、车辆资源、患者与身份归并、院前病历、设备数据、医院资源、院前院内协同、音视频、通知、质控分析和审计证据。

事件主链采用不可跳跃的状态机：`呼叫接入 → 坐席受理 → 调度派车 → 车辆出发 → 到达现场 → 接触患者 → 转运 → 医院确认 → 到院交接 → 任务完成/质控关闭`。任何撤销、改派、退回、超时和人工覆盖均作为独立事件记录，不覆盖历史事实。

实时同步采用“业务API + 可靠事件总线 + 设备时序通道”：控制指令强制确认与重试；生命体征按时间序列传输；文档与影像走对象存储和受控链接；医院不可用时排队补偿并电话兜底。所有接口必须支持全局事件号、任务号、患者临时号/主索引号、机构号、车辆号、时间戳、版本号和幂等键。

## 六、首期数据与接口清单

### 6.1 核心对象

- `EmergencyEvent`：呼叫来源、受理时间、位置、事件类型、人数、分级和状态。
- `DispatchMission`：调度指令、车辆/车组、各节点时间、改派和回执。
- `EmergencyPatient`：临时身份、主索引映射、基本信息和授权来源。
- `PrehospitalRecord`：主诉、病史、检查、生命体征、初步诊断、评分、措施和反应。
- `ReceivingFacility`：医院、科室、专病中心、能力/资源状态和接收意见。
- `HandoverRecord`：到院时间、交接双方、交接内容、签名、院内就诊号和归档状态。
- `AuditEvidence`：操作者、终端、时间、目的、数据范围、授权/紧急例外和前后值。

### 6.2 必接接口

1. 120呼叫中心/CTI：来电、录音、坐席、受理单和回拨。
2. GIS与运营商定位：位置、置信度、地图匹配、车辆轨迹和路径。
3. 车载终端与医疗设备：任务、状态、生命体征、波形/心电及设备标识。
4. 区域全民健康信息平台：居民、机构、人员注册，健康摘要调阅、文档归档和审计。
5. 医院信息平台：急诊预建档、电子病历、检验、影像、专病中心、接诊和结局回传。
6. 统一身份与电子签名：医务人员强认证、居民授权、交接签名和时间戳。
7. 110/119/122及应急指挥：联动事件、资源请求、状态和处置结果。

## 七、安全与合规控制

- 医疗健康、精准位置、轨迹、音视频和未成年人信息均按敏感个人信息管理，遵循目的限定、最小必要、分级授权和可撤回授权。
- 抢救生命等紧急情形可设置“紧急访问”，但必须记录理由、范围、人员、时间并事后复核，不得成为常规绕权入口。
- 急救中心、车载端、医院端采用机构和岗位双重授权；调度员、急救医生、护士、医院接诊人员、质控人员权限隔离。
- 全链路加密、终端证书、API双向认证、关键数据字段加密、密钥集中管理；生产与测试数据隔离。
- 录音、视频、轨迹、病历、指令和签名分别制定依法合规的保存期限，禁止在需求阶段随意写死统一期限。
- 按等保三级目标先行设计，并在立项阶段完成定级论证、数据分类分级、个人信息保护影响评估和商用密码应用论证。

## 八、建议分期

### 第0期：四周，现状盘点与标准冻结

- 盘点现有120 CTI/调度、车辆终端、急救站、网络医院、区域平台和医院接口。
- 完成WS 542数据字典、WS/T 621电子交接单、事件状态机和接口责任矩阵。
- 选定1家急救中心、2至3家医院、5至10辆救护车作为试点。
- 完成定级、数据分类分级、个人信息影响评估和容灾指标论证。

### 第1期：8至12周，最小可运行闭环

- 上线120受理/调度、车载移动端、医院预告端和电子交接。
- 实现事件状态、车辆轨迹、核心生命体征、处置记录和预计到达时间实时同步。
- 完成电话、短信和纸质交接降级方案及全链路演练。
- 居民端首期只做拨打120、定位/资料授权补充和状态通知，不把互联网请求直接当作派车指令。

### 第2期：8至12周，专病与设备接入

- 接入监护仪、除颤仪、心电和音视频。
- 打通胸痛、卒中、创伤等绿色通道及医院能力/资源状态。
- 接入区域健康档案和医院电子病历，完成身份归并和结局回传。

### 第3期：持续优化

- 跨区域协同、重大事件批量伤员、110/119/122联动。
- 基于规则和可解释模型的调度辅助、资源预测和质控预警；所有推荐保留人工决策权。
- 按正式发布的国家质控标准更新指标体系。

## 九、首期验收指标建议

- 受理、派车、出车、到场、离场、到院和交接关键时间节点完整率不低于99%。
- 调度指令、改派、撤销和医院接收回执可追溯率100%。
- 试点医院院前信息成功预告率不低于95%，断网恢复后补传成功率不低于99.9%。
- 院前患者与院内就诊身份归并准确率不低于99%，错误归并必须可撤销并全程留痕。
- 核心链路具备双活或明确的灾备策略，完成断网、CTI故障、医院接口故障、消息积压和数据泄露应急演练。
- 对每例任务可生成包含呼叫、调度、轨迹、病历、医院接收、交接和审计记录的完整证据包。

## 十、立项前必须确认的问题

1. 建设主体和业务责任主体是市急救中心、卫健委信息中心还是区域平台运营方。
2. 现有120调度厂商、CTI协议、数据归属及能否提供实时双向接口。
3. 大连市现有急救站点、车辆、车载终端、网络医院及专病中心覆盖情况。
4. 区域全民健康信息平台可提供的居民主索引、健康摘要、机构人员注册和审计能力。
5. 医院侧采用统一前置机还是逐院对接，是否已有急诊预建档和绿色通道接口。
6. 运营商定位、短信、音视频、电子签名和地图服务的采购与合规边界。
7. 录音录像、轨迹、病历和调度记录的本地法定或主管部门规定保存期限。
