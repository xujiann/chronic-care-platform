# 传染病直报纯合成联合测试执行器

## 交付结论

本迭代在 T08 外部集成边界内提供离线联合测试执行器。它按照当前
`public-health-direct-report-v1` 控制契约运行 8 个固定场景，生成可复算摘要、
受控证据引用以及待独立签署的 evidence subject。

该执行器只验证平台自身的契约行为，不连接疾控端点，不读取凭据，不使用患者
数据，不生成或伪造正式签名。8 个场景全部通过后，输出仍固定为：

```text
externalCalls=0
credentialsUsed=false
syntheticDataOnly=true
officialSignaturesGenerated=false
activationReady=false
productionReady=false
```

## 执行方式

字典必须是受控的已批准字典文件，并使用绝对路径。直接执行：

```powershell
node scripts/public-health-direct-report-joint-test-runner.js `
  --dictionary=C:\controlled\direct-report-dictionary.json `
  --executed-at=2026-08-05T08:30:00.000Z `
  --package-id=synthetic-site-run-20260805
```

`--executed-at` 和 `--package-id` 可省略；生产留证建议显式提供不可变运行时刻与
运行编号。CLI 只向标准输出写 JSON，不写证据文件。现场归档应由受控发布流程
完成。

执行器只接受以下参数：

- `--dictionary`：字典 JSON 绝对路径；
- `--executed-at`：规范运行时刻；
- `--package-id`：本次合成运行编号。

端点、账号、令牌、客户端、传输器或自定义业务报文都不是允许参数。

## 八个场景

| 场景 | 合成断言 |
| --- | --- |
| `schema-acceptance` | 最小必填报文通过当前字典校验 |
| `invalid-code-rejection` | 未登记疾病码被字典拒绝 |
| `payload-minimization` | 仅保留 9 个当前必填字段，选填字段数为零 |
| `idempotent-replay` | 相同幂等键重放只产生一次副作用并返回同一回执 |
| `timeout-retry` | 首次合成超时、第二次成功，重试上限为三次 |
| `rejection-dead-letter` | 合成外部拒绝产生可恢复的受控死信引用 |
| `signed-callback` | 仅校验 `synthetic-test-proof-v1` 完整性证明，并明确不生成正式签名 |
| `reconciliation` | 合成投递与回执一致，差异数为零 |

请求和响应仅输出 SHA-256 摘要以及字段数、状态码、尝试次数、副作用数和差异数
等最小摘要。原始合成对象只存在于单次进程内存，不进入输出。

## 证据主题与签署边界

输出中的 `evidenceSubject` 已绑定：

1. 当前控制契约编号；
2. 字典 SHA-256 摘要；
3. `mappingFingerprint`；
4. 运行时刻和最长 168 小时有效期；
5. 8 个场景各自的运行编号、请求/响应摘要、trace 引用和 receipt 引用。

`evidenceSubjectDigest` 使用现有控制包的规范算法生成。`pendingSignatures` 仅列出
两个待签角色：

- `disease-control-office`；
- `hospital-information-center`。

执行器不输出 `attestations`。现场必须由两个角色分别使用独立 Ed25519 私钥，
对同一 subject digest 完成签署，再由现有控制包验证。私钥不得进入仓库、CLI
参数、输出文件或信任注册表。

## 后续 T00 集成

本分支不修改 `server.js`、路由、`package.json`、流程所有权清单或部署包。T00
集成时可按需：

1. 将模块、CLI、测试与文档登记为 T08 所有；
2. 把 CLI 纳入领域检查命令；
3. 由受控发布流程归档 JSON 输出并发起独立签署；
4. 将完成双签的证据文件交给现有直报控制包复核。

合成执行成功不是外部联合测试成功，也不是生产切换授权。
