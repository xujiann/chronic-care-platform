# 临床用血共享运行时生产化基线

模块标识为 `clinical-blood`，支持血液中心与用血机构按治理边界独立开发、逻辑选择和受控演练，但不授权独立服务、容器、数据库或部署单元。模块运行在平台既有 Node.js 组合根中，`deploymentMode=shared-platform-node-runtime`、`independentDeploymentAuthorized=false`。它不依赖急救、影像或体检模块；运行依赖限定为统一身份、MPI、HIS、LIS、PDA、冷链 IoT 与审计能力。

## 契约与现场证据

- BIS/BTIS 主数据必须携带机构编码、系统类型、代码、名称、版本及生效时间。
- 血袋唯一标识采用 `献血码-成分码-分装序号`，献血码 13 位，成分码 3–8 位，序号 2 位。
- 现场回执必须包含证据引用、SHA-256 摘要、机构、签署人、签署时间、关联 ID 和幂等键。
- 现场回执采用提交人与复核人分离，幂等键重放时必须保持证据摘要一致。
- BIS/BTIS 至少存在一个共享映射代码，同机构、同系统、同代码不得映射为不同名称。
- 冷链设备必须提供校准证书、有效期、告警测试证据，并由不同人员执行和复核。
- 冷链按成分和环节执行规则：红细胞储存 2-6℃、运输 2-10℃；血小板与粒细胞 20-24℃；冰冻血浆和冷沉淀保持冰冻状态；血小板储存须提供持续振荡证据。
- 配血前必须核对 ABO 正反定型、RhD、本次与既往血型、意外抗体筛查/鉴定和相应抗原阴性血液选择；冲突不得自动放行。
- 配血验收区分单一检测操作人、独立结果复核人和独立报告签发人，避免把“双人核对”错误实现为两人共同操作。
- 验收覆盖配血操作/复核/签发、床旁四码核对和召回确认/隔离/闭环。
- 共享运行时冒烟及逻辑模块禁用恢复验证均为上线硬门禁。

## 上线判定

软件完成状态与正式上线状态分离。代码和自动化测试通过最多表示 `local-rehearsal-ready`。现场回执、BIS/BTIS 契约、冷链证据、三类业务验收、共享运行时冒烟、逻辑禁用恢复演练和平台级上线审批全部签收前，正式状态固定为 `NO-GO`，且 `productionReady=false`。

运行检查：

```powershell
node scripts/blood-clinical-module-readiness.js
node scripts/blood-clinical-smoke.js
```

提供现场证据 JSON 后，可使用 `--evidence=<path>` 重新计算本地证据门禁；该命令不会授予生产上线或独立部署权限，流水线使用 `--require-go` 时，`NO-GO` 将返回退出码 2。
现场填写可从 `docs/clinical-blood-site-evidence-template.json` 开始，模板中的占位值不能作为生产证据。

## 标准数据集

`blood-standard-registry.js` 建立 WS/T 866—2025 的十二类数据子集注册表和首批核心数据元校验。该注册表用于持续补齐标准数据元、接口字段、允许值和现场映射，不以“十二类已建档”替代逐数据元符合性验收。

边界扫描区分硬依赖和可选事件订阅。对急救、影像、体检的代码导入、页面链接、网络调用或必需依赖声明均判定为跨域违规；仅作为事件消费者出现时记为可选集成，不构成临床用血逻辑模块启动前提。该扫描证明模块边界，不证明可独立部署。
