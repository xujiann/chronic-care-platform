# 三条开发线并行交付与集成

## 唯一集成基线

- 集成分支：`main`
- 开发基线：`baseline/governance-20260817-enhancement-v1`
- 集成责任：T00；数据线使用 T02，慢病转诊接口试点使用 T05。
- 三条线只提交各自模块、配置、脚本、测试和文档；中央命令及 CI 由 T00 统一注册。

## 开发线与首批交付

| 开发线 | 首批能力 | 本地完成条件 | 生产边界 |
| --- | --- | --- | --- |
| 数据线 | 三波次迁移、精确对账、回滚演练、四维质量门禁 | 每个迁移运行完成完整状态历史并成为本地候选 | 真实全量演练、签名对账和现场变更批准仍为外部门禁 |
| 接口试点线 | 四类机构适配器、确定性重试、摘要对账、慢病转诊五步闭环 | 至少一个纯合成会话完成闭环且无死信、无对账差异 | 真实机构端点、签名回执和现场验收未接入前始终 NO-GO |
| 产品运行线 | 事项、前端、监控、非功能和地区复制统一驾驶舱 | 五类本地控制均通过且只输出白名单元数据 | 负载、弱网、容灾、安全和第二真实地区证据必须来自现场 |

第二批已把三条线推进到运行时：数据迁移使用后台 worker、事务 outbox 和可恢复
checkpoint；机构接口增加预生产沙箱签名摘要回执和防重放控制；产品驾驶舱通过
`GET /api/platform/productization/operations/cockpit` 接入平台页，并仅向 `commission`
角色返回白名单运行元数据。

## 验收命令

```powershell
npm run development-lines:check
npm run development-lines:test
npm run development-lines:readiness
```

也可分别执行 `data-migration:readiness`、`data-migration:execution-readiness`、
`institution-pilot:readiness`、`institution-sandbox:readiness` 和
`product-operations:readiness`。统一报告只表示仓库内控制面的状态，不得被用作
生产授权或替代真实机构、真实地区的签名证据。

## 下一批集成点

1. T00 为三条线提供只读、脱敏的统一运行投影；禁止返回原始机构报文和迁移业务载荷。
2. 数据线把真实迁移执行器接入 outbox/checkpoint，而不是在请求路径双写。
3. 接口线从纯合成会话升级为预生产机构沙箱联调，证据只登记引用和 SHA-256 摘要。
4. 产品运行线把驾驶舱挂入事项中心，并按地区上下文加载复制目标和非功能预算。
