## 一、模块定位

本模块以“医联体转诊与远程会诊平台”为基础，升级为面向县域医共体的协同闭环能力。业务上覆盖双向转诊、远程会诊、接诊反馈、报告回传、检查检验互认轻量证据、基层随访回填、质控反馈和绩效评价；管理上支持县域端集中查看牵头医院、基层机构、接诊医院、医院 IT、医保/绩效等角色的待办、回执、终签、阻塞项和 G 端可采集指标。

当前实现边界为“演示与现场联调前置证据”。平台已经具备可运行页面、可机检 readiness、发布报告和本地预览证明，但真实 HIS/EMR/LIS/PACS/医保核心回调、现场签字、生产身份源、审计导出和监控值守仍属于上线前现场阻塞项。

## 三、已实现功能

### 1. 六步医共体闭环

县域端已呈现统一状态链：

`发起 -> 受理 -> 执行/会诊 -> 报告回传 -> 反馈/评价 -> 绩效归档`

每一步都显示本地证据、责任角色、回执状态、终签状态、现场签字状态、跳转按钮和阻塞项。页面明确区分“本地已实现证据”和“外部/现场阻塞”，避免把演示能力误写成真实生产接入。

### 2. 角色化责任与待办

已实现以下角色视图：

| 角色 | 已实现功能 |
| --- | --- |
| 牵头医院/转诊中心 | 查看转诊发起、居民授权、接诊反馈闭环、联调回执和现场签字入口。 |
| 基层机构 | 承接双向转诊发起、报告接收、基层随访回填和连续服务证据。 |
| 接诊医院 | 处理接诊反馈、排期、远程会诊执行和报告回传证据。 |
| 医院 IT | 维护 feedback、schedule、report 三类回调联调证据和 HIS/EMR/LIS/PACS 阻塞项。 |
| 县域绩效/医共体办公室 | 处理 SLA 督办、质控反馈、闭环评价、绩效归档和角色待办积压。 |
| 医保/绩效 | 查看支付路径、重复检查控制、互认证据、医保结算和绩效公式现场阻塞项。 |

### 3. 双向转诊与远程会诊

已支持转诊会诊台账、接诊反馈、会诊排期、接诊医生、临床问题、报告状态、报告摘要、绩效字段和 SLA 处置字段。平台复用现有 `referralSystem`、`countyCollaborationOrders`、`careOrders`、`taskMessages`、`workflow-actions` 等能力，没有另起平行流程。

### 4. 报告回传与互认证据

报告回传已进入 `reportStatus`、`reportSummary`、`personalRecords` 和居民/机构消息证据。检查检验/影像互认以 `countyMutualRecognitionRecords` 作为轻量证据入口，展示互认状态、退回复核原因、重复检查控制和医保/绩效关联口径。真实 LIS/PACS 质控规则和影像附件仍需现场接入。

### 5. 基层随访与质控反馈

闭环指标已识别基层随访回填和质控/SLA 反馈关闭情况，支持下转后基层机构继续随访、报告归档和质量反馈闭环的发布证据。当前 readiness 输出中，基层随访回填为 2 条，质控反馈闭环为 1 条。

## 五、上线前准备

### 1. 现场系统联调

上线前需完成以下真实系统对接：

1. HIS/EMR：真实转诊单号、病历摘要、医嘱、接诊反馈和报告摘要回写。
2. 预约号源/床位/视频会诊：真实号源、床位、视频会议室、专家排班和失败重试规则。
3. LIS/PACS/影像/心电：真实报告编号、附件地址、影像调阅、互认质控规则和危急值链路。
4. 医保核心：转诊支付路径、重复检查控制、统筹区结算规则、医共体绩效结算公式。
5. 居民身份与授权：统一身份源、居民主索引、医生身份源、机构目录和跨机构授权策略。

### 2. 现场签字与验收

需补齐以下签字材料：

1. 转诊中心/牵头医院联调签字。
2. 接诊医院接诊反馈、排期和报告回传签字。
3. 医院 IT 接口回放、签名密钥和审计留痕签字。
4. 医保/绩效支付规则、重复检查控制和结算公式签字。
5. 县域医共体办公室 SLA 督办、质控反馈和绩效归档签字。

### 3. 生产安全与运维

上线前仍需完成：

1. 生产 `NODE_ENV`、`STORAGE_ENGINE`、会话密钥、接口网关 HMAC 密钥配置。
2. 审计保全目标配置，如 `AUDIT_EXPORT_PATH` 或 SIEM 对接。
3. 生产数据库适配、备份恢复、RTO/RPO 验收和灾备演练。
4. 接口监控、SLA 超时监控、死信补偿、重试队列和告警值守。
5. 等保、密评、信创适配和上线切换签字材料。

## 六、下一步规划

### P0：小范围真实机构联调

1. 选择 1 家基层机构和 1 家接诊医院完成真实转诊会诊闭环试点。
2. 以 `feedback-callback`、`schedule-callback`、`report-callback` 为主线完成三类回调报文联调。
3. 将现场回放结果沉淀为接口字段表、样例报文、失败重试记录和签字截图。
4. 将 5 项角色待办逐项关闭，形成上线前签收包。

### P1：业务深水区增强

1. 深化检查检验/影像互认：补充互认规则、质控复核、不互认原因、医保调阅和重复检查控制。
2. 强化基层随访：报告回传后自动生成家庭医生随访、居民提醒、复诊建议和异常升级。
3. 完善绩效评价：把响应时长、报告回传、下转随访、满意度、基层留诊率和互认节约费用纳入统一公式。
4. 增加县乡村协同视图：牵头医院、乡镇卫生院、村卫生室、医保和 IT 待办统一归集。

### P2：G 端指标中心汇聚

1. 将 7 个医共体闭环指标接入 G 端指标中心统一采集口径。
2. 支持按区县、机构、角色、病种、优先级和时间周期钻取。
3. 输出月度医共体协同效率、闭环完成率、互认节约和基层承接能力报表。
4. 将现场联调状态、外部阻塞项和上线签字进度纳入综合驾驶舱。

## 七、结论

医共体协同闭环模块已经具备演示级、联调级和发布证据级能力：县域端可运行，转诊会诊链路可追踪，角色责任可定位，报告回传和互认有证据，基层随访与质控反馈可纳入闭环，G 端指标也已具备采集标记。

当前距离正式上线运行的主要差距不在本地页面或业务模型，而在真实外部系统、生产身份、医保规则、报告附件、现场签字和生产运维。下一阶段应以“小范围真实机构试点”为主线，把本地闭环证据转换为可签收、可对账、可监控的生产联调材料。
