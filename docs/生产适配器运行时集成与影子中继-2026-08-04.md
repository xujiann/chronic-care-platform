# 生产适配器运行时集成与影子中继

## 已完成的本地能力

平台服务器通过中央装配根暴露 `GET /api/production-adapters/runtime`，仅委员会角色可读。该接口只返回脱敏配置与缓存的校验状态，不在请求路径连接 PostgreSQL、不启动工作进程，也不改变主读写路径。

转诊与院前急救领域在本地事务 outbox 中写入单调 `relaySequence`。独立影子中继进程读取本地 outbox，将事件幂等写入 PostgreSQL 领域 outbox，并在每个成功写入后把无业务载荷的游标保存到独立 SQLite 文件。进程在“写入成功、游标未保存”处崩溃时会重复投递同一事件，目标仓储通过事件 ID 和摘要校验将其识别为幂等重放。

## 进程边界

| 进程 | 责任 | 默认状态 |
| --- | --- | --- |
| HTTP 服务 | 业务请求、本地事务写入、只读运行时状态 | 不进行 PostgreSQL 双写 |
| `platform-shadow-relay@referral` | 转诊 outbox 的 PostgreSQL 影子副本 | 关闭 |
| `platform-shadow-relay@emergency` | 急救 outbox 的 PostgreSQL 影子副本 | 关闭 |
| `platform-production-worker@referral` | 转诊外部交付 | 关闭，需外部四方授权 |
| `platform-production-worker@emergency` | 急救外部交付 | 关闭，需外部四方授权 |

`platform-shadow-relay@.service.template` 和 `platform-production-worker@.service.template` 使用 oneshot 进程、最小文件写权限和 systemd 定时器。实例名只允许部署为 `referral` 或 `emergency`。

## 启用与验证顺序

1. 保持 `PLATFORM_PRODUCTION_ADAPTER_MODE=disabled` 与 `PLATFORM_SHADOW_RELAY_ENABLED=false` 完成软件部署。
2. 由现场密钥管理系统注入 PostgreSQL 连接，不把连接串写入仓库、日志或证据包。
3. 设置适配器为 evidence-gated，提供真实迁移、备份、恢复和审批引用；先执行只读 schema 校验。
4. 设置中央模式为 `shadow`，配置绝对路径 `PLATFORM_SHADOW_CHECKPOINT_FILE`，再显式打开影子中继。
5. 分别运行：

   `node scripts/platform-shadow-relay.js --domain=referral --run --verify-schema`

   `node scripts/platform-shadow-relay.js --domain=emergency --run --verify-schema`

6. 对两个领域分别执行 `--reconcile --verify-schema`；只保留 count、high-watermark 和摘要，不保留患者数据。
7. 使用 `--fault-after-enqueue=<sequence>` 做受控故障恢复演练，随后重跑并确认幂等恢复。
8. 只有两个领域对账均通过、持久游标与故障恢复均有受控证据后，才可将结果装入试点切换输入。

## 强制门禁

试点切换的本地 reconciliation 门禁同时要求：

- 转诊和急救两个领域的摘要对账均通过；
- SQLite 持久检查点已验证；
- “目标写入后、检查点保存前”故障恢复已验证；
- 对账报告明确 `payloadsExposed=false`。

这些结果仍只是本地技术证据。真实数据库迁移、联合测试、安全测评、容灾演练、站点验收和四方 GO/NO-GO 决策必须由外部受控证据提供；代码不会推断或代替这些结论。
