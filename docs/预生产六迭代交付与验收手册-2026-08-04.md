# 预生产六迭代交付与验收手册

## 目标与边界

本轮将生产切换前的六类能力固化为可重复、可审计、默认拒绝的本地控制面。仓库中的代码、模板和测试只能证明“本地基础具备”；真实外部机构回执、安全评估、四方批准以及现场人工切换不得由程序推断或伪造。

所有报告只允许保存账号标识、时间、状态、受控证据引用和 SHA-256 摘要。禁止写入口令、令牌、私钥、患者信息、诊断信息和业务报文。

## 六个迭代

| 迭代 | 责任线 | 本地交付 | 必须补齐的真实外部证据 |
| --- | --- | --- | --- |
| 1 | T01 身份与信任 | 远程签名验证、密钥同步/轮换/冻结/吊销/过期、身份与用途绑定 | 真实 KMS/HSM 身份、密钥状态和远程签名回执 |
| 2 | T00 预生产环境 | PostgreSQL、对象存储、集中会话、可靠消息、审计留存及四类恢复验收 | 独立复核的环境与恢复证据 |
| 3 | T08 外部联调 | HIS/EMR/LIS/PACS 等通道的双签名联调战役和异常场景矩阵 | 双方真实签名回执 |
| 4 | T03 监控与安全 | 送达、确认、升级、恢复、重试、死信和审计闭环 | 真实告警路由回执与安全验收 |
| 5 | T00 演练 | 七席位、六检查点、精确回滚口令和 T+1 六观察面 | 现场人员回执及远程签名演练记录 |
| 6 | T00 集成评审 | 五类报告绑定同一发布和包指纹，输出阻断项与责任人 | 四方 GO/NO-GO 批准和人工执行命令 |

## 推荐执行顺序

1. 生成并固化不可变发布包，记录 `releaseId` 与 `packageFingerprint`。
2. 完成迭代 1 的信任根同步与健康检查，确保密钥未过期、未冻结、未吊销。
3. 使用预生产环境模板采集迭代 2 证据，操作人与复核人必须不同。
4. 按迭代 3 的通道和场景矩阵完成联调，归档双方签名的回执摘要。
5. 按迭代 4 完成告警送达、确认、升级、恢复和死信重放演练。
6. 按迭代 5 组织七席位演练，实际发出精确回滚口令并在时限内完成验证。
7. 将授权、预生产、联调、监控和演练五份报告提交迭代 6 汇总。

## 本地命令

```powershell
npm run platform:preproduction -- environment --input=<environment-evidence.json> --require-ready
npm run platform:preproduction -- joint-test --campaign=<campaign.json> --trust-registry=<public-keys.json> --evidence=<signed-evidence.json> --release-id=<release-id> --package-fingerprint=<sha256> --require-ready
npm run platform:preproduction -- monitoring --input=<monitoring-acceptance.json> --journal=<alert-journal.jsonl> --release-id=<release-id> --package-fingerprint=<sha256> --require-ready
npm run platform:preproduction -- rehearsal --input=<rehearsal-session.json> --require-ready
npm run platform:preproduction -- rehearsal --input=<rehearsal-session.json> --ledger-payload
npm run platform:preproduction -- candidate --authorization=<authorization.json> --preproduction=<preproduction.json> --joint-tests=<joint-tests.json> --monitoring=<monitoring.json> --rehearsal=<rehearsal.json> --require-go-candidate
```

`GO-CANDIDATE` 只是评审结果，所有输出都固定保留 `cutoverExecutionAuthorized: false`、`productionPrimary: false` 或 `productionReady: false`。切流和回滚只能由已批准的现场人工命令执行。

## 失败处理

- 任一证据缺失、过期、被吊销、签名不可信或发布绑定不一致：立即 `NO-GO`。
- 恢复实际 RPO/RTO 超标、告警未送达/未确认/未恢复、联调缺少双签回执：保持阻断。
- 演练席位复用账号、检查点缺失、回滚口令或签发/确认/见证人不匹配：演练失败。
- 只更换失败证据，不覆盖历史记录；重新生成报告后再提交候选评审。
