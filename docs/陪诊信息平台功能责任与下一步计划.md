## 下一步开发优先级

1. 生产接入：实名身份、短信网关、电子健康卡、订阅消息和隐私协议上线。
2. 医院联调：HIS 预约号、门诊导诊台、科室联系人、退回补证和医院回执对账。
3. 服务履约：陪诊师移动端签到、轨迹留痕、服务记录、异常上报和居民确认。
4. 保障结算：电子签章、合同/保险附件、补贴资格核验、结算对账和费用明细。
5. 监管闭环：投诉工单、黑名单、星级评价、运营日报、现场签字和 SIEM 审计归档。

## 本次已完成的生产接入契约

- 建单只接收居民、服务商、医院科室、预约时间和服务项目等白名单字段，客户端伪造的订单状态、陪诊员、资格结论和医院回执不会进入订单。
- 家庭代办必须同时具备居民范围授权和授权登记回执；机构、区县或主管部门建单必须由服务端提供居民访问判定。
- 服务商必须已发布、处于允许状态，准入审批必须显式通过且在预约日期有效，订单全部服务项目必须同时属于政策目录和服务商目录。
- 同一居民、服务商、医院科室和预约时段使用稳定幂等键；相同请求安全重放，不同内容复用同一键时拒绝。
- 状态迁移必须提供访问判定和命令编号，资格核验、服务商匹配及派单证据绑定订单、居民/服务商/陪诊员和策略版本，公共调用不能关闭证据门禁。
- 建单、迁移和消息回执均生成事务外盒事件，事件标识和载荷摘要可重算；缺失或被篡改的外盒事件阻断幂等重放。
- `care-service-runtime.js` 已实现独占租约、租约接管、指数退避、死信登记、受控补偿和队列健康检查；公共 API/真实仓储/worker 的接入由 T00 统一集成。

联合生产判定见 `docs/互联网护理与陪诊生产上线门禁.md`，执行 `node scripts/care-service-production-readiness.js`。公共平台未接入、真实生产配置未完成或现场证据未签字时，报告必须保持阻断。

## 服务器与采购设置

陪诊模块复用统一平台的 `server.js`、登录、居民家庭关系、消息和审计，不建议第一阶段为陪诊单独购买服务器；试点可与慢病平台共用一套 Node 后端，正式生产按 `docs/陪诊服务上线服务器采购与部署方案.md` 准备云服务器、域名备案、HTTPS、数据库、对象存储、短信、统一身份、医院接口、监控审计和 `launch:smoke -- --base-url` 现场验证。
