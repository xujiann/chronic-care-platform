# 数智医院标准平台开发报告与下一步计划

- 报告日期：2026-07-11
- 开发分支：`codex/merge-chronic-followup-into-platform`
- 当前阶段：MVP 业务功能、生产适配器、可观测性告警、不可变部署和 PostgreSQL 迁移制品基础完成，现场生产割接未完成
- 结论：仓库已形成可运行、可测试、可审计、可发布验证的生产前版本；在真实凭据、外部接口联合测试、安全测评、监控灾备和正式签字完成前，不得标记为正式生产就绪。

## 一、本轮主要开发成果

### 1. 生产运行底座

- SQLite 生产配置支持 WAL、FULL 同步、外键、忙等待、自动检查点和 `quick_check` 健康证据；不支持的 PostgreSQL 配置会明确阻断，避免静默降级。
- OIDC UserInfo、受控本地账号绑定、短信随机验证码、摘要存储和供应商受理回执已接入运行时。
- HIS、EMR、LIS、PACS、号源连接器支持 HTTP 出站、HMAC-SHA256、幂等键、有限重试、受理回执、死信和人工对账。
- 安全对象存储支持上传意图、大小与 SHA-256 复核、服务端恶意文件扫描、短时下载授权、隔离、法律保全和不可变留存控制。

### 2. 支付、医保与电子证照

- 新增 PAYMENT、INSURANCE、CERTIFICATE 三类生产网关基础，共 14 个受控操作。
- 新增 `GET /api/financial-gateways` 和 `POST /api/financial-gateways/dispatch`，并复用统一集成事件、死信、人工重试和审计链。
- 支付交易契约 `payment-transaction-v1` 已加入接口字段映射，接口契约达到 9/9 完整映射。
- 金额强制使用整数分；证照正文使用摘要和受控引用；身份证号、手机号、访问令牌、私钥和 Base64 原文禁止进入网关事件。
- 生产环境门禁要求三类 HTTPS 地址及强签名密钥；专项 readiness 明确保持 `productionReady=false`。

### 3. 生产可观测性与 SIEM 告警闭环

- 新增 SIEM/Webhook 双路由适配，支持生产 HTTPS、HMAC-SHA256、时间戳、请求 ID、幂等键和有限重试。
- 告警只携带计数、环境、责任方、服务标签和证据引用，居民/患者标识、身份证号、手机号、诊断病历、令牌和私钥会在投递前被拒绝。
- 新增告警中心、投递和人工重放 API；失败投递自动生成运维事件，接收端恢复后关闭事件并保留审计链。
- 运行调度中心展示活动信号、路由状态、投递回执和重放队列；未配置真实接收端时不生成伪回执。
- 监控 readiness、环境矩阵、发布报告、部署检查和生产切换清单已同步纳入该能力，同时保持 `productionReady=false`。

### 4. 不可变部署包与密钥外置

- 新增生产部署包构建器，对运行时文件逐项计算 SHA-256，并生成聚合制品摘要、源码提交号和发布标识；校验器可在部署前复算文件与总摘要，发现篡改即失败。
- 密钥契约只记录环境变量引用和外部提供方，不把会话密钥、网关密钥、签名密钥或告警令牌写入制品；生产矩阵要求明确配置 Vault、KMS 或编排器密钥来源。
- 新增加固的 systemd 服务模板，包含只读系统目录、独立数据与日志写入目录、外部环境文件、自动重启、优雅停机和健康检查约定。
- 部署契约明确要求上一个制品摘要、存储备份、回滚快照和回滚后健康检查，CI 在发布报告后执行严格源码洁净检查、构建部署包并独立验签。
- 部署包、发布清单、发布报告、混合部署就绪度和部署检查已形成同一证据链；通用自动化基础通过不等于现场 Vault/KMS、TLS、制品仓库和编排平台已经验收。

### 5. PostgreSQL 迁移制品与安全导出

- 新增 PostgreSQL 迁移包生成与验签工具，默认 CI 制品只包含 `health_platform` 落地区 schema、集合与记录计数、逐集合摘要、装载/校验/回滚模板和文件摘要，不包含居民或就诊记录正文。
- 真实全量模式生成 COPY TSV，必须显式确认敏感数据，并强制写入仓库之外的访问受控目录；工具不会保存 `DATABASE_URL`、用户名或密码。
- 迁移清单对当前 JSON 快照生成源摘要、逐集合摘要和记录总数，可在装载后使用 `verify.sql` 对照导入计数、唯一键和摘要格式，并按 `migration_run_id` 执行批次回滚。
- 生产数据库 readiness、CI、发布清单、发布报告、部署检查和生产审计已同步接入；迁移包通过仍不启用 PostgreSQL 运行时适配器，生产状态保持阻断。

### 6. C 端全流程审查

- 居民端新增 10 条业务管线审查台账，覆盖登录、居民首页、健康档案、电子病历、授权审计、消息待办、护理、陪诊、挂号和移动发布。
- 每条管线列出入口、接口、责任方、现场动作、阻断项和证据，支持复制验收清单。
- 审查面板只在 `launch=1` 内部模式展示，正常居民模式保持隐藏。
- 已完成 1440px 桌面和 390px 移动视口验收；移动端审查模式导航改为非遮挡布局，无横向溢出。

## 二、正式生产前已实现的主要标准平台功能

1. 标准治理与评价：六大标准域、自评、校验、整改、证据包和正式割接审批台账。
2. 数据治理与平台底座：数据资产、标准字典、血缘、质量规则、平台总线、二期目录、SQLite 生产配置和 PostgreSQL 迁移清单与安全全量导出。
3. 接口集成与区域交换：9 类接口契约、签名、幂等、重试、死信、区域共享、转诊和会诊。
4. 身份、安全与审计：多角色会话、机构/居民数据范围、访问日志、安全事件、哈希链和国密适配中心。
5. 医疗质量与运营：质量安全、危急值、病历抽查、整改闭环、床位人力设备监测和药耗监管。
6. 公共卫生与慢病协同：21 个公共卫生标准域、慢病筛查分层、随访、家医、传染病直报和指挥台。
7. 居民连续服务：健康档案、预约挂号、候补、停诊改签、支付退费状态、护理和陪诊。
8. 重点应用：妇幼、免疫、影像云、多点执业、互联网护理、助医陪诊和临床辅助决策。
9. 科研、共享与驾驶舱：科研沙箱、伦理与导出审批、区域共享、指标中心和综合驾驶舱。
10. 运行保障与发布治理：健康检查、SLO、值班、事件、SIEM/Webhook 告警路由、不可变部署包、制品摘要验签、外部密钥引用、加固进程模板、备份恢复模型、发布报告、割接清单和回滚快照。

## 四、当前生产阻断项

1. 不可变部署包、外部密钥引用、加固进程模板和回滚契约已实现；生产域名、TLS、网络区划、Vault/KMS、制品仓库与编排平台尚未现场验收。
2. PostgreSQL 迁移清单、落地区 schema、安全全量导出、摘要验签和回滚模板已实现；是否作为首期生产库仍待容量与 RTO/RPO 决策，运行时适配器、领域表转换、增量同步和原生备份恢复仍未完成。
3. OIDC、短信、医院系统、支付、医保、电子证照和对象存储需要真实凭据、白名单、字典和联合测试回执。
4. 支付/医保回调验签、防重放、乱序处理、日终对账、冲正和差错补偿需按供应商协议落地。
5. SIEM/Webhook 告警适配基础已完成；目标接收端、值班升级、SIEM/WORM 保全、生产演练和首日观察尚未联合验收。
6. 等保、密评、渗透、隐私影响评估、漏洞整改、灾备演练和 go/no-go 正式签字尚未完成。

## 五、下一步开发计划

### P0：0-30 天

1. 完成生产可观测性现场接入：在现有告警适配基础上接入目标 SIEM/工单/呼叫平台、值班升级、WORM 留存和接口成功率/延迟/死信采集。
2. 完成密钥与部署自动化现场化：基于现有不可变制品、摘要验签、密钥引用和进程模板，接入现场 Vault/KMS、TLS 轮换、制品仓库、环境级流水线、进程编排和一键回滚演练。
3. 确定数据库生产路线：完成 SQLite 容量评审；如选 PostgreSQL，在现有迁移制品基础上交付运行时适配器、领域表转换、增量同步、全量装载复核和原生备份恢复工具。
4. 获取试点方参数，完成 OIDC、短信、HIS/EMR/LIS/PACS/号源、对象存储、支付、医保和证照沙箱联调。
5. 为支付/医保/证照补齐供应商回调验签、乱序状态机、日终对账与差错处理工作台。

## 六、下一开发批次建议

生产可观测性、密钥部署自动化和 PostgreSQL 迁移制品的通用基础已完成。下一批优先完成数据库路线决策；若采用 PostgreSQL，则继续实现运行时适配器、领域转换、增量同步、原生备份恢复和目标容量演练，同时建立 OIDC、短信、医院系统、对象存储、支付、医保、证照和告警接收端的真实联合测试参数表；现场侧并行完成 Vault/KMS、TLS、制品仓库和编排平台接入。
