# 可信身份与远程签名提供方接线

## 目标和边界

T01 只接收 KMS、Vault 或远程签名服务导出的公钥目录快照，不请求、不缓存、不持久化签名私钥。提供方必须使用预先固定的 Ed25519 根公钥对整份快照签名。平台验证快照来源和完整性后，仅把当前有效、账号启用、职责匹配且未冻结或撤销的公钥转换为切换授权账本可消费的 `pilot-cutover-trust-registry-v1`。

仓库代码和自动测试不能证明真实 KMS/Vault 已接通，也不能产生正式上线证据。真实环境在完成供应商配置、网络白名单、根公钥线下核验、密钥仪式和现场签字之前仍为 `NO-GO`。

## 数据流

```text
审批人或核验人
  -> KMS/Vault 内部签名（私钥不离开设备）
  -> 提供方导出公开身份/公钥目录
  -> 提供方根密钥签署目录快照
  -> T01 验证根信任、快照时效和生命周期
  -> 只导出当前可用公钥注册表
  -> T00 切换账本验证事件签名
```

## 生命周期规则

- `active`：账号为 `active`、职责和 scope 匹配、密钥处于有效期内时才能导出。
- `frozen`：必须携带 `frozenAt`，立即从可用注册表排除。
- `revoked`：必须携带 `revokedAt`，立即从可用注册表排除。
- `retired`：作为轮换历史保留，但不能验证新事件。
- `rotation.previousKeyId`：前驱密钥必须存在、属于同一账号和职责、开始时间早于后继密钥，且轮换链不能成环。
- `requiredForCutover`：该身份声明的每个 scope 都必须至少有一把当前可用密钥，否则整份快照 fail-closed。
- 快照默认最长存活 60 分钟；时间来自未来、超过最大年龄或 `expiresAt` 已过期时全部阻断。

## 文件部署

参考：

- `deploy/identity-trust-provider.env.template`
- `docs/evidence-templates/identity-trust-provider-anchors.template.json`
- `docs/evidence-templates/identity-trust-provider-snapshot.template.json`

两个文件必须是绝对路径、普通非符号链接 JSON 文件，单文件不超过 1 MiB。根公钥须通过独立线下渠道核对指纹，不能直接信任与快照同渠道传递的未核验根公钥。

提供方快照的签名主体是：

```json
{
  "schemaVersion": "pilot-cutover-trust-provider-snapshot-subject-v1",
  "body": "<删除 attestation 后的完整快照对象>"
}
```

使用稳定 JSON 序列化后计算 SHA-256 并执行 Ed25519 签名。`attestation.subjectDigest` 和签名必须同时匹配。

## 健康与告警

适配器健康结果只可能是 `healthy`、`warning` 或 `blocked`：

- 根签名失败、快照陈旧、账号职责漂移、轮换链异常、必需 scope 无可用密钥：`blocked`。
- 当前密钥临近过期、历史中存在冻结/撤销密钥、存在停用身份：`warning`。
- 所有检查通过且无预警：`healthy`。

健康报告始终返回 `productionReady: false` 和 `cutoverExecutionAuthorized: false`。它是可信身份控制面输入，不是生产切换命令。

## T00 集成交接

T00 在中央运行时组合中读取上述四个环境变量，调用
`evaluatePilotCutoverTrustProvider()`。仅当 `health.status !== "blocked"` 且
`registry` 非空时，才将 `registry` 传给现有
`createPilotCutoverTrustVerifier({ registry })`。同时把 provider health 纳入
`/api/production-adapters/pilot-cutover/health`；任何读取或验证异常都应保留
`NO-GO`，不得回退到静态注册表或跳过签名验证。
