# 传染病直报生产候选就绪门禁

日期：2026-08-05

## 目标

将字典生命周期、正式控制包、纯合成联合测试、投递回执对账和运行监控五个安全投影汇入同一技术候选判定，避免各模块分别显示“通过”后被误读为已经批准生产上线。

## 八项检查

1. 当前字典版本有效且生命周期账本可验证；
2. 官方控制包已通过独立签署校验；
3. 官方控制包与当前字典摘要、映射指纹一致；
4. 官方联合测试证据尚未过期；
5. 官方联合测试场景完整；
6. 纯合成离线测试全场景通过且没有外部调用；
7. 没有未关闭的投递与回执对账事项；
8. 监控 SLO 健康且没有活动告警。

八项全部通过时只产生 `technicalCandidateReady: true`。报告始终保留
`GLOBAL_SITE_PRODUCTION_GO_NO_GO_REQUIRED`，并始终输出
`productionReady: false`。

## 自动化入口

将五份脱敏投影组合为单个 JSON 文件后执行：

```powershell
npm run public-health:direct-report-readiness -- --input=C:\controlled\direct-report-readiness.json --require-technical-ready=true
```

输入必须是绝对路径、普通 JSON 文件且满足既有受控文件大小限制。CLI 不接受端点、凭据、自定义报文或人工生产批准参数。技术门禁不通过时退出码为 `2`；输入或参数不合法时退出码为 `1`。

## 安全边界

- 输入只允许各模块的安全投影，不使用原始病例、报文、回执、签名或凭据；
- 输出只包含检查结果、责任方、计数和稳定阻断码；
- 合成测试永远不能替代疾控与医院的独立正式签署；
- 本门禁不能设置或推导平台全局生产 Go/No-Go 决策。
