# 传染病直报运行监控与告警

## 目标与边界

本模块为传染病直报独立 Worker 提供领域级运行监控、安全告警和 SLO 判定。它只消费投递状态的安全投影、签名失败计数以及控制包的公开状态，不读取或输出接口端点、密钥、签名、原始报文、回执编号、病例标识或居民数据。

监控通过只表示仓库内技术信号满足阈值。输出始终包含 `productionReady=false`，生产切换仍须完成现场监控投递、值守升级演练和签字验收。

## 安全快照

`collectDirectReportObservabilitySnapshot` 从以下受控信息生成聚合快照：

- 投递状态、尝试次数和可信回调等待起始时间；
- 控制包公开的证据失效时间、字典摘要和映射指纹；
- 已批准的字典摘要与映射指纹基线；
- 监控窗口内签名验证失败总数。

病例、投递和回执标识只可能存在于上游安全投影中，采集器不会读取或复制这些字段。快照标明不含居民数据、原始报文和凭据。

## SLO 与默认阈值

| 信号 | 默认目标 | 说明 |
| --- | --- | --- |
| 队列积压 | 不超过 20 条 | `queued`、`leased` 和 `retry-scheduled` 聚合计数 |
| 死信率 | 不超过 1% | 死信数除以监控样本内已尝试投递数 |
| 回执超时 | 0 条 | 已接受投递 300 秒内应获得可信终态回调 |
| 证据有效期 | 大于 24 小时 | 进入 24 小时窗口时预警，过期时严重告警 |
| 字典与映射 | 与批准基线一致 | 基线缺失时阻断，摘要值不写入告警 |
| 签名失败 | 0 次 | 回调或控制证据签名失败均按窗口聚合 |

阈值可由调用方在受控装配时传入，但模块限制了数值范围，异常配置会以稳定错误码失败关闭。

## 告警契约

每条告警只包含稳定代码、稳定指纹、严重级别、责任方、固定说明和恢复条件。告警按信号聚合，不带投递、病例、回执或机构标签。

| 告警 | 级别 | 责任方 | 恢复条件 |
| --- | --- | --- | --- |
| 队列积压 | warning；超过阈值两倍为 critical | hospital-information-center | 积压回落到 SLO |
| 死信率 | critical | hospital-information-center | 死信率回落到 SLO |
| 回执超时 | critical | joint-direct-report-operations | 无超时回调 |
| 证据即将过期 | warning | direct-report-control-custodians | 有效期退出预警窗口 |
| 证据过期或不可用 | critical | direct-report-control-custodians | 验证新的当前证据 |
| 字典或映射漂移 | critical | direct-report-control-custodians | 运行时指纹恢复为批准值 |
| 签名验证失败 | critical | security-operations | 当前监控窗口无签名失败 |

## 输出

- `renderDirectReportObservabilityJson` 输出脱敏 JSON 报告，适合只读运维 API、证据归档或告警适配器；
- `renderDirectReportPrometheus` 输出固定指标名和有界严重级别标签，不包含高基数标识或摘要；
- Prometheus 的 `health_platform_public_health_direct_report_production_ready` 永远为 `0`。

中央 API、Prometheus 路由、告警投递和部署参数由 T00 在集成阶段装配。本模块不保存告警、不直接调用外部端点，也不提供人工放行操作。

## 验证

定向测试：

```powershell
node --test test/public-health-direct-report-observability.test.js
npm run process:verify
```

现场验收还需证明指标已接入受管监控、告警可达责任人、恢复条件会自动关闭告警，并完成签署后的值守升级演练。
