# 影子中继运行控制面

## 目标与边界

影子中继运行控制面把转诊和院前急救两个独立中继进程的执行结果，汇总为可复核、篡改可检出、无业务载荷的本地技术证据。它不改变 HTTP 请求路径，不执行双写，不证明外部系统交付、现场验收、容灾演练或生产切换。

生产主链路仍保持关闭。控制面报告始终包含：

- `payloadsExposed=false`
- `externalEvidenceVerified=false`
- `cutoverAuthorized=false`
- `productionPrimary=false`
- `productionReady=false`

## 进程和存储

| 进程 | 职责 | 写入 |
| --- | --- | --- |
| HTTP 服务 | 提供委员会只读状态 `GET /api/production-adapters/shadow-relay` | 仅安全审计事件 |
| `platform-shadow-relay@referral` | 转诊 outbox 幂等影子转发 | PostgreSQL 影子表、SQLite 检查点、运行账本 |
| `platform-shadow-relay@emergency` | 急救 outbox 幂等影子转发 | PostgreSQL 影子表、SQLite 检查点、运行账本 |
| `platform-shadow-reconcile@referral` | 转诊摘要对账 | 运行账本 |
| `platform-shadow-reconcile@emergency` | 急救摘要对账 | 运行账本 |

`PLATFORM_SHADOW_CHECKPOINT_FILE` 保存每个 relay 的持久游标。`PLATFORM_SHADOW_OPERATIONS_FILE` 是独立的 SQLite STRICT 账本，只保存运行标识、序号、数量、摘要、受控错误码和哈希链，不保存事件 ID、患者字段、业务载荷、数据库凭据或外部响应。

两个文件必须使用绝对路径，位于仅服务账号可读写的部署数据目录。HTTP 服务仅以只读模式打开运行账本。

## 运行顺序

1. 保持 `PLATFORM_PRODUCTION_ADAPTER_MODE=disabled` 和 `PLATFORM_PRODUCTION_WORKERS_ENABLED=false`。
2. 设置检查点文件、运行账本文件和对账最大新鲜度：

   ```text
   PLATFORM_SHADOW_CHECKPOINT_FILE=/var/lib/health-platform/shadow-checkpoint.sqlite
   PLATFORM_SHADOW_OPERATIONS_FILE=/var/lib/health-platform/shadow-operations.sqlite
   PLATFORM_SHADOW_RECONCILIATION_MAX_AGE_MINUTES=60
   ```

3. 完成 PostgreSQL 只读 schema 校验后，显式开启 `PLATFORM_SHADOW_RELAY_ENABLED=true`。
4. 分别启动 `platform-shadow-relay@referral.timer` 和 `platform-shadow-relay@emergency.timer`。
5. 对两个域各执行一次 `--fault-after-enqueue=<sequence>`，随后重跑同一域，确认出现幂等重放并推进检查点。
6. 启动两个 `platform-shadow-reconcile@*.timer`，让摘要对账持续保持在新鲜度窗口内。
7. 使用 `npm run production-adapters:shadow-control -- --require-ready` 获取双域控制面报告；也可由委员会角色读取只读 API。

## 门禁语义

每个域必须同时满足：

- 运行凭据哈希链完整；
- 最近一次 relay 成功；
- 最近一次对账的 count、high-watermark 和 digest 一致；
- 对账发生在最近一次成功 relay 之后并覆盖其检查点；
- 持久检查点与源端 high-watermark 一致；
- 已记录“写入后、检查点前”的受控故障，之后出现幂等恢复和成功对账；
- 对账仍在配置的新鲜度窗口内。

控制面根据两个域的凭据摘要生成 `technicalEvidenceFingerprint`。试点切换输入中的 `evidenceDigests.reconciliation` 必须与该指纹完全一致；任一字段漂移、账本篡改、新故障未恢复或对账过期都会回到 `NO-GO`。

即使本地技术门禁全部通过，真实迁移、联合测试、安全测评、容灾演练、站点验收和四方审批仍必须由外部受控证据单独提供。
