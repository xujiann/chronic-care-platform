# 浪潮方案 4.1 立即采纳开发任务分派表

> 来源：`浪潮方案对标采纳意见与后续开发报告` 第 4.1 节。本文把“建议立即采纳”的方向转成可执行开发任务，并分派到现有模块线程。

## 一、执行原则

1. 不另起平行系统，全部复用现有平台、模块工作树、API、页面、readiness/report/release 校验链。
2. 每个模块线程必须形成“可运行能力 + 可验证证据 + 发布校验”的闭环，不能只提交说明文档。
3. 已经处于开发中的线程先收口当前切片，再承接下一步增强，避免半成品叠加。
4. 涉及跨模块指标、主数据、任务流的能力，优先在平台总线或 G 端综合管理线程沉淀统一出口。

## 三、各线程首轮任务拆解

### 1. 数据治理底座

- 完成当前数据治理底座切片的 API 探测、静态检查、测试、deploy check、release report、发布验证。
- 将现有 EMR、HIS、LIS、PACS、随访、药耗、区域平台等来源整理成平台主数据目录。
- 给出标准字典、血缘、接口阻断项和责任人证据，供后续指标中心和智慧医院线复用。

### 2. 指标中心

- 完成指标中心当前切片的 Playwright/预览验证与发布。
- 把“公立医院改革与高质量发展”指标拆成运营、质量、安全、协同、公卫、科研、资源效率等分类。
- 形成指标中心统一出口，接收医共体、智慧医院、公卫闭环等模块指标状态。

### 3. 医共体协同闭环

- 完成六步闭环当前切片的 DOM 证明、数据恢复、提交与发布。
- 下一步优先补齐角色化待办、检查检验互认证据、基层随访回填、质控反馈闭环。
- 输出可被 G 端指标中心采集的协同效率和闭环完成率。

### 4. 智慧医院管理线

- 质量安全线程：建设医疗质量、病案/质控、整改闭环、预警指标。
- 运行监测线程：建设床位、手术、急诊、资源调度、效率指标。
- 科研平台线程：建设重点专科、科研队列、转化项目和合规数据出口。
- 药耗监管线程：建设药品、耗材、合理用药、供应保障和异常预警指标。
- G 端综合管理线程：汇总上述模块状态，形成智慧医院管理入口。

### 5. 疾控和公卫闭环

- 以慢病高危人群、基层随访、家庭医生任务为第一入口。
- 建立风险监测、规则预警、任务派发、干预随访、结果回填、指挥汇总闭环。
- 后续和免疫规划、传染病报告、区域公共卫生系统联动。

首轮第一切片：

- API：`GET /api/chronic/public-health-loop` 输出慢病高危与基层随访的 `monitor -> alert -> dispatch -> intervention -> follow-up -> summary` 六步闭环。
- UI：医疗机构端“疾控和公卫闭环”面板展示六步阶段、重点人群队列、家庭医生派单和随访汇总。
- 证据：`chronic:followup-readiness`、`release:report`、`deploy:check` 和 API 回归均纳入该闭环。

## 四、验收与发布规则

每个线程完成首轮开发时，至少提交以下证据：

- 代码层：实际 UI/API/状态模型增量，不接受纯文档交付。
- 校验层：`npm.cmd run check`、相关 `npm.cmd test`、模块 readiness、`deploy:check`、`release:report`。
- 预览层：需要用户可见页面的模块，应提供本地预览或 DOM/截图证明。
- 发布层：按线程既有发布流程完成提交、推送或发布验证，并在最终回复中列出证据。
