# 机构适配器与连续照护闭环增强

## 交付边界

本迭代在 T05 服务协同领域新增两层能力：

1. 机构适配器 SDK 与元数据契约运行器；
2. 动态风险到随访关闭的连续照护闭环。

没有修改中央路由、T08 外部集成路由、CI、运行时装配或生产部署配置。外部适配器通过依赖注入交由后续运行时装配，仓库中不存在真实机构端点、凭据、私钥、患者信息和请求/响应原报文。

## 机构适配器 SDK

配置注册 HIS、EMR、LIS、PACS、药事和医保六类元数据合约。每次运行只处理：

- 受控请求证据引用和请求 SHA-256 摘要；
- 关联标识、幂等键摘要、端点摘要、nonce 摘要和时间戳；
- 响应、签名和回执 SHA-256 摘要；
- 回执证据引用和签名验证证据引用。

调用方注入 `dispatch` 与 `verifyReceipt`。`dispatch` 可以访问仅在内存中存在的 HTTPS 端点，`verifyReceipt` 由环境侧密钥托管实现完成签名校验；控制层永不保存端点、密钥和原始签名。

契约运行器包含以下控制：

- HTTPS 和端点摘要一致性；
- 请求/回执时间窗；
- nonce 防重放；
- 命令与业务幂等；
- 指数退避、永久失败和重试耗尽死信；
- 可重算回执摘要、签名验证证据和请求摘要对账；
- 任何 `payload`、`patient`、`body`、`credential`、`token`、原始 `signature` 等字段均被拒绝。

## 连续照护闭环

状态链为：

```text
动态风险评估/重评
  → 照护计划（目标摘要 + 任务摘要）
  → 异常升级
  → HIS 转诊请求
  → 已签名且已对账的转诊回执
  → 药事回执脱敏投影 + 医保回执脱敏投影
  → 随访与结局摘要关闭
```

每个转换要求命令幂等、预期版本和前置状态。转诊请求必须与已经通过的 HIS 适配器运行使用同一请求摘要；转诊回执直接引用该运行的回执摘要与签名验证证据。药事和医保挂钩只保留来源类型、适配器运行标识摘要、回执/响应摘要及受控证据引用，不保留处方、药品、费用、结算或患者明细。

## 生产门禁

所有报告固定：

- `productionGate: "NO-GO"`；
- `productionReady: false`；
- `externalEvidenceVerified: false`。

本地契约通过和闭环关闭不能替代现场网络验证、机构与临床验收、密钥托管、安全测评、运行审批及生产变更授权。
