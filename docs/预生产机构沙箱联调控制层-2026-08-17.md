# 预生产机构沙箱联调控制层

## 目标

在不把真实机构端点、凭据、患者数据或接口原报文写入仓库和平台状态的前提下，提供机构适配器的预生产沙箱联调控制层，并把技术回执与既有慢病转诊闭环绑定。

该控制层只证明本地控制逻辑和预生产沙箱交互的技术完整性。即使所有沙箱检查通过，`productionReady` 仍固定为 `false`，生产门禁仍为 `NO-GO`。

## 控制流程

1. 准备联调会话：选择允许的机构适配器，校验受控请求证据引用和请求 SHA-256 摘要；HTTPS 端点仅在运行时提供，状态只保存端点摘要。
2. 注入传输适配器：调用方通过 `options.transport.send` 注入实现。控制层传递请求摘要、证据引用、时间戳和 nonce 摘要，不传患者载荷。
3. 执行防护：校验 HTTPS、端点摘要、请求时间窗和 nonce 唯一性；传输异常转换为可重试失败，复用现有试点编排器的指数退避和死信规则。
4. 验证回执：接收请求/响应/签名 SHA-256 摘要、受控回执与签名验证证据引用，重算回执摘要并校验请求一致性及回执时间窗。原始签名和原报文不得进入状态。
5. 完成对账：已验证回执的请求摘要与试点投递摘要一致后，调用既有机构试点对账能力。
6. 绑定闭环：只有签名摘要回执验证并完成对账后，才能触发慢病转诊五事件闭环；沙箱状态只保存闭环摘要和技术证据指纹。

## 依赖注入契约

传输适配器必须实现异步 `send(request)`。成功时返回：

- `outcome: "accepted"`；
- `receipt.acknowledgedRequestDigest`、`responseDigest`、`signatureDigest` 和可重算的 `receiptDigest`；
- `receiptEvidenceRef` 与 `signatureVerificationEvidenceRef`；
- `signatureVerified: true`，表示注入适配器已完成脱敏后的签名校验；
- `receivedAt`。

临时失败和永久失败分别返回 `retryable-failure` 或 `permanent-failure`，并附受限的 `errorCode`。控制层拒绝包含 `payload`、`body`、`patient`、`credential`、原始 `signature`、`token` 等字段的适配器响应。

## 状态与证据边界

允许持久化：受控证据引用、SHA-256 摘要、受限业务关联标识、状态、版本和时间戳。

禁止持久化：真实端点、用户口令、令牌、密钥、原始签名、患者数据、请求/响应原报文和传输异常正文。

沙箱通过后仍需外部完成生产端点和密钥托管、独立现场验收及生产变更审批。仓库内测试或环境开关不能替代这些证据。
