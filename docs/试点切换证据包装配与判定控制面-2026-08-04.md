# 试点切换证据包装配与判定控制面

## 交付目标

本控制面把生产适配器、影子对账、区域联调、业务闭环、运营治理、外部发布证据、回滚和灾备八类材料装配为一个不可覆盖的 JSON 包。装配器只绑定已有技术证据，不生成签字、不补造现场回执，也不执行切换。

## 装配流程

1. 从 `docs/evidence-templates/platform-iterations/pilot-cutover-package-manifest.template.json` 创建现场清单。
2. 为六类报告、回滚证据和灾备证据填写绝对路径。
3. 执行：

```powershell
npm run platform:cutover-package -- build --manifest=C:\controlled\cutover-manifest.json --output=C:\controlled\cutover-release-20300804.json
```

装配器逐项重算技术投影，验证报告自带指纹，生成八个 `evidenceDigests` 和一个 `candidateEvidenceFingerprint`。输出中的 `authorization` 固定为空、`decision` 固定为 `NO-GO`，已有输出文件禁止覆盖。

## 验证与运行读取

```powershell
npm run platform:cutover-package -- verify --input=C:\controlled\cutover-release-20300804.json
npm run platform:cutover-package -- verify --input=C:\controlled\cutover-release-20300804.json --require-go-candidate
```

普通验证只检查包是否可安全读取并输出当前判定；`--require-go-candidate` 在外部门禁或批准不完整时返回退出码 2。

部署环境设置：

```text
PLATFORM_PILOT_CUTOVER_INPUT_FILE=C:\controlled\cutover-release-20300804.json
```

委员会只读接口：

```text
GET /api/production-adapters/pilot-cutover
```

仅 `commission` 角色可读取，访问会记录 `pilot-cutover-control-plane-read` 审计事件。文件缺失、相对路径、符号链接、超限、JSON 损坏、敏感字段、摘要漂移或批准不完整时均保持 `NO-GO`。

## 文件与数据边界

- 单个源文件最大 1 MiB，装配包最大 4 MiB。
- 输出通过同目录临时文件、文件同步和原子重命名写入。
- 禁止凭据、令牌、私钥、患者或居民原始数据、诊断明细和原始报文。
- `GO-CANDIDATE` 也不代表已执行切换；`cutoverExecutionAuthorized`、`productionPrimary` 和 `productionReady` 始终为 `false`。
