# 数据治理统一运营控制面

## 交付范围

本轮把六个数据迭代统一成一个只处理元数据的运营控制面：

1. 迁移执行：只允许后台工作器消费已经提交的本地事务 outbox。
2. 可恢复 checkpoint：租约版本隔离并发工作器，checkpoint 只允许单调前进，崩溃后从最后位置恢复。
3. 精确对账：源目标计数、摘要、重复数和 checkpoint 必须完全一致。
4. 回滚门禁：恢复摘要、RPO/RTO 和两个独立角色的证据必须同时通过。
5. 质量规则：计数、重复、完整性、有效性和新鲜度规则形成统一规则目录，未解决问题阻断候选。
6. 血缘与影响分析：为 3 个迁移波次、12 个 P0 集合生成元数据血缘，并沿控制拓扑计算变更的下游影响。

## 事项中心对接

对账异常和质量问题会被投影为现有统一事项中心可直接读取的 `platformWorkItems` 结构。投影只包含：

- 稳定摘要标识；
- 事项类型、严重程度、状态和 SLA；
- 证据引用；
- 数据治理领域和版本信息。

投影不包含批次业务内容、源目标记录、患者信息、机构原始报文、异常原文或凭据。事项中心可以分派、处理、阻断和留痕，但不能反向修改迁移批次，也不能替代对账、回滚或质量门禁。

## 本地候选判定

本地候选要求迁移控制记录和执行批次同时达到 `local-candidate`，并绑定相同的 run、wave 和 checkpoint；此外不得存在开放的对账异常或质量问题，回滚与质量控制证据必须完整。

即使全部本地检查通过，结果仍固定为：

- `productionReady: false`
- `productionPrimary: false`
- `activationAuthorized: false`
- `decision: NO-GO`

真实全量演练、签名对账、独立回滚演练、容量和容灾评估、现场变更审批仍是外部证据，仓库代码不能生成或替代这些证据。

## 使用与验证

```powershell
node scripts/data-governance-control-plane-readiness.js
node scripts/data-governance-control-plane-readiness.js --input=<元数据输入.json> --output=<报告.json> --write
node --test test/data-governance-control-plane.test.js
```

输入只允许 `migrationRuns`、`executionState`、`reconciliationExceptions`、`qualityFindings` 和 `changes` 五类元数据。未知字段、敏感字段、未登记规则、跨波次集合和未知拓扑节点都会被拒绝。
