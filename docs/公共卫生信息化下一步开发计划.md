# 公共卫生信息化下一步开发计划

生成日期：2026-07-08
适用范围：`public-health.html`、`GET /api/public-health/system`、公共卫生事件处置、数据交换、发布就绪和现场验收材料。

## 目标

公共卫生信息化系统已经完成标准矩阵、机构责任、事件队列、交换任务和发布证据的第一版。下一步开发要把系统从“标准展示和看板”推进到“可处置、可追踪、可验收”的工作台，优先围绕《全国公共卫生信息化建设标准与规范（试行）》要求的平战结合、医防融合、数据交换、安全审计和现场联调证据展开。

## 5 小时开发切片

| 时间 | 开发内容 | 交付物 | 验收清单 |
|---|---|---|---|
| 第 1 小时 | 梳理事件处置闭环和后续路线 | 本计划文档、建设报告补充 | 明确事件处置闭环、数据交换、现场联调、发布闸口 |
| 第 2 小时 | 建立公共卫生事件动作 API | `POST /api/public-health/events/:id/actions` | 支持复核、派发、闭环、备注、责任人、时限 |
| 第 3 小时 | 升级卫健委端公共卫生页面 | 风险队列操作按钮、动作历史、结果刷新 | 页面能直接触发事件处置并刷新系统摘要 |
| 第 4 小时 | 补齐 readiness、部署检查和发布报告证据 | `public-health:readiness`、`deploy:check`、`release:report` | 新增事件动作 API 和前端操作检查 |
| 第 5 小时 | 跑完整验证并整理下一阶段事项 | 测试结果、预览验证、剩余依赖 | `check`、专项测试、API 测试、部署/发布报告通过 |

## 两周路线

| 阶段 | 重点 | 产出 |
|---|---|---|
| 第 1 阶段：处置闭环 | 公共卫生事件动作、审计、责任人、时限、闭环证据 | 事件工作台、动作 API、审计链、测试 |
| 第 2 阶段：数据交换 | 疾控直报、实验室、免疫、妇幼、应急、安全审计六类交换任务细化 | 交换任务运行记录、失败补偿、回执状态 |
| 第 3 阶段：机构协同 | 疾控、基层、医院、监督、妇幼、卫健管理部门角色化视图 | 分角色任务摘要、机构责任清单、现场账号清单 |
| 第 4 阶段：现场验收 | 等保密评、国密、备份恢复、接口联调、签字材料归档 | 验收材料清单、阻塞项、证据台账 |

## 开发完成记录

完成日期：2026-07-09

本计划已开发到演示/验收发布包状态，具体完成如下：

1. 事件处置闭环：`POST /api/public-health/events/:id/actions` 支持复核、派发、闭环，写入 `publicHealthEvents.actionHistory` 和 `securityEvents`。
2. 数据交换：新增 `publicHealthExchangeRuns` 和 `POST /api/public-health/exchange-tasks/:id/runs`，覆盖六类交换任务的运行记录、回执状态、失败补偿和重放/人工复核。
3. 机构协同：新增 `publicHealthInstitutionTasks` 和 `POST /api/public-health/institution-tasks/:id/actions`，覆盖疾控、基层、卫健管理、监督、妇幼、医院和其他公卫机构。
4. 现场验收：新增 `publicHealthOnsiteAcceptances` 和 `POST /api/public-health/onsite-acceptances/:id/actions`，覆盖接口联调、等保密评、备份恢复、应急演练、账号确认和发布材料。
5. 前端工作台：`public-health.html` 已增加交换运行、机构协同、现场验收面板，`public-health.js` 支持记录回执、完成协同和记录签署。
6. 发布证据：`public-health:readiness`、`deploy:check`、`release:report`、`release:manifest`、静态测试和 API 测试均已纳入新增能力。

发布边界：本计划完成的是可运行演示/验收包；正式生产上线仍以现场真实接口、密钥、等保密评、国密设备、备份恢复演练和签字材料到位为准。
