# 传染病直报可信回调与时间线

日期：2026-08-05

## 本轮结果

传染病事件报告运行时在原有案件建档、人工动作和持久化基础上，新增疾控直报平台可信签名回调入口和委级门户全过程时间线。

本轮仍保持：

- `productionReady: false`；
- 人工动作 API 不允许写入 `record-receipt`；
- 仓库测试不能替代真实 VPN、机构凭证、字段字典、联合调试回执和现场审批。

## 可信回调

入口：

`POST /api/public-health/infectious-reporting-cases/:id/direct-report-callback`

请求头：

- `X-Public-Health-Direct-Report-Timestamp`
- `X-Public-Health-Direct-Report-Nonce`
- `X-Public-Health-Direct-Report-Signature`

服务端复用 `public-health-connectors.js` 的 `verifyDirectReportCallback`，执行以下校验：

1. HMAC-SHA256 签名；
2. 回调时间窗；
3. nonce 格式及持久化后的跨案件重放约束；
4. `eventId` 与案件 `externalEventId` 的稳定绑定；
5. 仅接收终态回执，`processing` 等中间态不能推进案件；
6. 同一回执、同一语义幂等重放，内容漂移返回冲突。

持久化只保留：

- 合同编号；
- 外部事件编号；
- 回执编号和业务状态；
- nonce 的 SHA-256 摘要；
- 已验签标志；
- 回执审计摘要。

原始 nonce、签名、密钥和回调报文均不持久化，也不返回门户。

## 门户时间线

委级公共卫生门户新增“传染病事件报告全过程”面板，读取：

`GET /api/public-health/infectious-reporting-cases`

列表接口仅返回最小化案件投影：

- 案件、事件、报告和报告卡编号；
- 当前状态与版本；
- 可信回执状态；
- 标准映射和随访状态；
- 去除幂等摘要、居民身份和回调机密的时间线。

时间线覆盖：

1. 发现事件；
2. 校验事件；
3. 标准映射复核；
4. 生成报告卡；
5. 提交直报；
6. 写入可信回执；
7. 疾控复核；
8. 随访关闭。

门户为只读视图，不提供人工补写回执按钮。
