# 身份权限与生产会话加固

## 交付结论

T01 已完成外部身份、账号状态、机构绑定、浏览器会话、CSRF 与高风险 step-up 的运行时基础。OIDC 可以执行受控绑定、刷新和注销；SAML 仅完成严格配置与签名约束契约，未实现断言运行时验签，也没有真实身份提供方联合测试证据，因此平台生产状态必须保持 `NO-GO`、`productionReady: false`。

## 外部身份唯一键

外部账号必须使用以下复合键：

```text
canonical issuer + persistent subject
```

- OIDC 使用配置的 `OIDC_ISSUER_URL` 与 `sub`。
- 同一个 `sub` 可以存在于两个不同 issuer，但不能在同一个 issuer 内绑定到两个本地账号。
- 只保存 `externalSubject`、没有 `externalIssuer` 的历史绑定返回 `legacy-binding-review-required`，不能用于登录。
- 目录绑定同时保存 `externalIssuer`、`externalSubject` 和 `externalIdentities[]`；issuer 变更必须走独立迁移审核。
- UserInfo 返回的 `iss` 与配置 issuer 不一致时立即拒绝；生产 discovery 必须返回一致的 `issuer`。

## 账号与会话联动

每次读取当前身份上下文时都重新核对本地账号：

1. 角色必须属于平台角色白名单。
2. `accountType` 必须属于该角色允许的岗位白名单。
3. 账号和机构必须启用，机构类型必须与角色匹配。
4. 会话快照中的角色、岗位或机构与当前目录不一致时，立即撤销会话并要求重新登录。
5. 目录停用继续调用集中会话存储的 `revokeByUserIds`，确保账号停用与会话撤销联动。

居民账号允许绑定个人/家庭主体；其他角色必须绑定 `authOrganizations` 中存在且启用的机构。未知角色、未知岗位和未知机构统一 fail-closed。

## 浏览器会话

生产环境默认：

```text
Cookie: health_city_browser_session
HttpOnly; Secure; SameSite=Strict; Path=/
```

登录、居民手机号登录、OIDC 登录/刷新成功后签发 Cookie；退出和 OIDC 注销时清除。生产响应默认不返回 Bearer token。只有非生产环境，或显式设置 `AUTH_BEARER_COMPATIBILITY=enabled`，才保留 Bearer 兼容；生产打开兼容会继续形成阻断项。

T00 需要在中央请求入口消费同名 Cookie，并在静态 HTML 页面守卫和所有 API 调用前完成会话水合。T01 路由不会修改中央 router 或 `server.js`。

## CSRF 与 step-up

Cookie 认证的写请求使用签名双提交 CSRF：

- 服务器签发 `health_platform_csrf` Cookie；
- 客户端从身份上下文取得相同令牌并写入 `X-CSRF-Token`；
- 服务端同时校验 Cookie、Header 和基于会话 ID 的 HMAC。

以下高风险 T01 操作在生产环境要求近期强认证：

- 安全控制状态变更；
- 会话保留数据清理；
- 外部身份绑定；
- 目录批量停用。

接受 `aal2`、`aal3`、`mfa` 等上游已验证等级，默认最长 600 秒。开发演示环境保留明确标记的 `development-bypass`，不得作为生产证据。

## 身份上下文字段

服务端只允许向浏览器暴露以下身份字段：账号 ID、用户名、姓名、角色、岗位、机构代码/名称/类型/层级、数据范围、首页、居民/家庭/医生/护士标识和地区代码。密码、哈希、上游令牌、会话 ID、目录凭据不得返回。

权限声明包含：

```text
role + accountType + permissions + organizationScope + regionScope + dataScope
```

默认策略为 `deny`。T00 的 `/api/auth/context` 应消费 T01 的 `publicIdentity()`、`identityClaims()` 和实时账号校验结果，再与中央功能清单合并。

## SAML NO-GO 门禁

配置必须同时具备入口、SP entity ID、audience、IdP 证书 SHA-256 指纹、签名 Assertion、签名 Response 和 persistent NameID。即使配置完整，当前 `runtimeAdapterReady` 仍为 `false`，原因是：

- 尚未接入成熟 XML 签名验证器；
- 尚未验证 metadata 和证书轮换；
- 尚无防重放、时钟窗口、InResponseTo 和 ACS binding 的真实联调；
- 尚无身份提供方联合测试回执和现场签字。

禁止以模拟断言、测试开关或仓库内自签证书将 SAML 标记为生产就绪。
