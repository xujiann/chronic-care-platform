# C端开发报告

生成日期：2026-07-08
适用范围：居民端/C端，包括 `citizen.html`、`mobile-preview.html`、手机号验证码登录、健康档案、电子病历、护理、陪诊、挂号、消息待办、小程序/APP/PWA 预览和移动端上线材料。本文用于研发汇报、试点沟通和上线评审准备，不替代正式立项、政策解读、隐私合规评估或生产上线审批。

## 一、总体结论

C端已形成可运行的受控试点版本，重点能力包括手机号验证码登录、居民家庭范围数据裁剪、健康档案/电子病历/护理/陪诊/挂号二级页面导航、小程序与 APP 形态预览、PWA 离线壳、服务待办、消息通知、授权复核和发布验收摘要。

当前版本适合内部测试、现场演示、真机预览和小范围白名单试点准备。正式生产上线仍需补齐生产短信网关、实名身份、家庭/监护关系、HIS/EMR/LIS/PACS、医保/支付/号源、隐私协议、移动端发布材料、监控审计、灾备和现场签字。

## 五、下一步开发计划

### P0：真实上线底座

1. 接入生产短信网关，保留冷却、有效期、失败锁定、脱敏响应、发送回执和审计。
2. 接入政务实名/OIDC、电子健康卡、居民主索引、家庭/监护关系核验。
3. 完成域名、HTTPS、隐私协议、用户协议、小程序主体、APP 签名、推送证书和崩溃监控。
4. 完成 C端上线门禁：`npm.cmd run citizen:launch-foundation`、`npm.cmd run launch:smoke`、真机截图和现场验收摘要。

### P1：医疗数据只读接入

1. 接入真实居民主索引、公卫健康档案和基层慢病档案，只读展示。
2. 接入 EMR/LIS/PACS 摘要，展示门诊病历、检查检验、用药处方、影像索引和附件摘要。
3. 完成授权撤销强拦截，撤销后机构端、远程会诊和居民端访问复核同步生效。
4. 建立数据来源标签、更新时间、源机构、异常提示和居民纠错反馈入口。

### P2：服务履约闭环

1. 护理：补齐知情同意、电子签名、位置轨迹、护理记录附件、费用预估、质控回访和投诉处理。
2. 陪诊：接入医院接诊回执、陪诊师签到、保险合同附件、补贴结算、服务评价和异常上报。
3. 挂号：接入 HIS/互联网医院号源、号源锁定、停诊排班变更、居民改签确认、支付、医保电子凭证、退号回调和短信通知。
4. 消息：打通短信、订阅消息、APP 推送和站内信，形成触达回执和失败补偿队列。

### P3：试点运营与持续优化

1. 建立试点白名单，按机构、社区、服务类型和居民群体灰度开放。
2. 建设 C端运营看板，跟踪登录成功率、验证码送达率、页面到达率、订单完成率、消息触达率和投诉率。
3. 完成适老化和无障碍复核，保持 44px 以上触控、清晰状态、大字模式、弱网降级和真机兼容。
4. 形成培训材料、客服口径、问题分级、上线日报、应急下线和回滚流程。

## 七、验收建议

1. 文档验收：核对本报告、`docs/居民端下一步开发优先级.md`、`docs/citizen-production-launch-requirements.md`。
2. 静态验收：打开 `mobile-preview.html?client=mini-program&page=health-record&compact=1`，逐项检查健康档案、电子病历、护理、陪诊、挂号导航。
3. 脚本验收：执行 `npm.cmd run check`、`npm.cmd test`、`npm.cmd run citizen:launch-foundation`。
4. 真机验收：覆盖登录、二级导航、服务切换、待办、消息、预约提交、取消、反馈、弱网和返回路径。

结论：C端当前已具备受控试点和现场预览基础。下一阶段不宜继续堆叠新入口，应优先补齐生产短信、实名身份、真实医疗数据只读接入、护理/陪诊/挂号履约闭环和移动端发布合规材料。
