# 互联网护理与陪诊生产上线门禁

## 结论

互联网护理与陪诊的领域状态机、安全建单、资质与服务目录校验、证据化迁移、幂等控制、事务外盒、通知回执、独占领取、指数退避、死信和人工补偿已形成可测试的模块契约。

正式上线不得仅凭页面可访问或演示测试通过作出结论。生产判定必须同时满足：

1. T06 模块代码门禁通过。
2. T00 将服务适配器和可靠投递运行时接入公共 API、真实仓储事务与部署 worker。
3. 生产环境、真实外部接口、密钥、存储、审计和队列健康门禁通过。
4. 业务、接口、安全、灾备和值守签字全部归档。

验证命令：

```text
node scripts/care-service-production-readiness.js
```

报告输出：

- `release/care-service-production-readiness.json`
- `release/care-service-production-readiness.md`

报告状态说明：

| 状态 | 含义 |
| --- | --- |
| `blocked-by-code` | T06 领域或运行时能力缺失 |
| `blocked-by-platform-integration` | T06 模块已具备，但公共 API/事务仓储/worker 尚未接入 |
| `blocked-by-production-configuration-or-health` | 平台已接入，但生产配置、真实适配器或队列健康不满足 |
| `blocked-until-site-evidence-signed` | 技术门禁通过，仍缺现场验收签字 |
| `ready-for-production-cutover` | 所有代码、集成、配置、健康和签字门禁通过，可进入正式切换审批 |

## T00 公共平台集成清单

公共 `server.js`、`package.json` 和统一发布总表由 T00 维护。集成时应：

1. 公共预约接口调用 `createInternetNursingOrder` 或 `createEscortOrder`，不得继续直接拼接高权限订单字段。
2. 状态操作接口调用对应 `transition*Order`，必须传入服务端访问判定和命令编号，不得开放 `enforceEvidence` 参数。
3. 消息供应商回调调用对应 `record*NotificationReceipt`，并校验签名、消息、订单和渠道绑定。
4. 通过 `executeTransactionalCommand` 或等价真实仓储事务同时提交订单集合和外盒集合；版本冲突必须整体回滚。
5. 部署独立 outbox worker，使用稳定 `CARE_OUTBOX_WORKER_ID`，定时调用领取与投递流程。
6. 提供只读队列健康指标、死信清单和受控补偿接口；死信重开不得接受居民端或普通业务角色调用。
7. 将积压、死信、租约过期和完整性失败接入监控与 SIEM。

## 生产配置门禁

| 类别 | 必需配置/证据 |
| --- | --- |
| 运行与数据库 | `NODE_ENV=production`；SQLite/PostgreSQL 事务存储；PostgreSQL 配置 `DATABASE_URL` |
| 会话与接口签名 | 强 `SESSION_SECRETS`、`INTEGRATION_GATEWAY_SECRET`，不得使用 demo/example/placeholder |
| 统一身份 | HTTPS OIDC issuer、client 和 secret；本人、家庭、监护关系联调 |
| 消息 | HTTPS 短信网关、已审批模板、访问凭据、签名回调密钥和失败回执样例 |
| 医院 | HTTPS HIS 与预约适配器、签名密钥、医院/科室/就诊号字典和异常补证联调 |
| 证据存储 | HTTPS 对象存储、专用 bucket、签名密钥、病毒扫描、保留和不可变策略 |
| 支付/医保/签章 | HTTPS 网关、请求签名、回调签名、对账、退款和失败补偿样例 |
| 审计与监控 | 不可变审计导出或 HTTPS SIEM；队列积压、死信、租约过期、完整性失败告警 |
| worker | `CARE_OUTBOX_WORKER_ENABLED=true`、稳定 `CARE_OUTBOX_WORKER_ID`、服务守护和健康探针 |

部署模板：

- `deploy/care-service-outbox-worker.service.template`
- `deploy/care-service-outbox-worker.timer.template`
- `deploy/care-service-outbox.env.template`

worker 入口为 `scripts/care-service-outbox-worker.js`。`CARE_SERVICE_RUNTIME_MODULE` 必须指向 T00 提供的生产仓储与投递适配器模块；缺少该模块、事务仓储或投递适配器时 worker 会拒绝启动。

## 现场签字门禁

原有 `CARE_CUTOVER_*_SIGNOFF=signed` 字符串不再能够单独放行。正式切换必须使用证据清单：

- 以 `deploy/care-service-cutover-evidence.template.json` 为模板，在不可变证据库归档业务、接口、安全、灾备和值守五类独立材料。
- 每类审批必须显式为 `approved`，绑定不同签署人、独立证据引用、SHA-256 摘要、签署时间和有效期。
- 清单必须匹配当前 `care-service-runtime-v1` 策略和 `production` 环境；缺项、拒绝、过期、超期、未来时间、签署人复用或证据摘要复用均拒绝。
- 将清单挂载到 `CARE_CUTOVER_EVIDENCE_FILE`，并把精确文件摘要写入 `CARE_CUTOVER_EVIDENCE_SHA256`。文件被追加空行或发生任何字节变化后必须重新审批并重新固定摘要。
- `CARE_CUTOVER_SIGNOFF_MAX_AGE_DAYS` 默认 30 天，现场可按批准的变更制度收紧，但不得超过程序允许的 365 天。

部署模板：

- `deploy/care-service-cutover-evidence.template.json`
- `deploy/care-service-cutover.env.template`

五类审批范围如下：

| 范围 | 责任方 | 必需证据 |
| --- | --- | --- |
| `business` | 老龄健康/护理管理部门 | 服务目录、风险分级、服务规范和异常处置签字 |
| `interface` | 医院信息科/接口责任方 | 身份、消息、HIS、支付/医保/签章联合测试记录 |
| `security` | 网信与安全责任部门 | 个保影响评估、授权范围、审计和安全验收 |
| `dr` | 数据库与灾备责任方 | 备份恢复、消息不丢失和 RPO/RTO 演练记录 |
| `oncall` | 运维值守负责人 | 监控、告警、联系人、升级路径和交接记录 |

## 上线日判定

切换前重新生成联合报告。若 `productionReady` 不是 `true`，不得执行正式切换。切换后至少观察：

- 订单写入成功率和事务冲突率；
- 外盒待投递数量、最老事件年龄和投递时延；
- 死信、租约接管和完整性失败数量；
- 身份、HIS、短信、支付、医保、签章和对象存储错误率；
- 高风险订单、投诉、不良事件和退款 SLA；
- 审计日志与 SIEM 接收完整性。
