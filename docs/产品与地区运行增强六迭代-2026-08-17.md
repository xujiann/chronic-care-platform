# 产品与地区运行增强六迭代

## 交付目标

本轮在不改变现有事项中心 1.0、产品运行驾驶舱和中央路由的前提下，新增可旁路集成的事项中心 2.0 与地区运行视图。所有公开对象采用固定字段白名单，只保存和展示运维协作元数据；真实地区验收与生产启用继续保持 `NO-GO`。

## 六个迭代

| 迭代 | 能力 | 本地验收 |
| --- | --- | --- |
| 1 | 来源归一、优先级归一、SLA 计算 | 来源标识只保留 SHA-256；支持超时、临期、时限内、已关闭四态 |
| 2 | 按角色分派、按执行人认领、乐观版本 | 分派角色必须在白名单；认领人与分派角色一致；版本漂移默认拒绝 |
| 3 | 协作消息、已读回执、幂等命令 | 正文只存摘要；公开视图只显示类型、角色、时间和已读数量 |
| 4 | 重开、升级、脱敏时间线 | 重开与升级有次数上限；时间线不含备注正文、业务载荷和基础设施信息 |
| 5 | 地区能力、配置差异、部署/复制/验收视图 | 只展示能力键、差异键及状态；不返回配置值和探测目标 |
| 6 | 非功能预算、告警摘要、安全 UI、readiness | UI 全量转义；报告固定 `productionReady=false`、`decision=NO-GO` |

## 领域模块

- `src/platform/productization/work-item-center-v2.js`：事项归一、状态机、消息已读、SLA 和脱敏公开投影。
- `src/platform/regional/product-regional-operations-view.js`：地区能力、配置差异、部署、复制、验收、预算和告警聚合。
- `src/platform/productization/product-regional-operations-view-model.js`：面向前端的第二次白名单裁剪。
- `product-regional-operations-ui.js`：无业务写入能力的安全渲染组件。
- `scripts/product-regional-enhancement-readiness.js`：六迭代就绪检查和 JSON/Markdown 证据输出。

## 事项中心 2.0 操作约束

状态流如下：

```text
queued --dispatch--> dispatched --claim--> in-progress
in-progress --block--> blocked
in-progress|blocked|escalated --resolve--> resolved --reopen--> dispatched
queued|dispatched|in-progress|blocked --escalate--> escalated
```

`message` 和 `read` 是版本化协作动作。所有命令必须带命令标识、事项标识、期望版本、操作者角色和不透明操作者标识。命令精确重放返回原事项结果；同一命令标识表达不同意图时拒绝处理。

备注、协作正文和证据引用不会进入公开响应：备注与正文仅保存 SHA-256；证据引用也只保存摘要。事项来源仅保留来源集合白名单、固定分类、领域和来源标识摘要。

## 地区运行视图边界

地区视图允许公开的字段只有：

- 六位地区代码、部署类别和阶段；
- 能力键及启用状态；
- 配置文件键、能力键和扩展键的差异数量/列表；
- 配置、复制、验收、非功能预算和告警门禁状态；
- 固定阻断项代码。

视图禁止公开地区配置值、机构报文、患者数据、探测正文、域名、IP、端口、路径、运行账号、存储资源、凭据、告警接收端和签名材料。即使验收状态为 `accepted`，也不能据此生成生产授权。

## 本地验证

直接运行：

```powershell
node scripts/product-regional-enhancement-readiness.js
```

需要输出评审文件时：

```powershell
node scripts/product-regional-enhancement-readiness.js --output=release/product-regional-enhancement.json --markdown=release/product-regional-enhancement.md
```

报告通过表示六个迭代的仓库内控制已经具备，不表示真实地区已经上线。生产仍需真实机构联调、监控值守演练、压测与弱网证据、备份恢复与容灾演练、独立安全评估、签字验收和明确切换授权。
