# 传染病直报投递箱与独立 Worker

日期：2026-08-05

## 本轮目标

把传染病报告案件的 `submit-report` 从“只更新业务状态”升级为可恢复的外发边界：

1. 请求事务先写案件状态和最小化投递命令；
2. 独立 Worker 获取有版本约束的短租约；
3. 租约持久化成功后才构造去身份化报文并调用疾控直报连接器；
4. 临时故障执行有限指数退避，永久故障或次数耗尽进入死信；
5. 外发接口即时受理只进入 `awaiting-callback`；
6. 案件最终接收或拒收仍只能由 HMAC 验签回调确认。

本轮不把自动化测试解释为生产接口联通，不改变 `productionReady: false`。

## 组件

| 组件 | 职责 |
|---|---|
| `public-health-direct-report-outbox-service.js` | 投递命令、版本、租约、重试、死信、人工重放和可信回调绑定 |
| `public-health-direct-report-worker.js` | 先持久化租约，再构造报文和发送；持久化发送结果 |
| `src/http/routes/public-health/infectious-reporting.js` | 提交动作原子入队、最小化运维列表、死信重放、回调同步 |
| `public-health-connectors.js` | HMAC 请求签名、HMAC 假名引用、HTTPS、超时和有限传输重试 |
| `public-health.js` | 委级门户只读展示投递状态、尝试次数和安全错误码 |

## 投递状态

```text
queued
  -> leased
     -> awaiting-callback
        -> callback-accepted
        -> callback-rejected
     -> retry-scheduled
        -> leased
     -> dead-letter
        -> queued（委级授权重放）
```

`awaiting-callback` 不是业务接收成功。外部平台返回的即时 `receiptId` 只用于把后续已验签回调绑定到同一投递命令。

## 数据最小化

投递箱持久化：

- 投递、案件、事件和报告标识；
- 契约标识、版本、状态和尝试次数；
- 幂等键摘要与业务绑定摘要；
- 租约 token 摘要和 Worker 标识摘要；
- 最小化受理回执、可信回调状态和安全错误码。

投递箱不持久化：

- 原始直报报文；
- 居民主索引、姓名、证件或联系方式；
- 样本号明文；
- HMAC 密钥、Bearer token 或租约明文；
- 上游错误消息和响应原文。

Worker 发送前在内存中使用独立 `PUBLIC_HEALTH_REFERENCE_SECRET` 生成：

- `hmac-sha256:v1:<digest>` 主体引用；
- `hmac-sha256:v1:<digest>` 样本引用。

## HTTP 运维边界

### 案件列表

`GET /api/public-health/infectious-reporting-cases`

委级角色可查看案件时间线和最新投递状态。响应不包含幂等摘要、租约摘要、居民身份或原始报文。

### 投递列表

`GET /api/public-health/infectious-reporting-deliveries`

委级角色可查看：

- 排队、重试、等待回调、死信和完成数量；
- 每个投递的版本、尝试次数、下次尝试时间；
- 最小化受理回执；
- 安全错误码。

### 死信重放

`POST /api/public-health/infectious-reporting-deliveries/:id/retry`

请求必须包含：

```json
{
  "expectedVersion": 5,
  "idempotencyKey": "controlled-operation-key",
  "at": "2026-08-05T08:05:00.000Z"
}
```

仅 `dead-letter` 可重放；版本冲突、幂等漂移和非死信状态均失败关闭。

## Worker 持久化契约

`processDirectReportDelivery` 要求调用方注入 `writeState`：

1. 第一次写入必须持久化 `leased` 状态；
2. 第一次写入失败时不得调用外部平台；
3. 第二次写入记录 `awaiting-callback`、`retry-scheduled` 或 `dead-letter`；
4. 生产实现应使用具备比较并交换或行版本约束的数据库仓储；
5. Worker 进程必须由独立进程守护、任务调度和监控告警管理，不得嵌入 HTTP 请求处理路径。
