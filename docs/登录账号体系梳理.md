# 登录账号体系梳理

生成日期：2026-07-08

事实来源：`README.md`、`auth.js`、`server.js`、`data/db.json`。

## 1. 总体结构

当前系统采用“机构目录 + 登录用户 + 角色权限 + 数据范围”的账号模型。

- 机构目录：`authOrganizations`，当前 9 个机构/组织。
- 登录用户：`authUsers`，当前 14 个演示账号。
- 居民家庭账户：`accounts`，当前 2 个家庭账户，绑定居民本人和家庭成员。
- 医生档案：`doctorProfiles`，当前 2 个医生账号绑定执业档案。
- 护士档案：`internetNursingNurses`，当前 3 名互联网护理护士，其中 `nurse` 登录账号绑定 `inn-001`。

登录方式分两类：

- 管理端、机构端、医保端、医生端、护士端：用户名 + 密码，演示密码为 `123456`。
- 居民端：用户名 + 密码，另支持手机号 + 短信验证码；演示短信验证码为 `888888`。

权限控制分两层：

- 前端页面守卫：`auth.js` 根据 `role` 控制可访问页面和导航入口。
- 后端 API 守卫：`server.js` 使用 `requireApiRole`、`canAccessResident`、`canAccessDoctor` 等函数控制接口、居民数据和医生执业数据范围。

## 8. 当前边界

1. 当前账号为演示账号，适合本地演示、静态预览和 API 闭环验证，不代表正式生产身份源。
2. `auth.js` 静态预览可本地模拟登录；真实会话、接口写入和审计以 Node 后端 `/api/auth/*` 为准。
3. 医疗机构下的医生、护士当前仍共享 `institution` 角色，实际数据范围依赖 `accountType`、`doctorId`、`nurseId` 和接口校验继续收窄。
4. 居民端已经支持手机号验证码演示路径，但生产上线仍需要真实短信网关、实名核验、隐私协议、家庭关系证明和移动端安全策略。
5. 正式上线前应把账号矩阵纳入现场验收材料，逐项确认机构编码、人员身份、角色权限、数据范围、审计留痕和停用回收机制。
