# 数智医院标准平台 v0.18 生产运行与投产证据报告

## 一、建设目标

v0.18 面向国家级、省级和医疗机构三级业务平台，将“标准评价、医院接入、任务执行、回调核验、异常处置、现场投产”连成可审计闭环。版本重点补齐 v0.17 之后的生产运行底座和试点切换治理能力，并严格区分软件交付完成与真实生产环境激活。

## 二、总体架构

平台采用“浏览器工作台 + 认证 API + 领域服务 + 持久化任务仓库 + 外部安全适配器”的分层结构：

1. 工作台展示任务、Worker、回执、死信、隔离、切换窗口、投产证据和 Go/No-Go 决策。
2. Node 服务提供鉴权、角色控制、机构范围控制和统一错误响应。
3. 执行领域负责幂等入队、原子领取、租约心跳、失败重试、死信重放和回调状态机。
4. SQLite WAL 仓库通过 `BEGIN IMMEDIATE` 保证任务领取及状态迁移的原子性和持久性。
5. 安全适配器从外部托管保险库临时取钥，在服务端完成 HMAC-SHA256、时间窗、nonce 和 mTLS 校验。
6. 投产治理模块以证据摘要、独立复核、四方签批和硬门禁形成生产切换决策。

## 三、已实现功能

### 3.1 持久化任务运行中心

- 任务幂等入队和载荷 SHA-256 摘要登记。
- 按能力池注册 Worker，并原子领取待执行任务。
- 一次性租约令牌、令牌摘要落库、心跳续租和超期租约恢复。
- 指数退避重试、最大重试次数、死信登记及授权重放。
- 回调等待、成功闭环、失败阻断、连接器隔离和人工解除。
- 任务、Worker、回执、死信、隔离和切换记录的脱敏运行看板。

### 3.2 外部安全控制

- 生产回调密钥只保存外部引用，密钥材料由 Loader 临时获取。
- 回调签名采用 HMAC-SHA256 和时间安全比较。
- 校验回调时间偏差、nonce 新鲜性、载荷摘要和客户端证书指纹。
- 生产 Worker 仅允许受信 mTLS 服务身份领取任务。
- 持久化边界禁止原始凭据、保险库引用、幂等键、租约令牌、签名、nonce 和业务载荷。
- 安全看板分别展示代码实现状态与外部配置状态。

### 3.3 投产证据与 Go/No-Go

平台设置十项投产证据要求：

1. 托管保险库取钥证明。
2. 签名回调与 mTLS 回执。
3. 联调成功场景。
4. 联调失败场景。
5. 重试与幂等场景。
6. 对账补偿场景。
7. 切换值守表。
8. 回滚演练记录。
9. 生产变更单。
10. 试点医院现场签字。

证据只登记文件名、SHA-256 摘要、提交身份和核验身份，不保存证据原文。提交人与复核人必须独立，接口、安全、运行和医院四类责任人必须由四个不同身份签批。只有在证据齐全、独立复核完成、四方同意、队列与死信清空、无活动隔离、外部安全适配器就绪且切换窗口通过时，系统才能形成 `GO`。

### 3.4 API 能力

生产运行 API 覆盖：

- 运行中心和安全适配器状态查询。
- Worker 注册、保险库引用登记和任务创建。
- 任务领取、心跳、完成、失败和过期租约恢复。
- 死信重放、隔离解除和签名回调。
- 切换窗口评估。
- 证据包创建、证据登记、独立核验、四方签批、综合评估、开始、完成和回滚。

接口已同步到 `digital-hospital-standard-platform/mock-api/openapi.v0.1.yaml`，交换包结构已同步到 `package-schema.v0.1.json`。

## 四、安全与审计边界

1. 客户端不能自行声明签名有效，签名结论由服务端计算。
2. 客户端时间不作为平台审计时间，业务变更使用服务端接收时间。
3. 原始密钥、签名、nonce、租约令牌和载荷不进入运行看板或持久化状态。
4. 证据提交、复核、签批、评估、切换和回滚均形成审计事件。
5. 任一必要控制未满足时保持 `NO-GO`，不得通过前端操作绕过。

## 五、验收结果

`npm.cmd run digital-hospital:execution-check` 覆盖领域状态机、SQLite 仓库、安全验证、投产治理和真实 HTTP API 流程。生产运行就绪脚本共检查八类软件能力，包括事务仓库、秘密边界、服务路由、托管取钥、签名与 mTLS、证据要求、四方签批和 OpenAPI 契约。

软件验收目标状态为：

- 软件能力：完成。
- 生产运行代码检查：通过。
- 真实生产激活：待外部配置和现场证据。
- 当前发布决策：`software-complete-external-activation-required`。

## 六、生产激活前置条件

以下事项由现场环境和责任单位完成，不能由演示数据替代：

1. 配置生产托管回调密钥引用及临时取钥 Loader。
2. 登记回调网关和 Worker 服务的受信 mTLS 证书指纹。
3. 完成试点医院成功、失败、重试、对账和回滚联合测试。
4. 归档十项证据并完成独立复核。
5. 完成四方责任人签批和生产变更审批。
6. 在批准窗口内执行 Go/No-Go，保留首笔回执、监控观察和回滚待命记录。

因此，v0.18 可以用于完整演示、接口联调、试点准备和投产评审，但在上述外部事项完成前，不应表述为已正式生产上线。
