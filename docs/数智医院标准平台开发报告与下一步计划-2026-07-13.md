# 数智医院标准平台开发报告与下一步计划

- 报告日期：2026-07-13
- 开发分支：`codex/merge-chronic-followup-into-platform`
- 本轮主题：PostgreSQL 影子库基线入队与只读一致性核对
- 生产结论：影子核对能力完成不等于 PostgreSQL 已成为生产主库，`STORAGE_ENGINE=postgres` 与 `productionReady` 继续保持受控阻断

## 一、本轮主要开发成果

### 1. SQLite v9 影子核对台账

- SQLite schema 从 v8 升级到 v9，新增 `postgres_sync_reconciliations`。
- 台账记录核对批次、时间、状态、集合计数、匹配数、差异数、差异类型、耗时和安全错误码。
- 差异明细只保存集合名、源版本、SHA-256 和批次 ID，不保存居民、诊疗或业务正文。
- 最近一次核对结果进入 `/api/health` 和 `/api/metrics` 的 `storage.postgresSync.reconciliation`。

### 2. 安全基线入队

- 新增 `postgres:sync-bootstrap`，首次启用影子同步时把当前 SQLite 集合状态写入一个受控基线批次。
- 基线保持现有集合版本，不通过伪造业务写入补齐远端状态。
- `storageMeta` 被排除；已有 outbox 时默认跳过，防止重复基线。
- 基线批次仍受 payload SHA-256、前序链摘要和批次链摘要保护，不输出业务正文。

### 3. PostgreSQL 只读影子核对

- 新增 `postgres:shadow-reconcile`，使用 `BEGIN READ ONLY` 查询 `health_platform.runtime_collection_state`。
- 按集合比较本地与远端的源版本和 payload SHA-256，识别远端缺失、远端多余、版本不一致和摘要不一致。
- 连接错误只记录安全错误码，不返回连接串、主机、用户名、密码或驱动原始错误正文。
- 核对命令可把 JSON/Markdown 证据写入指定运行日志目录，报告明确标记 `productionPrimary=false`。

### 4. 运行与告警闭环

- 新增仅限卫健管理角色访问的 `GET /api/production-database/shadow-reconciliation`。
- 核对差异自动形成 `postgres-shadow-reconciliation` critical 运行信号，可进入现有 SIEM/Webhook 告警路由。
- 新增加固的 oneshot service 和五分钟 timer，使用最小权限、只读系统目录和受控数据/日志写目录。
- 核对 CLI 已进入不可变生产部署包，并接受逐文件 SHA-256 验签。

### 5. 发布治理

- 生产数据库 readiness 新增基线入队、只读核对、核对台账和定时部署检查。
- 发布报告、部署检查、生产审计、CI、静态契约和正式文档同步升级到 SQLite v9。
- 正式生产阻断继续保留：影子库不得通过 worker 或核对命令变成生产主库。

## 三、当前生产阻断项

1. PostgreSQL 仍是影子目标，生产主读写适配器尚未实现。
2. 尚未在真实脱敏数据上连续运行基线、增量追平和周期核对，也没有现场差异处置签字。
3. 容量、锁竞争、慢查询、连接池、故障转移、原生备份恢复和回切演练尚未完成。
4. OIDC、短信、医院系统、支付医保、对象存储和 SIEM 仍需真实凭据与联合测试回执。
5. 等保、密评、渗透、隐私影响评估、灾备和 go/no-go 正式审批尚未完成。

## 四、下一步开发计划

### P0：0-30 天

1. 增加 PostgreSQL 影子核对历史查询、差异责任人、处理备注和关闭/重开状态。
2. 将差异数、积压量、最老积压时间、送达延迟和核对时效纳入 Prometheus 指标与 SLO。
3. 在脱敏全量数据上执行“基线入队、增量追平、周期核对、断网恢复、重复批次和乱序批次”演练。
4. 实现 PostgreSQL 只读业务适配器，在受控开关下对关键查询进行双读比对，但不向居民或业务端返回影子结果。
5. 完成数据库最小权限账号、TLS 证书、备份和监控接入。

### P1：31-60 天

1. 将通用集合状态转换为居民主索引、任务、审计和集成事件领域表。
2. 完成容量、索引、锁、慢查询、连接池和故障转移专项测试。
3. 建立双读差异工单、抽样复核和数据库负责人签字流程。
4. 完成外部系统真实联调、多角色 UAT 和安全整改。

### P2：61-90 天

1. 通过审批后开展 PostgreSQL 受控主读灰度，再评估主写切换。
2. 执行生产备份恢复、数据库故障切换和应用回滚演练。
3. 完成首日指挥、值班交接、多方 go/no-go 审批和生产证据归档。
