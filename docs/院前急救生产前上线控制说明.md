# 院前急救生产前上线控制说明

## 上线判定原则

急救模块把“功能可运行”和“允许正式切换”作为两个独立状态：

- `functionalReady=true`：业务闭环、API、页面、状态机、权限和专项测试已完成。
- `productionReady=true`：所有必接接口已通过现场联调并签署，所有生产演练有证据，全部切换阻塞已解除。
- 任一现场证据缺失时，`formalGoLiveState` 必须保持 `blocked-until-site-evidence-signed`。

## 生产前控制面

### 外部接口探测

控制中心覆盖120 CTI与录音、运营商定位与短信、车载设备、医院急诊网关、区域全民健康信息平台五类接口。接口探测记录服务地址、凭据引用、证书指纹、探测时间和时延。探测通过只进入 `probe-passed-site-signoff-pending`，不会自动获得生产资格。区域平台接口必须对应 EMG-SITE-06 的独立现场证据；没有该项签署，区域平台接口不会进入 `ready`，切换前检不会通过。

车载设备接入由 `emergency-device-gateway.js` 提供独立可信边界。登记只保存密钥引用与 SHA-256 证书指纹，不保存原始密钥；设备外部证明先提交证据摘要，再由不同卫生行政责任人复核。已激活设备的信号必须同时通过 HMAC-SHA256、120秒时钟窗口、设备单调计数器和来源信号幂等校验，幂等重放也必须重新验签。生命链只消费已经验签的可信网关信号，跨居民信号会被拒绝，同一网关信号最多链接一个自动 SOS 事件。设备可按证据暂停、退役或轮换凭据；轮换后旧证明失效并重新进入待证明状态。T00 按模块导出的 `ROUTE_CONTRACTS` 接入公共服务端后，方可执行 HTTP 现场验收。

### 可靠消息

医院预警、调度回执、院前记录和结局回传使用幂等键防止重复处理。每条消息记录尝试次数、最大次数、载荷摘要和最后错误；达到最大次数后进入 `dead-letter`，由值班人员复核和重放。

### 生产演练

正式切换前必须完成并提交证据：

1. 车载弱网与断网补传；
2. CTI故障电话降级；
3. 医院接口中断、电话预警和纸质交接；
4. 数据库与消息服务灾备切换；
5. 敏感位置和医疗数据泄露响应。

### 现场证据签署

现场签署要求同时提供证据引用、签署说明和精确确认短语。CTI、定位、设备、医院四类要求还必须先完成关联接口探测。签署动作进入哈希审计链，禁止只修改状态字段绕过。

## 生产目标

## 接口

- `GET /api/emergency/production-center`
- `POST /api/emergency/production/endpoints/:id/probe`
- `POST /api/emergency/production/deliveries`
- `POST /api/emergency/production/deliveries/:id/retry`
- `POST /api/emergency/production/drills/:id/complete`
- `POST /api/emergency/production/requirements/:id/sign`

生产前控制中心仅向卫生行政和医疗机构角色开放；探测、演练签署和上线证据签署仅允许卫生行政角色执行。现场上线证据采用四眼原则：第一名责任人提交外部签署人、所属机构、证据引用及 SHA-256 摘要；不同责任人必须使用相同摘要和独立核验引用完成核验，系统才将要求标记为 `signed` 并允许关联接口进入生产就绪。提交人不得核验自身提交的证据。
