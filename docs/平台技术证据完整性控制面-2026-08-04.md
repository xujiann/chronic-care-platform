# 平台技术证据完整性控制面

## 目标

本控制面把生产适配器、影子对账、区域联调、业务闭环、运营治理、外部发布、回滚和灾备八类证据绑定到同一个不可变发布判定。它只验证技术报告、受控引用和 SHA-256 摘要的一致性，不执行生产切换，也不替代现场签字。

## 运行入口

运营输入使用绝对路径，并且只保存元数据、`evidence://`、`artifact://`、`cmdb://`、`ticket://` 或 `vault://` 受控引用及 SHA-256 摘要：

```powershell
$env:PLATFORM_OPERATIONAL_CONTROL_INPUT_FILE='C:\controlled\platform-operational-control.json'
npm run production-adapters:operational-control
npm run production-adapters:operational-control -- --require-operational-ready
```

第二个命令在本地或外部门禁不完整时返回退出码 2。输入文件必须是绝对路径、非空常规文件且不超过 1 MiB。模板见 `docs/evidence-templates/platform-iterations/operational-control-input.template.json`。

委员会只读接口为：

```text
GET /api/production-adapters/operational-control
```

接口仅允许 `commission` 角色访问，并记录 `operational-control-plane-read` 安全审计。路径缺失、JSON 无效、文件过大、敏感字段出现或门禁计算异常时统一返回失败关闭报告。

## 摘要绑定规则

以下报告必须携带由当前安全投影确定性生成的 `technicalEvidenceFingerprint`：

- `platform-production-adapter-runtime-v1`
- `shadow-relay-control-plane-v1`
- `regional-joint-test-evidence-v1`
- `regional-business-loop-report-v1`
- `platform-operational-control-report-v1`

试点切换判定会重新计算可重算报告的技术指纹，并逐项比对 `evidenceDigests`。回滚包和灾备包同样由完整元数据投影生成摘要。任意报告内容变化、摘要漂移或批准指纹未同步，判定都回落为 `NO-GO`。

## 安全边界

- 不提交凭据、令牌、私钥、患者数据、居民原始记录、诊断明细或供应商原始报文。
- `localReady=true` 只代表仓库和目标环境的本地控制检查通过。
- `externalReady=true` 只表示提供的受控引用和摘要结构满足规则，真实性仍由指定责任方核验。
- 即使输出 `GO-CANDIDATE`，`cutoverExecutionAuthorized`、`productionPrimary` 和 `productionReady` 仍保持 `false`。
