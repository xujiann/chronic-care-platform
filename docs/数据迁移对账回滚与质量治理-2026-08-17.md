# 数据线控制面：迁移、对账、回滚与质量治理

## 交付边界

本控制面把十二个 P0 权威数据集合划分为三个迁移波次，使用
`outbox-shadow-then-cutover` 模式管理本地准入。它只接收集合数量、版本、检查点、
受控证据引用和 SHA-256 摘要，不接收患者数据、原始消息、账号凭据或数据库连接信息。

控制面可以把迁移运行推进到 `local-candidate`，但始终返回：

- `productionReady: false`
- `productionPrimary: false`
- `cutoverAuthorized: false`

仓库内的配置、自动化测试和演示数据都不能替代真实机构的签署证据，也不能授权生产切换。

## 状态机

```text
planned
  -> REHEARSAL_COMPLETED
rehearsed
  -> RECONCILIATION_PASSED
reconciled
  -> ROLLBACK_VERIFIED
rollback-verified
  -> QUALITY_GATE_PASSED
local-candidate
```

每个转换都要求受控证据引用、工件摘要和完成时间。跳过阶段、重复执行阶段、使用生产环境
作为演练环境或写入敏感字段都会失败并保持原状态。

## 四类门禁

1. 迁移演练：仅允许 `test`、`staging`、`preproduction`，记录源版本和源计数。
2. 对账：源/目标数量完全一致，差异数和重复数为零，源/目标 SHA-256 摘要一致，
   同时记录 outbox 检查点。
3. 回滚：快照与恢复摘要一致，RPO 不高于 300 秒、RTO 不高于 1800 秒，至少由
   `data-owner` 和 `release-manager` 两个不同角色留存批准引用。
4. 质量：完整性、有效性、唯一性和新鲜度达到配置阈值，关键及未关闭问题均为零。

## 使用方式

中央集成可在 `package.json` 中增加入口；当前也可以直接执行：

```powershell
node scripts/data-migration-readiness.js
node scripts/data-migration-readiness.js --input=C:\controlled\migration-runs.json --write
```

无输入时只验证控制面和配置，报告应为 `ok: true`、`localGateReady: false`、
`productionReady: false`。输入可以是运行数组，或包含 `runs` 数组的对象。

## 生产前仍需外部完成

- 脱敏全量演练；
- 签署的对账证据；
- 独立回滚演练；
- 容量与故障转移评估；
- 现场变更审批。

生产激活仍应由唯一集成线和环境审批完成；本数据线不修改路由、运行时组合或部署配置。
